# m3u8 获取方案

2026-10-10。状态：已接入按番号与来源定位、隐藏 Neutralino 取流、HLS 检查、结果显示及下载交接，并通过安全 mock 闭环验证。磁力暂不开发。当前实现依据 [ADR 0010](../decisions/0010-resource-lookup.md)，执行范围见 [验证记录](../verification/2026-10-10-resource-lookup.md)。

## 当前决策

用户明确：若旧版没有独立的番号 HTTP 取流，则放弃 HTTP 网页解析，改用 WebView。已核实旧版 `rs_find_video_links(code, site_id)` 根据站点模板直接创建 WebView；没有找到对应的纯 HTTP 取流实现。

当前目标流程为：**番号＋来源 → 对应资源页 → 隐藏 WebView 捕获候选 → 关闭取流实例 → HLS 链接检查**。HTTP 仅保留清单与必要小范围请求验证，不继续扩展网页解析。成功、失败、超时和取消都应结束取流实例，主程序继续运行。

用户进一步明确：窗口不显示是硬条件，抢焦点尽量解决，无法解决也可接受。保留官方 Neutralino 6.10.0，使用 `CreateProcess + STARTF_USESHOWWINDOW + SW_HIDE`，并启用 `hidden` 与 `skipTaskbar`。安全文字 mock 的正常完成、无结果和 20 秒超时三种场景均无可见窗口采样与 SHOW 事件，均已退出；每次仍有一次短暂前台激活，不宣称已解决焦点问题。

`webview/webview + 自有隐藏 HWND`、saucer 与官方 WebView2 SDK 保留为能力缺口备选。本次未引入新 WebView 库，已把 Win32 隐藏启动接入受管进程，通过独立 Neutralino/WebView2 的本机 CDP 接口捕获资源；远程页面的原生 API 和扩展关闭。历史选型证据见 [隐藏 WebView 能力与库选型](../verification/2026-10-10-hidden-webview-selection.md)。

以下保留原 HTTP 优先方案和第一阶段实现记录，作为历史依据；其“HTTP 必须先执行”“WebView 只作兜底”与“不抢焦点”的硬性安排已被上述决策替代。HTTP 网页解析原型不接入资源搜索；受管 HTTP 与 HLS 检查用于验证 WebView 候选。

## 原 HTTP 优先方案

采用 HTTP 解析优先、隐藏 WebView 兜底的获取流程。先尝试直接请求和解析，得到经过检查的 HLS 资源后立即返回；只有符合回退条件的失败才启动一次隐藏 WebView。获取失败、超时或取消后自动关闭取流实例并结束任务，JAVM 主程序继续运行。

用户在方案完成后明确授权“开始 HTTP 实现，仅用安全 mock”。本次落实 HTTP 获取、解析和验证服务，不接入真实内容源。开发与验证只使用安全的虚构数据、占位素材和 mock；隐藏窗口也必须遵守此限制。

## 已确定的约束

- HTTP 必须先执行。不能同时预热 WebView，也不能因为某个来源常用动态页面就跳过 HTTP。
- WebView 从创建起保持隐藏，不显示任务栏入口、不抢焦点、不发声，不打开外部浏览器、开发者工具或交互验证窗口。不能先显示再隐藏，也不能以移到屏幕外代替隐藏。
- 出现登录、验证码、用户手势或其他必须人工参与的条件，直接报告原因并退出取流实例，不等待用户处理。
- 成功也关闭取流实例。失败不得无限重试、刷新或重新创建窗口。
- 页面切换不取消应用级任务；显式取消、显式退出应用时，停止请求、解析 Worker 和本任务所属的子进程。
- 普通业务使用 TypeScript；不新增 Python、Rust 服务、生产用 Playwright、第二套浏览器或自定义 HTTP 服务器。不扩大 C++ 业务范围。
- 本阶段实现应用级 HTTP 服务及针对性 mock 用例；WebView、资源界面和下载交接留在后续阶段。不新增依赖或数据库迁移，不运行真实来源与桌面媒体验证。

## 获取流程

每个“来源与查询”构成独立任务。一次查询可产生多个来源任务，分别返回成功或失败，不因一个来源失败丢弃其他来源结果。

| 阶段         | 行为                                                                 | 下一步                                   |
| ------------ | -------------------------------------------------------------------- | ---------------------------------------- |
| 排队         | 校验输入、来源能力和队列上限，合并相同的在途请求                     | 获得容量后开始计时                       |
| HTTP 获取    | 直接链接先检查清单；页面输入按适配器规则请求详情页、配置接口或嵌入页 | 进入 Worker 解析                         |
| HTTP 解析    | 提取候选地址；必要时进行有界的后续 HTTP 请求和文本解包               | 有候选则验证；无候选则按失败类型决定回退 |
| HLS 验证     | 检查播放列表、所选音视频轨和必要的小范围探测                         | 通过则成功，完全跳过 WebView             |
| 隐藏 WebView | 只在 HTTP 未成功且允许回退时执行一次，收集有界候选并退出             | 对候选执行同一 HLS 验证                  |
| 收尾         | 取消剩余操作、确认子进程退出、清理本任务临时文件                     | 发布一次最终结果，释放容量               |

状态建议为 `queued → http → validating → webview → validating → closing → succeeded / failed / cancelled`，其中 WebView 段可跳过。只有确认收尾完成后才能发布正常终态；无法确认退出时保留 `cleanup_failed` 和进程所有权记录。

任务以 `requestId` 和尝试序号识别归属。取消、重试或进入终态后到达的响应全部丢弃；同一任务只能结算一次。

## HTTP 获取与解析

### 传输层

新增取流专用的 `ResolutionHttpPort`，复用项目现有受管进程和网络配置。它需要返回状态码、最终 URL、响应头和有界响应体，支持真实取消、响应大小限制、重定向检查与代理策略。

官方 `net.request` 可避开浏览器 CORS，但所用 6.10.0 接口未提供请求取消句柄、流式读取或代理参数，源码将响应体整体返回。第一阶段优先复用现有 curl 子进程机制来满足这些要求；通过官方 `os.spawnProcess` 启动，不增加新的常驻网络服务。不能只用 `Promise.race` 把请求包装成“已取消”。[官方网络 API](https://neutralino.js.org/docs/api/net/)、[6.10.0 实现](https://github.com/neutralinojs/neutralinojs/blob/v6.10.0/api/net/net.cpp)

沿用下载的直连优先策略：直连发生网络错误且已配置代理时，最多切换一次线路，仍受同一个阶段截止时间约束。明确的不存在、解析规则不匹配或用户取消不触发线路切换。重定向最多 3 跳，每跳检查目标，跨域时不自动转发 Cookie 或 Authorization。

URL 保留原有签名参数和参数顺序；相对地址使用响应最终 URL 解析，不自行拼接、不删除查询参数。开发 fixture 的 `.invalid` 地址只由 mock transport 响应，不能发送真实网络请求。

### 来源适配器

| 职责             | 输入与输出                                                       |
| ---------------- | ---------------------------------------------------------------- |
| `buildRequest`   | 将来源标识、查询或页面地址转换为第一个 HTTP 请求                 |
| `parse`          | 将有界 HTML、JSON 或脚本文本转换为候选、下一步请求或明确失败原因 |
| `fallbackPolicy` | 判断本次失败是否适合隐藏 WebView，不改变全局隐藏与超时要求       |
| `requestContext` | 保存页面来源、必要 Referer、User-Agent，以及有作用域的会话信息   |

首批只安排三类安全 mock 适配器：页面明文变量、JSON 或嵌入页的两步解析、已知格式的文本解包。后续真实来源规则必须另行确定范围，不能因为存在适配器接口就默认启用。

解析顺序为：已知播放器配置字段、明确的媒体元素或内嵌 JSON、适配器认可的地址重组、最后才是受限解包。通用正则只能发现候选，不能仅凭字符串含 `.m3u8` 就返回成功。

HTML、JSON、解包和清单分析放在有界 Web Worker 中。解析器不执行远程 `eval` 或 `new Function`，不把页面 HTML 插入应用 DOM。只需单个变量时使用受限提取；需要完整 HTML 结构时再选择支持 Worker 的解析库，不能假定 Worker 提供 DOMParser。

### 回退判定

| HTTP 结果                                                  | 处理                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| 至少一个候选通过 HLS 检查                                  | 成功，不创建 WebView                                    |
| 页面获取成功但需动态加载，或已有规则未发现有效候选         | 允许一次隐藏 WebView                                    |
| 普通 403 或可自动完成的浏览器检查，且没有明确人工交互要求  | 允许一次隐藏尝试；浏览器未能静默通过则结束              |
| 已检测到登录、交互验证码或必须用户点击确认                 | `interaction_required`，直接结束                        |
| 明确的详情页 404、410                                      | `not_found`，不回退；某个候选清单失效仍可检查其他候选   |
| 429、离线、DNS 或连接失败，有限线路切换后仍失败            | `rate_limited` 或 `network_error`，不再加一次浏览器请求 |
| 响应超限、无效输入、用户取消                               | 直接结束，不回退                                        |
| 仅得到直播、不可支持的保护格式或必须依赖不可导出会话的资源 | 返回对应的不支持原因，不通过换获取方式掩盖限制          |

每个适配器的页面与候选判断都要有 fixture，不能用宽泛的标题关键词把正常页面误判为不存在。

## m3u8 验证与下载交接

获取服务的成功定义是“在检查时清单与所选资源的必要探测通过”，不保证远端签名永久有效，也不等同于完整视频已下载验证。

1. 以有界 GET 检查清单，确认正文为 `#EXTM3U`。扩展名和 Content-Type 仅作提示，HTTP 200 返回 HTML 仍判失败。
2. 区分主播放列表和媒体播放列表，解析相对 URI、音频组、初始化段和加密声明。递归与候选都有上限，循环引用直接失败。
3. 结合来源身份、播放器关联和轨道信息选择候选；分辨率、码率与时长只作排序依据，不把最长时长作为内容身份的充分证据。无法确定归属时保留候选供选择，不自动下载。
4. 对所选视频及独立音频各探测一个分片；fMP4 检查必要初始化段，AES-128 检查对应密钥可获取。使用有界 Range GET，服务端忽略 Range 时及时中断，不能顺势下载整个大分片。初期只处理有结束标记的点播；其他加密方式和直播返回明确限制。[HLS 清单与标签依据](https://www.rfc-editor.org/rfc/rfc8216)
5. 返回来源页面、发现方式、主清单 URL、已验证的轨道选择、检查时间和所需请求上下文。独立音频存在时不能只把视频子清单交给下载器，否则可能丢失音轨。

首次接入下载时，保留主清单与音频组关系，并让验证器和下载器采用一致的选流策略。若要指定某个非默认画质，需扩展内部选流交接；在契约支持前，不把“验证了 A 轨”表述为“下载器一定会下载 A 轨”。已有显式选流方式见 [视频下载 ADR](../decisions/0007-video-downloads.md)。

链接仅在短期内复用，初始建议 60 秒；来源明确提供更早失效时间时取更早值。真正开始下载时重新检查，过期则按原始页面重解析一次，受新任务预算约束，不进行无限刷新。

Cookie、Authorization 和签名 URL 不进入日志。当前下载契约为统一 `headers`，不能表示任意跨域凭据策略。第一阶段优先验证无会话依赖的样例；需要按域分配凭据时，先补齐内部传输契约，不能把一个 Cookie 盲目转发给所有清单、密钥和分片域名。只有浏览器会话可访问而下载传输无法复现的候选返回 `session_required`。

## 隐藏 WebView 的落地方式

### 官方能力与待验证边界

当前工程固定 Neutralino 宿主和客户端 6.10.0。官方支持隐藏窗口、独立窗口进程以及预加载脚本；6.10.0 源码在导航前注册 `injectScript`，并提供 `newWindowPolicy: custom` 拦截新窗口请求。这些是实现基础，尚不能证明所有页面、框架和系统对话框都能全程无可见界面。[窗口 API](https://neutralino.js.org/docs/api/window/)、[预加载参数](https://neutralino.js.org/docs/cli/internal-cli-arguments/#--window-inject-scriptscript_path)、[初始化源码](https://github.com/neutralinojs/neutralinojs/blob/v6.10.0/api/window/window.cpp#L623-L728)

拟采用同一官方 Neutralino 可执行程序的隔离子实例，由应用现有受管进程机制启动和追踪。相较只调用返回 `void` 的 `window.create`，受管启动能保留真实 PID、取消句柄和退出确认，便于在隐藏页面卡住时收尾；不新增浏览器引擎。

子实例使用任务专属配置和目录，显式设置 `hidden: true`、`skipTaskbar: true`、`useSavedState: false`、关闭 Inspector 与 Extensions。禁止从任务中调用显示、激活窗口或打开系统浏览器的 API。新窗口请求使用宿主策略拒绝；预加载脚本处理可控的页面对话框和媒体静音，但不能将脚本覆盖视为原生对话框全部被禁止的证明。

### 捕获与结果回传

预加载脚本沿用旧版 fetch、XHR、媒体元素和播放器配置的候选发现思路。只读取有界的清单或文本前缀，不对任意响应执行无上限 `clone().text()`；`blob:` 地址本身不作为可下载结果。

捕获到候选后短暂收集同组轨道并退出，最多保留 16 个唯一候选。父任务用同一个 HTTP 验证器检查候选。只有确有必要且能保持无声、隐藏时才允许适配器触发媒体加载；遇到必须用户手势则失败。

结果通道优先验证官方 `storage` 在隔离任务目录中的一次性结果槽：子实例写入后退出，父任务通过官方文件 API 读取、检查结构与大小后立即清理。子实例最多开放 `storage.setData` 和自身 `app.exit`，不继承主应用的文件、进程、数据库权限或认证令牌。结果槽只保存候选和机器可读状态，不保存页面 HTML、封面、标题或截图。带签名的临时数据限制为当前用户可访问，并在收尾时删除。[官方存储路径](https://neutralino.js.org/docs/configuration/neutralino.config.json/#storagelocation-string)、[存储实现](https://github.com/neutralinojs/neutralinojs/blob/v6.10.0/api/storage/storage.cpp)

该通道与任务目录隔离必须先用本地 mock 验证；不复用播放器的 `BroadcastChannel` 作为跨站点通道，因为现有播放器依赖同源页面。HttpOnly Cookie 导出、跨域 iframe、页面 Worker 和原生媒体请求的完整捕获仍是能力边界，不能宣称 JS hook 等同于浏览器网络层拦截。

### 自动退出

- WebView 创建、页面加载、脚本执行和候选收集共用一个截止时间，不因重定向、收到心跳或发现新候选而延长。
- 确认无资源、人工验证、取消、宿主错误或超时后立即开始关闭；成功提交候选后同样关闭。
- 超时监督放在受管进程侧，不能只依赖隐藏页面里的 JavaScript 定时器。父进程异常退出时也要回收其取流子树。
- 优先正常退出；未完成时仅终止该任务持有的子进程树，核对退出后再释放槽位，不按 `msedgewebview2.exe` 名称批量终止进程。
- 清理脚本、结果文件、会话和任务目录。删除失败保留清理记录，不能伪报无残留；下一次启动只处理验证过的任务专属路径。

正式启用兜底前必须通过：创建期间无窗口闪现、任务栏与焦点不变、页面和系统对话框不弹出、无声音、跨页面候选回传、取消与超时后无所属进程残留、父进程退出后回收。若官方能力无法满足其中任何硬要求，保持 HTTP 获取与明确失败反馈，列出具体缺口后再决定宿主补充方案；不自动显示窗口，也不自动引入额外浏览器或 C++ 取流实现。

## 初始资源与时间预算

以下是拟定初值，后续只用安全 mock 调整。所有重试和后续请求都消耗已有预算，不重新计时。

| 项目                   | 初值                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------- |
| 活跃来源任务与等待队列 | 最多 4 个活跃，32 个等待；等待超过 120 秒结束                                       |
| 受管 HTTP 请求并发     | 全服务最多 4 个，同来源最多 2 个；清单验证共用此额度                                |
| 解析 Worker            | 最多 2 个；单个超时任务终止对应 Worker，不阻塞 UI                                   |
| 隐藏 WebView 并发      | 全服务最多 1 个；等待槽位仍计入任务总时限                                           |
| HTTP 阶段              | 最多 30 秒，含页面请求、解析、线路切换和首轮 HLS 验证                               |
| 单次请求               | 连接最多 5 秒，总时限最多 10 秒，且不超过阶段剩余时间                               |
| WebView 阶段           | 从启动进程开始最多 20 秒；每来源任务只启动一次                                      |
| 总工作时限             | 出队后最多 60 秒；覆盖 WebView 等待和第二轮验证                                     |
| 退出清理               | 目标 5 秒内确认退出；超限标记清理失败，不恢复任务执行                               |
| 请求与递归             | 每任务受管 HTTP 请求最多 32 次，含重试与每跳重定向；嵌入页最多 2 层，清单最多 3 层  |
| 输入与候选             | 单个 HTML 或配置响应最多 2 MiB；单个清单最多 1 MiB；候选最多 16 个，优先验证前 3 个 |
| 分片探测               | 每个选定轨道探测最多 64 KiB；初始化段最多 256 KiB；触及上限立即停止读取             |
| 文本解包               | 单次最多 250 毫秒、展开文本最多 2 MiB，超出转失败分类                               |
| 状态更新               | 约 200 毫秒节流；队列保留可取消进度，禁止伪造百分比                                 |

WebView 页面自身的子资源请求不受上述 HTTP port 计数直接控制，其首期边界是单实例和进程截止时间。若后续要求逐请求硬限制，需要单独验证宿主网络拦截能力。

## 模块与交接契约

HTTP 部分已按以下职责落地；三类通用解析规则集中在 `parsers.ts`，尚未添加任何真实来源适配器。隐藏宿主仍为后续建议。

| 模块                                                          | 职责                                                                    |
| ------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `frontend/src/services/streamResolution/ResolutionService.ts` | 应用级排队、阶段切换、预算、取消和订阅，独立于 React 页面               |
| `frontend/src/services/streamResolution/parsers.ts`           | 纯 TypeScript 页面、JSON、受限解包和 HLS 解析；不持有窗口或自行创建并发 |
| `frontend/src/services/streamResolution/worker.ts`            | 有界 HTML、JSON、文本解包、清单分析                                     |
| `frontend/src/platform/neutralino/resolutionHttp.ts`          | 受管 curl、网络策略、请求上下文与有限读入                               |
| `frontend/src/platform/neutralino/hiddenResolver.ts`          | 隐藏宿主配置、任务归属、结果回传与退出确认                              |
| `frontend/src/contracts/streamResolution.ts`                  | 输入、状态、成功结果和失败分类                                          |

输入包括 `requestId`、`providerId`、查询或页面 URL、预期资源标识和取消信号；输出包括候选身份、主清单与轨道关系、发现方式 `http / webview`、必要请求上下文、检查时间与验证范围。凭据通过短期上下文引用管理，UI 与普通日志只取得脱敏状态。

失败至少区分 `not_found`、`parse_failed`、`network_error`、`rate_limited`、`interaction_required`、`session_required`、`unsupported_stream`、`timeout`、`cancelled`、`cleanup_failed`。一个来源失败只更新对应行；既有页面接收结果，不新增独立的浏览器操作界面。

## 安全样例与 mock 验证设计

默认完全离线。HTTP 测试使用 fixture transport；WebView 验证使用官方资源服务器承载的本地 mock 页面。样例标识统一为 `DEMO-001`，页面只含说明文字和几何图形；需要可解码媒体时使用预先确认安全的短色块视频和静音音轨。任何非测试允许地址的访问都应导致用例失败。

| 场景                                            | 必须得到的结果                                               |
| ----------------------------------------------- | ------------------------------------------------------------ |
| HTML 明文变量和转义 JSON                        | HTTP 获取成功，WebView 启动次数为 0                          |
| 两步 API 或嵌入页、相对地址、重定向、签名参数   | 正确关联最终 URL，签名参数不被重排或裁剪                     |
| 安全合成的文本解包                              | 还原 mock URL；不执行样例脚本；超时和膨胀被限制              |
| 主清单、独立音频、fMP4、AES-128                 | 保留轨道与初始化依赖，验证使用正确的上下文                   |
| 伪 m3u8、HTML 错误页、循环清单、分片失败、直播  | 不产生“已可下载”结果，返回具体原因                           |
| HTTP 无候选、本地脚本延迟生成 URL               | 只启动一次隐藏 WebView，回传后退出                           |
| 明确登录或人工验证 mock                         | 不弹窗、不等待人工操作，自动结束                             |
| 弹窗、alert、权限或下载提示 mock                | 不产生可见界面；不能保证时判定兜底验收失败                   |
| Worker、跨域 iframe、blob 和 HttpOnly 会话 mock | 记录实际覆盖范围；无法转交 HTTP 下载的候选不得伪报成功       |
| 请求无响应、重定向不断、页面不断发事件          | 截止时间不延长，超时自动退出                                 |
| 取消与成功同时发生、迟到回调                    | 只结算一次，不发布已取消任务结果                             |
| 队列满、重复提交、切页、StrictMode              | 并发和队列不超限，不重复初始化服务                           |
| 关闭主窗口与显式退出                            | 遵守现有后台运行设置；真正退出时清理所属任务                 |
| 父进程退出、子进程启动中取消、清理失败          | 无误杀其他 WebView，持有退出确认和清理证据                   |
| 大响应、慢 I/O 与大量候选                       | UI 主线程无单次超过 50 毫秒的持续处理；触发时定位并拆分      |
| 缓存过期、跨域跳转、日志与临时文件              | 过期重新解析，凭据不跨域泄露，日志不含页面内容或完整敏感链接 |

mock 通过只证明规则和流程；本地隐藏宿主通过只证明所测宿主与安全页面场景。两者都不证明真实站点可用。此方案不安排真实内容源验证，也不下载或保存其页面 fixture。

## 后续实施顺序

1. **先做 HTTP 获取与解析。** 实现有界队列、请求适配、Worker 和三类安全 mock 规则，完成清单检查；这一阶段不启动 WebView。
2. **验证隐藏宿主能力。** 仅使用本地 mock 检查隐藏、对话框、预加载、结果回传、独立会话和进程清理。任一硬要求失败就保持 HTTP 阶段，不降低用户约束。
3. **接入一次性兜底。** 通过能力验证后，将隐藏宿主接入既定失败分类和全局预算，共用 HLS 验证器。
4. **接入既有资源列表与下载交接。** 使用安全样例检查选流、音频、请求上下文和过期重新解析，保留每来源失败反馈。

确需执行测试时只运行本次新增的针对性用例，不自动运行既有回归或完整测试。

## 第一阶段交付记录

- `ResolutionService.submit()` 返回任务句柄、结果 Promise 和取消入口；应用启动处创建一次，通过 Workspace 上下文提供给后续业务，应用显式退出时调用 `shutdown()`。提交前不创建 Worker 或网络进程。
- HTTP 支持直接 HLS、页面变量、JSON／嵌入页链及受限文本解包。当前页候选通过即结束；失效时才继续后续候选或嵌入页，最多验证 3 个候选。没有站点专用规则、资源身份匹配或搜索入口。
- 共用 HLS 验证器保留主清单与选定音视频轨，检查首个可用分片、相关初始化段和 AES-128 密钥。仅返回首个通过必要探测的候选。这里的“验证”不包含解码、播放或全片下载。
- 输入请求头按原始 URL 的精确 origin 传递；跨域后全部移除，HTTPS 降级拒绝。不收集浏览器会话或自动接受 Set-Cookie，也未扩展下载器的跨域凭据契约。
- 原生传输复用受管 curl，使用手动重定向和有界 GET；先检查 curl 至少为 8.4.0，确保未知长度响应也受传输大小上限约束，明确请求 identity 编码，不自动解压。临时响应按 64 KiB 分块读入。[curl 上限语义](https://curl.se/docs/manpage.html#--max-filesize)
- 正常结果在原生端口完成清理后结算；停止或删除未确认时保留重试句柄，阻止新任务，显式退出会再次清理。活跃取消保持 closing，等待底层操作返回；共享初始化或系统文件调用没有可强制中止的句柄，收尾可能超过 HTTP 工作预算，不能宣称绝对 30 秒内完成退出。
- 同一输入与请求上下文的在途调用共享句柄，任何调用者取消都会取消整个共享任务。订阅快照只含脱敏状态；结果包含检查时间与 60 秒有效期提示，目前没有持久化缓存或过期自动重解析。
- WebView 尚未接入；`fallbackEligible` 只表达后续回退资格。当前失败直接结束 HTTP 任务，不会打开可见或隐藏浏览器。

验证范围与未验证项见 [HTTP 第一阶段验证记录](../verification/2026-10-10-stream-resolution-http.md)。
