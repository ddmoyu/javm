# 1.0 作品、资料与本地视频独立建模

2026-10-10。用户确认 1.0 是全新版本，仅要求迁移 0.5.3；不继续兼容开发过程中的临时媒体库结构。本决策更新 ADR 0006、0008、0018、0019、0020 中依赖“先有视频再有资料”的部分。

## 数据模型

新媒体库为 `%APPDATA%/JAVM/library.sqlite3`，application_id 为 1245793585，schema 从 1 开始。旧版固定来源仍为 `%APPDATA%/com.ddmoyu.javm/javm.db`。不改写或删除此前开发阶段的 `JAVM/javm.db`；若当前新库文件用途、版本或完整性异常，明确报错，不删除重建。

| 对象                     | 所有权与约束                                                                   |
| ------------------------ | ------------------------------------------------------------------------------ |
| `works`                  | 作品身份、标题等资料与收藏，不要求有视频                                       |
| `work_sources`           | MetaTube provider + source ID 唯一映射到作品                                   |
| `media_files`            | 真实视频资源，规范绝对路径唯一；一部作品可以有多个文件                         |
| `nfo_documents`          | 原始 XML、编码、签名及路径；一部作品只有一个规范写入位置，可以保留多个导入来源 |
| `entities/work_entities` | 演员、分类、标签与作品关联                                                     |
| `directories`            | 扫描管理范围；移除目录不删除作品或文件关联                                     |
| `asset_roots`            | 已授权本地资料/资源的挂载根，与扫描目录管理独立                                |
| `legacy_records`         | 旧表逐行 CBOR 原始记录，包括未知字段和 BLOB；不进入新业务表结构                |

作品的可播放性根据关联资源计算，不存储伪造视频路径：

- `metadata_only`：没有关联视频，界面显示“未下载”。
- `available`：至少一个关联视频可用。
- `unavailable`：有关联视频，但全部在扫描中确认不可用，界面显示“文件不可用”。

列表计数以作品为单位；文件清理以资源 ID 为单位。详情列出所有关联视频及 NFO。播放、截图和文件大小展示只使用真实资源。原有单视频接口字段是查询视图的派生值，不能作为第二份持久化事实。

## 闭环

1. MetaTube 搜索结果的“收藏并保存资料”创建或复用作品，加入应用级刮削队列。详情请求、封面与 XML 写入继续使用后台任务，失败可以重试。
2. 无本地 NFO 时，规范资料位置为 `metadata/<work UUID>/movie.nfo`；没有视频也能保存。采用已有 NFO 的作品继续在其规范位置保存，不搬移用户文件。
3. 详情可以填写下载链接，任务记录携带 `workId`；下载与合并成功后将真实视频关联到作品，再补全资料。也可以用“关联视频”直接选择已有文件。
4. 目录扫描同时发现视频和独立 NFO。后补视频可通过来源身份或唯一规范番号自动归并。显式作品身份、已关联路径及番号冲突时拒绝猜测，要求用户确认。
5. 同作品多视频、重复扫描、重复收藏与下载交接不会新建重复作品。没有番号也没有身份的 NFO 保持独立，不通过相似标题猜测归并。
6. 删除一个视频资源保留作品、收藏、NFO、封面和截图；最后一个视频删除后作品显示“未下载”。后续扫描到匹配的视频时重新关联到已有作品。

2026-10-13 菜单调整：卡片与详情菜单的入口改为“删除视频”，确认框显示完整文件路径；同作品多个视频时先选择具体文件，每次仅删除一个。复用现有资源删除流程，逐文件复核身份后删除本地视频及资源记录，保留作品、收藏、NFO、封面和截图；最后一个视频删除后显示“未下载”。

2026-10-10 后续接入 [视频资源查找](0010-resource-lookup.md)：作品详情的查找入口传入番号与 `workId`，隐藏 Neutralino 获取候选，经 HLS 校验后交接现有下载队列。仍支持手工填写链接与关联已有视频；搜索结果尚未在本详情资源页回显或持久保存，真实来源兼容性未验证。

## 写入和一致性

- NFO 写入 `uniqueid type="javm-work"` 与 `uniqueid type="metatube"`。没有视频不生成 `fileinfo`。
- 保留人工字段，包括明确清空的简介、评分和时长；人工修改番号会解除过时来源身份。技术分辨率来自实际文件探测，不作为可编辑作品资料。
- 重刮只补空字段，保留未知 XML 扩展、注释及原始快照。规范 NFO 拥有字段来源，额外侧车文件不能覆盖其来源所有权。
- 保存前重新检查 NFO 签名；涉及具体视频的任务同时检查视频签名和关联。外部修改不覆盖，重试时重新读取。
- NFO 同目录临时写入并替换，原文件首次修改保留 `.javm.bak`。文件与 SQLite 不能跨介质原子提交：文件先落盘，数据库提交失败保留可重试任务，下一次准备重新读取 NFO。
- 删除视频与清除刮削资料是不同操作。仅清除资料会保留视频与收藏；共享资料无法安全独占清除时拒绝执行。
- 原生磁盘、解析、扫描及数据库操作运行在已有有界后台队列；前端使用分页与应用级任务服务，切页不终止任务。

## 0.5.3 迁移

迁移器读取本仓库 `v0.5.3` 标签对应的 schema 2，转换作品、真实资源、演员/分类/标签及目录。相同资源路径或明确身份归并；新版非空资料和收藏优先，旧资料补空。离线资源保持文件关联及不可用状态，不伪装成尚未下载。

保留全部旧表行与字段到 `legacy_records`，并保留独立旧库备份。历史下载/刮削任务及当前没有对应界面的扩展数据只归档，不自动恢复执行。迁移前备份新旧两个数据库，校验源关联、目标完整性和外键；取消或失败回滚，保留原库。完成记录与迁移数据共同提交，之后才清理旧库文件。详见 [迁移 ADR](0018-legacy-database-import.md)。

不提供临时媒体 schema 2–6 的升级链，也不引入长期兼容视图模拟旧表。已有测试夹具随新模型更新；开发期升级相关用例由独立 0.5.3 迁移用例替代。
