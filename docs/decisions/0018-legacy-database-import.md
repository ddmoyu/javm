# 启动时引导导入旧数据库

2026-10-10。用户要求启动后发现旧数据库时显示引导，将旧数据导入新版，成功后移除旧库，避免重复提醒；已确认新版存在数据时采用合并导入，保留新版已有数据。本决策替代此前“不自动寻找旧库、始终保留旧路径原库”的规则。

## 启动与交互

- Windows 默认检测 `%APPDATA%/com.ddmoyu.javm/javm.db`，1.0 使用 `%APPDATA%/JAVM/library.sqlite3`。原生端从新版数据目录的父目录定位固定旧路径，前端不能指定任意待删除文件。
- 启动检测只检查文件及成功记录，不打开或升级旧库，也不要求当前库先升级成功；当前库尚未创建时不会因探测而创建。发现未导入旧库时显示 Mantine 引导，说明合并规则、备份与成功后移除旧库的行为。
- “开始导入”才会执行；“稍后导入”或关闭引导保留旧库，下次启动仍可提醒，同一会话可从“系统设置 → 片库与迁移”重新打开。浏览器预览不扫描本机 AppData。
- 显示备份、合并、校验和清理进度。运行时不能误关引导，可取消；失败显示原因并允许重试。请求超时会继续查询真实状态，不重复提交。

## 数据安全与合并

1. 要求旧程序退出。原生端用 Windows 文件共享权限拒绝已有写入者，并在导入期间阻止旧程序重新写入。发现链接、同一文件、未知版本或异常结构时终止。
2. 通过 SQLite Backup API 分页取得一致性副本，包含已提交 WAL 数据；分别保存旧库原始副本 `legacy-original.db` 和新版导入前副本 `new-before-import.db`，位于新版数据目录的 `backups/legacy-<UUID>/`。备份先写 `.partial`，通过完整性检查后再改名。
3. 只读取 0.5.3 的 schema 2，按 [作品与资源模型](0021-metadata-first-library.md) 转换到 1.0 schema 1。不在旧库上升级，也不保留开发期 schema 2–6 的升级链。
4. 在新版单个事务中导入作品、视频资源及资料关系，按规范路径、来源身份和唯一番号匹配。新版已有非空资料、收藏优先，旧资料补空；演员/分类/标签根据名称关联。身份冲突明确报错并回滚，离线视频保留资源记录。
5. 全部原始表逐行保存到 `legacy_records`，CBOR 保留未知字段与 BLOB，同时保留完整旧库备份。历史下载、刮削任务和当前没有对应界面的扩展资料只归档，不转换成运行中的新任务；不将旧表复制进新运行时结构。
6. 校验旧库关联及新库完整性与外键，再将完成记录和导入数据共同提交。取消、磁盘满或失败回滚，原库不删除；未完成备份在收尾时清理。
7. 提交成功后确认旧路径仍对应受保护的同一文件，再移除旧 `javm.db` 及其 `-wal`、`-shm`、`-journal` 文件；不删除旧目录、图片或其他配置。保留可恢复备份。
8. 文件清理失败或提交后进程中断，也可通过已提交的完成记录避免重复提醒或重复导入；不会在下次启动时擅自删除重新出现的旧库。界面在本次清理失败时说明残留文件。

## 执行与边界

- 通过官方 Extension 的 `library.legacy.*` 请求执行，应用级 TypeScript 服务独立于 React 挂载；原生单后台任务与扫描互斥，所有数据库操作离开 UI 线程。
- 复用有界请求队列，状态和取消走内存通道，不等待数据库写锁。前端最多每 500ms 轮询一次，异常时退避至 1500ms。备份按页、合并按行检查取消，SQL 安装进度回调；应用退出时取消并等待后台回滚。
- 导入期间不受理其他媒体库操作；成功后递增媒体库修订号并刷新目录、统计及分页查询。
- 本功能迁移旧主数据库。旧配置、MetaTube 独立数据库及旧业务执行恢复不在本轮范围。
- 验证只使用独立合成数据库，不打开真实用户旧库。1.0 模型验证入口为 `legacy-1.0-native.integration.test.ts`，原有锁定、WAL、取消与探测用例继续维护，浏览器验证使用 `tests/fixtures/legacy-import` 的独立原生宿主。
