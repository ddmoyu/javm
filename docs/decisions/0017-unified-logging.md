# 统一应用日志与关于页面精简

日期：2026-10-10。按用户要求，应用版本只在“关于 JAVM → 当前版本”显示，移除品牌区域和设置侧栏的重复版本号，移除运行环境。下载与其他业务共用一个日志入口。

## 日志策略

- 在“设置 → 关于 JAVM → 应用日志”查看，支持按级别筛选、刷新和打开日志目录；下载页移除独立的日志区块，继续显示任务状态、进度和失败原因。
- 文件位于 `${NL_DATAPATH}/logs`。统一使用 UTF-8 JSONL，每条包含 UTC 时间、级别、模块、事件、会话 ID、递增序号及少量关联字段。
- 单文件最多 5 MiB，最多 10 个文件（含当前文件，合计上限 50 MiB），保留 7 天。写入到达大小上限或 UTC 日期变化时换文件；启动、写入、读取和每小时维护时清理。期限按文件创建时间计算，持续空闲时最多延后一次维护周期。
- 同时触及多个限制时优先清理旧文件，只识别并删除自身命名格式的 `.jsonl`，不清理目录中的其他文件。7 天是最长保留期限，容量达到上限时更早删除。
- 默认记录 info、warn、error，省略高频百分比进度与 debug。应用、下载、扫描、播放、网络测试、资料服务、设置、数据库错误和受管进程的关键事件进入统一流。

### 扫描诊断补充（2026-10-19）

- 每个扫描任务仅在开始和终态记录日志，不随 500ms 进度轮询重复输出。`scan_partial` 使用 warn，明确标为“扫描部分完成”；`scan_failed` 保留 error。取消和正常完成不生成失败报告。
- 结果记录发现、处理、新增或更新、未变化、跳过及错误数量。处理项包括视频与 NFO；目录级错误也计入 errors，不能将 processed 减 errors 当作成功视频数。
- 终态另记总耗时、并发上限、探测峰值、单进程超时阈值、全部探测超时次数、兼容警告数及存储类型。Windows 在原生后台读取卷类型，区分 fixed/removable/remote/optical/ramdisk；不能据此区分 SSD/HDD 或保证识别 USB 硬盘，其他平台或读取失败记 unknown。
- 按失败阶段累计全部错误；最多记录前 30 个异常样本的序号、阶段、扩展名、已取得的文件大小与阶段耗时。probe 阶段耗时包含等待探测名额和终止子进程，不等同于 MediaInfo 纯解析耗时。缺少字段时省略，不用 0 代替未知。
- 样本记录失败文件路径和原始错误原因，由统一清理器隐藏用户名与凭据，保留文件名。诊断、阶段计数和样本条数先写入日志，最后生成终态反馈，使反馈前文包含这些信息。短上下文保持最多 8 个字段，路径放入独立的 `reproduction` 字段；日志轮转与反馈摘录总量上限不变，较长路径可能使摘录无法容纳全部样本。
- 兼容未提供诊断字段的原生扩展，此时阶段汇总明确标记为样本统计，不将前 30 个错误推断为全部错误分布。

### 资料查询诊断补充（2026-10-19）

- MetaTube 搜索与详情使用独立查询 ID，刮削同时传递任务 ID；重试沿用查询 ID，按来源、结果类别及缺失字段合并次数和累计耗时，结果数量保留最后一次观测。仅在逻辑查询结束时输出来源记录和汇总；不逐次复制完整来源列表。
- 查询使用受管进程启动时的实际网络配置和版本快照，记录 `direct`、`proxy/协议` 或 `unknown`，不记录代理地址或凭据。修改设置不改变在途查询快照，后续新进程使用新配置。应用直连不等于操作系统没有 VPN/TUN。
- 内置组件通过请求自己的 HTTP 响应返回 schema 1 诊断，搜索无结果的 404 仍带诊断。分类包括有结果、无结果、不支持编号格式、拒绝访问、限流、证书、DNS、超时、连接、解析、字段不完整和未知错误。仅包含来源名、类别、结果数、耗时和缺失字段名，不包含查询文本、标题、描述、URL、Cookie 或原始异常。
- 不支持编号格式的来源归为 skipped，仅进入汇总。每份查询最多保留 64 组来源记录，超过上限计数并标记诊断不完整。旧组件无法提供来源诊断时明确记录未知；旧 stdout 标记 legacy_engine，不用它推断某次查询的根因。
- 界面按分类给出提示，404 不直接指向代理；纯无结果在刮削中进入待确认状态，主动取消不产生故障报告，请求截止时间到达仍按超时处理。包含限流、超时及连接等暂时错误时沿用现有有界重试；仅有访问拒绝、证书、解析或不完整资料时不重试。
- 组件诊断补丁纳入组件配方和本地产物校验；保持来源实现、SQLite 缓存结构和原有 API 数据字段兼容。

## 实现与边界

应用级 `LogService` 独立于 React 挂载；主窗口统一写文件，播放器通过已有 BroadcastChannel 回传。文件访问全部使用官方 Neutralino 异步 API，不引入日志框架、额外服务或数据库表。Neutralino 自身不另写无大小限制的 `neutralinojs.log`。

待写队列最多 500 条，每批最多 16 条，默认延迟 250ms 合并写入。队列溢出时保留错误优先，记录丢弃计数；写入失败保留有界队列，每 10 秒重试并显示错误。故障不阻断业务。正常退出在任务停止后尝试排空，最多等待 3 秒，强制结束或持久磁盘故障仍可能丢失末尾记录。

查看器最多显示近期 200 条，各文件仅读取最后 128 KiB，兼容携带完整业务链接的日志行；按二进制读取并解码，丢弃起始残行与损坏末行，避免截断中文 UTF-8 后无法返回。界面按会话和序号去重；写入结果不明确时重试可能使原始文件出现重复记录。

日志不接收设置对象、请求体或工具参数。按用户要求保留番号、查询内容、文件名以及 HTTP/HTTPS 业务地址（包括查询参数与签名），隐藏 URL 中的用户名密码、SOCKS 代理地址、常见授权头、Cookie、独立命名密钥与本机用户目录名。下载工具文本继续过滤请求头值，但保留 Referer/Origin 地址。不承诺识别任意非结构化文本中的所有秘密。

复现信息放在独立、固定字段的 `reproduction` 中，不占用短上下文 8 项 / 160 字符的额度；单个链接最多 8192 字符，路径最多 4096 字符，查询内容最多 500 字符，超长链接明确标记未包含。预览、JSONL、反馈快照及复制使用相同清理规则，重新读取不会再次隐藏业务链接。播放、下载、资源解析、在线查询及资料刮削的失败按实际对象补充字段，不记录网页正文、封面、视频内容或请求头。

旧任务 `log` 字段仅用于兼容导入：最近 7 天的末尾最多 80 行分批脱敏写入，确认写入完成后通过原有修订号更新清空旧副本；失败、超时或退出时保留原数据，下次启动再试。超过 7 天的旧记录直接过期。旧行没有独立时间戳，导入时间作为日志时间，并保留任务原更新时间。新诊断不再追加到任务 JSON。

浏览器预览没有原生文件权限，显示日志仅桌面端可用。测试和验证边界见 [验证记录](../verification/2026-10-10-unified-logging.md)。
