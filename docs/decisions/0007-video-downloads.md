# 视频下载与合并

2026-10-09。按用户要求，参考旧版下载流程，将 Windows 桌面端的新建下载、下载列表和下载设置接入真实任务服务。支持 HTTP / HTTPS MP4 直链和 HLS m3u8，下载后生成带可识别音视频轨的 MP4；不以进程退出码单独判定成功。

## 使用方式

在“下载管理 → 新建下载”中粘贴直链，每行一条，选择保存目录后加入队列。可展开选项设置文件名、资源类型和 Referer、Cookie 等请求头。没有 `.m3u8` 后缀的 HLS 地址应手动选择 HLS；网页地址需要先取得媒体直链。

列表支持暂停、继续、失败重试、只重试合并、停止任务、播放文件及打开目录。日志统一在“设置 → 关于 JAVM → 应用日志”查看，下载任务只保留状态、进度与失败原因，见 [统一日志](0017-unified-logging.md)。移除记录不会删除文件；停止任务保留临时文件，但不再排入队列。重新启动后，未完成任务显示为已暂停，由用户决定继续。

列表顶部可调整同时下载数，默认为 2，支持 1–5 个任务。提高上限会启动排队任务；降低上限不打断已经运行的任务。历史记录按每页 50 个显示。下载记录总量上限为 1000 条，包含已完成、暂停和失败的任务；达到上限后可移除已结束记录腾出容量，文件仍保留。旧数据库已有的超限记录可以继续读取、更新和移除，不自动删除。

“进度 / 文件大小”显示已下载字节数与总大小。MP4 根据下载器提供的长度显示；HLS 分别汇总音频和视频，预测总大小带“约”，无法取得总量时显示“总大小未知”。合并成功后读取最终 MP4 的文件属性，显示实际文件大小；旧的完成记录在启动后异步补齐，不读取视频内容。

“设置 → 下载与存储”保存默认目录和同时下载数。下载完成后始终自动合并为一个 MP4 文件，不提供独立的合并设置项。下载工具随软件打包，界面不提供工具路径输入或文件选择；保留的工具检查会实际启动程序。代理统一在“设置 → 网络与代理”中配置和启用。纯浏览器预览不生成模拟下载任务，也不保存桌面网络配置。

```powershell
pnpm desktop:setup
pnpm downloads:setup
pnpm desktop:dev
```

`desktop:dev` 和 `desktop:build` 先构建数据库扩展。`downloads:setup` 下载并校验 N_m3u8DL-RE v0.6.0-beta Windows x64 发行包，安装到 `bin/tools`；现有程序默认保留，使用 `-ReplaceExisting` 可重新校验安装。安装脚本同时复制上游 MIT 许可。

桌面打包在 `build/desktop-package-*` 独立暂存目录运行官方 CLI，只复制配置、前端产物、Windows 宿主和声明的运行依赖。不要在项目根目录直接执行 `neu build`：该 CLI 会将整个根 `.tmp` 打包并清空，可能包含正在使用的测试数据库。使用 `pnpm desktop:build` 可以保留这些本地资料。

分发前将精简 FFmpeg 等组件放入 `bin/tools`；开发环境仍兼容系统 PATH 和已保存的旧工具路径。媒体轨道和时长检查通过官方 Extension 复用 MediaInfo，不再使用 ffprobe；旧设置中的 ffprobe 路径被忽略。也可运行 `pnpm downloads:setup -FfmpegDirectory 'D:\ffmpeg'` 将已有工具复制到 `bin/tools`。打包复制该目录；分发时保留所采用 FFmpeg 发行版的许可文件。

## 统一代理与直连优先

应用级 `NetworkSettingsService` 管理代理开关和地址，通过官方 `Neutralino.storage` 异步持久化，不依赖设置页挂载。当前提供手动 HTTP、HTTPS、SOCKS5 代理；没有启用代理时只使用直连。下载配置不再持有独立代理字段。旧下载代理仅在没有已保存的全局网络设置时迁移；用户已经保存的选择（包括关闭代理）优先。

网络设置页提供“测试代理”，使用当前填写的地址，无需保存，也不会写入设置。通过官方进程 API 异步运行 curl，强制经指定代理请求 `https://www.gstatic.com/generate_204`，保留 TLS 证书验证，只有收到预期的 HTTP 204 才显示成功和请求耗时。显式清空 `noproxy`，不允许环境绕过或直连回退；连接超时 5 秒，总请求超时 15 秒。测试最多并发一项、不排队，可取消，退出时等待进程收尾；修改地址后清除旧结果。界面移除“连接策略”说明卡片，实际下载策略保持本节约定。

每次下载或继续下载先明确禁用工具的环境/系统代理。curl 使用空 `proxy` 和 `noproxy="*"`；N_m3u8DL-RE 使用 `--use-system-proxy false`。直连出现 DNS、连接、超时或 HTTP 访问错误时，读取统一代理并最多切换线路一次。curl 的代理重试清空 `noproxy`，避免 `NO_PROXY` 环境变量跳过已配置的代理。HLS 通过显式 `--custom-proxy` 使用代理；工具自身绕过本机地址的行为仍保留。

暂停、取消、工具启动失败、磁盘写入失败、续传校验失败和 MP4 合并失败不触发代理切换。HLS 没有细分网络退出码，只在日志有网络错误证据，或固定版本停在加载清单阶段时回退。工具自身的有限分片/清单重试仍保留；“重试一次”表示直连到代理的线路切换次数。

HTTP 切换线路继续复用临时文件和 ETag / Last-Modified 校验。HLS 复用分片目录，每次下载尝试均使用新的源轨输出目录，包括暂停后继续、失败重试及切换代理；只收集本次尝试生成的源轨，避免下载器对重名文件改名后选中旧的半成品。统一应用日志记录直连与代理切换及关联任务 ID，不显示代理凭据；最终成功仍需通过文件、音视频轨道和时长校验。

网络配置目前接入下载流程，未扩展到尚未接入的刮削、AI 等服务。保存后用于后续连接尝试，正在传输的任务不被中断。实现依据：[Neutralino 存储 API](https://neutralino.js.org/docs/api/storage/)、[curl 代理参数](https://curl.se/docs/manpage.html#--proxy) 和 [N_m3u8DL-RE 代理处理](https://github.com/nilaoda/N_m3u8DL-RE/blob/v0.6.0-beta/src/N_m3u8DL-RE/Program.cs)。

## 下载与合并流程

| 阶段       | 实现                                                                                | 完成条件                                                  |
| ---------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------- |
| HTTP 下载  | curl 跟随重定向、写入 `download.part`，续传使用 Range 与保存的 ETag / Last-Modified | 返回码成功；有长度声明时，本地总字节数必须一致            |
| HLS 下载   | N_m3u8DL-RE 解析主播放列表，选择音视频流，并发下载分片，保留分片与合并后的源轨      | 下载器成功退出，且媒体输入存在、非空                      |
| 音视频合并 | MediaInfo 检查输入，FFmpeg 以 `-c copy` 封装 MP4，映射视频和可用音频                | FFmpeg 成功；输出非空、有视频、有预期音频、时长未明显缩短 |
| 发布结果   | 同一任务目录内把临时 MP4 移动为最终文件                                             | 不覆盖现有目标；成功后清理任务专属临时目录                |

每个任务创建独立的“文件名加任务 ID”目录，临时文件位于其 `.javm-download` 子目录。源轨列表在合并前写入 SQLite；合并失败保留源轨，再次继续只执行合并。若已写出最终文件但尚未提交完成状态，恢复时重新校验该文件。

HLS 沿用旧版的 N_m3u8DL-RE 引擎；新实现将下载阶段和最终 MP4 合并分开管理。HTTP 直链使用 curl，默认优先使用随包的 `bin/tools/curl.exe`，开发环境兼容已保存的工具路径和系统 PATH。合并使用 FFmpeg 无损封装，不自动转码；不兼容 MP4 的编码会报告失败并保留输入。

HLS 显式使用 `--select-video best --select-audio best`，按下载器规则选择最佳视频和一条最佳音轨。`--auto-select` 在多语言源中可能选出多个音轨，而当前产物只映射一个音轨，不能依赖文件名排序决定语言。当前不提供语言偏好设置；“最佳”不保证选择源站声明的默认语言。

N_m3u8DL-RE 的管道输出可能将进度行连续拼接，且大小、速度、百分比之间没有空格。HLS 使用独立的增量拆行器，以包含 ETA 的完整进度行作为边界；跨数据块保留残片，按去除进度条后的轨道名称汇总大小。真实原始输出保存在 `tests/fixtures/downloads`，回归必须验证下载期间的大小，不能只检查合并后的文件。

解析兼容速度后的 `(1)` 等数字附加标记、ANSI 转义、CR/LF 和进程结束时的残片。等待中的音轨尚无大小时，显示已下载字节数和“总大小未知”，进度暂按各轨道百分比平均；全部轨道有大小后再按字节加权。进度四舍五入为 `100.00%` 但分片未齐时，不判定完成。无效计数、非有限数值被丢弃，日志和残片有长度上限，截断不拆开 UTF-16 代理对。

参考旧版的限长日志、增量缓存、正常/完成行解析和节流思路，按当前 TypeScript 服务重新实现。单条 `Binary merging...` 日志只表示下载器在合并某一轨道的分片；此时另一条音轨可能还没开始下载，因此最终合并阶段以下载进程退出、媒体输入校验为边界。

## 服务与生命周期

- `DownloadService` 在 React 挂载前建立，页面切换或 StrictMode 不创建第二个队列。并发任务数为 1 到 5，HLS 每任务最多 8 个分片请求线程。
- 网络和媒体工具均在子进程中异步运行，所有任务共享一个约 200 毫秒的进度刷新计时器，进度持久化最多约每 2 秒一次；阶段切换和停止立即保存。异步写库期间继续收到的进度不会被旧的保存结果覆盖。
- 下载进度由下载页面直接订阅，不经过应用级共享状态触发其他页面重绘；离开下载页后停止该页订阅，后台队列继续工作。新建下载与设置只订阅稳定的控制状态，不随进度刷新。此处遵循 React [`useSyncExternalStore` 快照约定](https://react.dev/reference/react/useSyncExternalStore)，不依靠 `startTransition` 将外部状态更新变成非阻塞更新。
- 通过官方 Neutralino `os.spawnProcess` 获取运行时 ID / PID，流式接收 stdout / stderr。PowerShell 使用 `ProcessStartInfo` 启动工具，参数按 Windows 规则引用；长 URL 和请求头由短期 JSON 参数文件传入，不作为 shell 语法执行。
- 暂停或停止通过官方进程 API 关闭监督器的标准输入；监督器持有实际工具进程句柄，停止工具及其子进程并等待退出，随后保存任务状态。curl、N_m3u8DL-RE、FFmpeg 与工具检查均采用此方式，避免强杀外层 shell 与工具刚启动之间的竞态。停止无法确认时阻止新任务与退出，允许重试停止。
- 页面重载先回收当前宿主会话记录的工作进程，按登记的协作取消方式发送 EOF 并确认退出；超时保留登记供再次恢复。工作进程监测宿主退出，在宿主意外结束时停止所属工具，防止残留进程继续写文件。下载服务在同一页面内重新读库时不重复回收其他服务新启动的进程。
- 写库失败时冻结新任务调度，并在下载页提供“恢复下载服务”。恢复先停止执行中的下载并确认所有未决进程已经退出，再从数据库读取实际修订号，将未完成任务保存为已暂停；保留下载/合并阶段和源文件，由用户手动继续。读库或停止仍失败则保留错误并允许再次恢复；不删除数据库、不重放可能已提交的旧写入。完成任务遗漏的刮削交接在恢复后重新尝试。
- 数据库扩展持有本地 IPC 监听进程的句柄。宿主异常退出后先留 2 秒供 IPC 正常收尾，仍未退出则结束扩展自身，释放所有者锁及媒体探测 Job。SQLite 下次启动恢复已提交的 WAL，未提交事务回滚；正常退出仍走任务停止和数据库关闭流程。
- 主窗口默认关闭后隐藏到托盘；关闭“关闭窗口后留在托盘”设置后，关闭主窗口直接走停止任务、保存状态和退出流程。显式退出及托盘不可用时同样正常收尾，详见 [可选后台运行](0016-optional-background-running.md)。

## 数据与边界

下载数据库为 `${NL_OSDATAPATH}/JAVM/downloads-v1.sqlite3`，独立于旧版媒体库。SQLite 扩展使用官方 stdin 引导 JSON，后续请求和响应都经过官方 Extension WebSocket；不建立业务 stdin/stdout 协议。

数据库有应用标识和版本检查、WAL、修订号冲突检测及 Windows 独占所有者锁。遇到不兼容的现有文件返回错误，不删除、不重建。应用内只暴露任务和设置操作，不接受任意 SQL。下载链接和请求头为本机续传所需数据，保存在本地任务记录；界面日志隐藏 URL 和请求头值。

下载任务按创建时间和 ID 稳定分页，每次最多 100 条，任务载荷约束在 1 MiB 内，前端在相邻页面之间让出事件循环。数据库新增对应排序索引；前端和数据库均限制新增后的任务总量不超过 1000 条。分页读取不截断原有历史记录；前端与数据库扩展需同步更新，不兼容的分页响应会显示错误。

当前范围为 Windows、可取得的 HTTP / HTTPS 视频直链、VOD HLS 和下载结果合并。未实现网站资源嗅探、磁力 / BT 引擎、DRM 解密、自动刮削入库、多语言轨选择、字幕合并或任意本地影片拼接。链接过期、资源变化或服务器拒绝 Range 时会保留现场并报错，不把不完整文件标为成功。
