# 视频下载与合并

2026-10-09。按用户要求，参考旧版下载流程，将 Windows 桌面端的新建下载、下载列表和下载设置接入真实任务服务。支持 HTTP / HTTPS MP4 直链和 HLS m3u8，下载后生成带可识别音视频轨的 MP4；不以进程退出码单独判定成功。

## 使用方式

在“下载管理 → 新建下载”中粘贴直链，每行一条，选择保存目录后加入队列。可展开选项设置文件名、资源类型和 Referer、Cookie 等请求头。没有 `.m3u8` 后缀的 HLS 地址应手动选择 HLS；网页地址需要先取得媒体直链。

手动新建和资源链接下载都会检查重复番号，包括下载列表中保留的已完成记录及本次批量中的重复项。发现重复时显示小型确认弹框，选择“继续添加”后才保存并启动新任务；取消、关闭或按 Esc 会放弃本次新增。等待确认不会阻塞其他下载，退出应用时自动取消待确认请求。

列表支持暂停、继续、失败重试、只重试合并、停止任务、播放文件及打开目录。日志统一在“设置 → 关于 JAVM → 应用日志”查看，下载任务只保留状态、进度与失败原因，见 [统一日志](0017-unified-logging.md)。移除记录不会删除文件；停止任务保留临时文件，但不再排入队列。重新启动后，未完成任务显示为已暂停，由用户决定继续。

列表顶部可调整同时下载数，默认为 2，支持 1–5 个任务。提高上限会启动排队任务；降低上限不打断已经运行的任务。历史记录按每页 50 个显示。下载记录总量上限为 1000 条，包含已完成、暂停和失败的任务；达到上限后可移除已结束记录腾出容量，文件仍保留。旧数据库已有的超限记录可以继续读取、更新和移除，不自动删除。

“进度 / 文件大小”显示已下载字节数与总大小。MP4 根据下载器提供的长度显示；HLS 的总大小是估算值，带“约”，算法见下文“HLS 大小估算”。合并成功后读取最终 MP4 的文件属性，显示实际文件大小；旧的完成记录在启动后异步补齐，不读取视频内容。

“设置 → 下载与存储”保存默认目录和同时下载数。下载完成后始终自动合并为一个 MP4 文件，不提供独立的合并设置项。下载工具随软件打包，界面不提供工具路径输入或文件选择；保留的工具检查会实际启动程序。代理统一在“设置 → 网络与代理”中配置和启用。纯浏览器预览不生成模拟下载任务，也不保存桌面网络配置。

2026-10-14：下载设置统一使用官方 Neutralino Storage 的 `javm-download-settings-v1`，与网络、播放、界面、后台运行、片库监控及刮削偏好共用 `nativeSettingsStorage`。官方记录缺失时校验并迁移 SQLite `download_settings` 中的默认目录、并发数和兼容保留的工具路径；旧代理继续由网络服务迁移，已停用的下载器／探测器字段不带入新配置。读取失败、格式损坏或迁移保存失败均报告错误，保留原记录，不用默认值覆盖，也不双写 SQLite；保存成功后才更新生效设置。旧表和协议保留用于历史兼容。

迁移在下载分页读取结束后、实际写入前再次检查官方记录，并与同键的正常保存串行执行；分页读取期间新增的配置优先。目标记录存在时不再解析或写入旧下载设置。全局代理迁移使用同一保护，包括用户明确关闭代理的记录。完整设置清单和异常处理约定见 [普通设置统一与迁移保护](0005-mantine-interface.md#普通设置统一与迁移保护2026-10-14)。

应用设置按功能分键保存在 Storage，避免不同服务整份覆盖彼此的配置。SQLite 继续保存媒体资料、目录关联、下载／刮削任务和播放进度。AI、MetaTube 等含密钥的配置沿用现有保护：Windows 加密后进入 Storage，macOS/Linux 使用系统密钥库；这些不改为普通明文配置。

```powershell
pnpm desktop:setup
pnpm downloads:setup
pnpm desktop:dev
```

`desktop:dev` 和 `desktop:build` 先构建数据库扩展。HTTP 与 HLS 都使用随包 curl，`downloads:setup` 只负责把已有 FFmpeg 复制到 `bin/tools`；完整运行依赖由 `offline:setup` 构建。

桌面打包在 `build/desktop-package-*` 独立暂存目录运行官方 CLI，只复制配置、前端产物、Windows 宿主和声明的运行依赖。不要在项目根目录直接执行 `neu build`：该 CLI 会将整个根 `.tmp` 打包并清空，可能包含正在使用的测试数据库。使用 `pnpm desktop:build` 可以保留这些本地资料。

分发前将精简 FFmpeg 等组件放入 `bin/tools`；开发环境仍兼容系统 PATH 和已保存的旧工具路径。媒体轨道和时长检查通过官方 Extension 复用 MediaInfo，不再使用 ffprobe；旧设置中的 ffprobe 路径被忽略。也可运行 `pnpm downloads:setup -FfmpegDirectory 'D:\ffmpeg'` 将已有工具复制到 `bin/tools`。打包复制该目录；分发时保留所采用 FFmpeg 发行版的许可文件。

## 统一代理与直连优先

应用级 `NetworkSettingsService` 管理代理开关和地址，通过官方 `Neutralino.storage` 异步持久化，不依赖设置页挂载。当前提供手动 HTTP、HTTPS、SOCKS5 代理；没有启用代理时只使用直连。下载配置不再持有独立代理字段。旧下载代理仅在没有已保存的全局网络设置时迁移；用户已经保存的选择（包括关闭代理）优先。

网络设置页提供“测试代理”，使用当前填写的地址，无需保存，也不会写入设置。通过官方进程 API 异步运行 curl，强制经指定代理请求 `https://www.gstatic.com/generate_204`，保留 TLS 证书验证，只有收到预期的 HTTP 204 才显示成功和请求耗时。显式清空 `noproxy`，不允许环境绕过或直连回退；连接超时 5 秒，总请求超时 15 秒。测试最多并发一项、不排队，可取消，退出时等待进程收尾；修改地址后清除旧结果。界面移除“连接策略”说明卡片，实际下载策略保持本节约定。

每次下载或继续下载先明确禁用工具的环境/系统代理：curl 使用空 `proxy` 和 `noproxy="*"`。直连出现 DNS、连接、超时或 HTTP 访问错误（curl 退出码 22，含 403）时，读取统一代理并最多切换线路一次；403 也重试，是因为按地区限制的 CDN 可能在代理线路上放行。curl 的代理重试清空 `noproxy`，避免 `NO_PROXY` 环境变量跳过已配置的代理。HTTP 与 HLS 共用同一套 curl 退出码判断。

暂停、取消、工具启动失败、磁盘写入失败、续传校验失败和 MP4 合并失败不触发代理切换。curl 的 `--retry 2` 只处理瞬时错误；“重试一次”表示直连到代理的线路切换次数。

HTTP 切换线路继续复用临时文件和 ETag / Last-Modified 校验。HLS 切换线路、暂停后继续和失败重试都复用已完成的分片，只下载缺失部分。统一应用日志记录直连与代理切换及关联任务 ID，不显示代理凭据；最终成功仍需通过文件、音视频轨道和时长校验。

网络配置目前接入下载流程，未扩展到尚未接入的刮削、AI 等服务。保存后用于后续连接尝试，正在传输的任务不被中断。实现依据：[Neutralino 存储 API](https://neutralino.js.org/docs/api/storage/) 和 [curl 代理参数](https://curl.se/docs/manpage.html#--proxy)。

## 下载与合并流程

| 阶段       | 实现                                                                                | 完成条件                                                  |
| ---------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------- |
| HTTP 下载  | curl 跟随重定向、写入 `download.part`，续传使用 Range 与保存的 ETag / Last-Modified | 返回码成功；有长度声明时，本地总字节数必须一致            |
| HLS 下载   | curl 读取播放列表，TS 选择音视频轨并生成分片清单，单个 curl 进程并行下载分片        | 每个分片都返回 2xx 且非空；本地播放列表引用的文件齐全     |
| 音视频合并 | FFmpeg 读取本地播放列表（HLS）或经 MediaInfo 检查的输入，以 `-c copy` 封装 MP4      | FFmpeg 成功；输出非空、有视频、有预期音频、时长未明显缩短 |
| 发布结果   | 同一任务目录内把临时 MP4 移动为最终文件                                             | 不覆盖现有目标；成功后清理任务专属临时目录                |

每个任务创建独立的“文件名加任务 ID”目录，临时文件位于其 `.javm-download` 子目录。源轨列表在合并前写入 SQLite；合并失败保留源轨，再次继续只执行合并。若已写出最终文件但尚未提交完成状态，恢复时重新校验该文件。

HTTP 直链和 HLS 都使用 curl，默认优先使用随包的 `bin/tools/curl.exe`，开发环境兼容已保存的工具路径和系统 PATH。合并使用 FFmpeg 无损封装，不自动转码；不兼容 MP4 的编码会报告失败并保留输入。

### HLS：curl 并行下载与本地合并（2026-10-12 修订）

原先由 N_m3u8DL-RE 下载 HLS。实测一个使用 Cloudflare 的来源会按客户端拒绝 .NET 的 HTTP 客户端：请求头完全相同时，curl 返回 200，.NET HttpClient、.NET Framework 和 N_m3u8DL-RE 一律 403；把请求头互换后结果仍跟着客户端走，与请求头无关。下载器的 `-H` 只能改 HTTP 请求头，改不了 TLS 握手指纹，因此改为 curl 实现，并移除 N_m3u8DL-RE。

1. 用 curl 读取播放列表（限 16 MiB，以重定向后的地址解析相对路径）。主播放列表选最高码率视频；音频在该清晰度声明的完整音轨组里先选 `DEFAULT=YES`，否则选组内第一条。所选音轨没有 URI 时表示封装在视频里（RFC 8216 4.3.4.2.1），不另外下载，也不会改用组内其他独立音轨。
2. TypeScript 把媒体播放列表改写为本地版本：分片、`EXT-X-MAP` 初始化段和 AES-128 密钥都换成任务目录内的文件名，相同地址只下载一次，`EXT-X-BYTERANGE` 原样保留给 FFmpeg 读取本地文件。没有 `#EXT-X-ENDLIST` 的直播或事件流、SAMPLE-AES 与非 identity 的密钥格式（DRM）直接报错。伪装成 `.jpeg` 等扩展名的 TS 分片按内容命名为 `.ts`。
3. 每个任务只启动一个 curl 进程：`--parallel --parallel-max 8` 并行下载全部缺失分片，`--remove-on-error` 删除失败的半成品；所有 curl 调用都带 `--globoff`，地址里的 `[ ]` `{ }` 按普通字符处理，不会被展开成多个请求或报错。分片按“HLS 大小估算”中的跨度顺序排队。每个分片完成后，`--write-out` 经 `%{stderr}` 立即输出一行结果（stdout 写入管道会被缓冲，进度要到进程结束才出现）。TS 增量更新大小估算、用 5 秒滑动窗口计算速度，并约每 2 秒保存进度：同一时间只有一次写盘，期间的新快照只保留最新一份；先写 `state.json.tmp` 再改名替换，被中断时最多丢失最后一次更新，不会留下半截记录。
4. 继续下载时重新读取播放列表。指纹由所选清晰度与音轨的子播放列表地址，以及每个文件的本地名称与资源身份组成。资源身份包括域名、路径和查询参数，只忽略含义明确的签名与时效参数（`token`、`signature`、`expires`、`auth_key`、`hdnts`、`X-Amz-*` 等）；`t`、`e`、`ts`、`hash` 这类泛用短名可能就是清晰度或内容哈希，保留在身份里，宁可重新下载也不混用。内嵌密钥按字节内容区分。只有签名变化时，已完成分片继续有效；否则视为不同资源，全部重新下载。复用前还会按有限并发异步读取文件属性，大小必须与下载完成时记录的字节数一致；没有完成记录的文件（例如被强制结束时写了一半的分片）一律重新下载。
5. FFmpeg 以 `-allowed_extensions ALL -extension_picky 0 -protocol_whitelist file,crypto` 读取本地播放列表并 `-c copy` 封装；独立音轨作为第二个输入映射。时长按播放列表 `EXTINF` 合计核对。HLS 合并不使用 `-xerror`：HLS 解复用器在独立 TS 音轨开头会给出重复的时间戳，FFmpeg 平时会自行修正，`-xerror` 却会把它变成致命错误（fMP4 视频加 TS 音频的组合因此失败过）。结果仍需通过视频、音频与时长校验；旧下载器留下的源轨合并保留 `-xerror`。

资源解析阶段会把请求头名统一转成小写。交给 curl 前改回 `User-Agent`、`Referer` 这类标准写法：实测同一 CDN 在 HTTP/1.1 下把小写的 `user-agent` 当作机器人特征返回 403，标准写法则返回 200。HTTP 头名本身不区分大小写，规范化对其他服务器没有影响。

随包精简 FFmpeg 从 `javm-lite-3` 起启用 `crypto` 协议，用于在本地解密 AES-128 分片，见 [精简 FFmpeg](0013-lightweight-ffmpeg.md)。遇到加密播放列表时会先用 `ffmpeg -protocols` 检查；如果配置了不支持解密的 FFmpeg，在下载前就报错，不会下载到一半才失败。旧版本下载器留下、已进入合并阶段的源轨文件仍按 MediaInfo 探测结果合并。

### HLS 大小估算

下载过程中总大小只能估算，不追求完全精确；为了精确而给每个分片发 HEAD 请求，会多出与分片同样多的请求，所以不这样做。

- 规划时记下每个分片文件承载的时长（字节范围共用文件时累加），密钥和初始化段记为 0。
- 视频和音频分别按“已下载字节 ÷ 已下载时长 × 该轨道总时长”推算后相加；密钥和初始化段按实际字节计入，不参与平均。这样短的末尾分片、体积差异很大的音视频分片都不会拉偏平均值。
- 分片不按时间顺序下载：先下载密钥和初始化段，再按位反转序列在全片均匀取样，视频和音频按播放位置交错。下载到几个百分点时，样本已覆盖片头、正片和片尾。合并只看本地播放列表，与下载顺序无关。
- 尚无样本时，用主播放列表的 `AVERAGE-BANDWIDTH`（没有时用 `BANDWIDTH`）× 视频时长作为初始值；样本覆盖不足 3% 的时长时，与实测值按覆盖比例混合，超过后完全采用实测值。还没有样本的轨道用声明码率补足差额。没有主播放列表时，在第一个分片完成前只显示已知字节。
- 进度条按“已下载字节 ÷ 估算总量”计算，估算值不低于已下载字节；全部分片完成后大小即为精确值，不再显示“约”。
- 估算每个分片完成时增量更新，不随分片数平方增长；5 万个分片的排序在 200 ms 内完成。

### 不阻塞界面

播放列表最大 16 MiB，每条轨道最多 5 万个资源。实测最大规格下，解析与改写约 245 ms，生成 curl 清单约 69 ms，指纹约 59 ms，排序约 35 ms，合计远超主线程单次 50 ms 的上限。因此这些计算都放在专用 Worker（`hlsWorker.ts`）里：每次下载尝试创建一个，地址列表留在 Worker 内，只把文件名和时长回传主线程；取消时直接终止 Worker，结束后关闭。没有 Worker 的单元测试环境在当前线程执行同一套核心代码。本地文件的大小核对按 16 路并发异步读取，每次等待都会让出事件循环。 合并前核对文件和合并后校验时长所需的播放列表拆分也在 Worker 中完成。主线程上剩余的逐项处理也按 50 ms 上限检查过：5 万条记录的大小估算器初始化与回填实测约 50 ms，因此改为每 4096 项一批，批次之间让出事件循环；进度记录序列化约 11 ms，保持原样。

### 分片自动重试与合并诊断（2026-10-12 补充）

- 单个分片：curl `--retry 3 --retry-delay 1 --retry-all-errors --retry-max-time 120`，连接重置、偶发的 403/5xx 也会即时重试。
- 整轮补下载：一轮结束仍有分片缺失时，分别等待 2、5、10 秒后只重新下载缺失的部分，最多 3 轮，等待可以取消。如果某一轮没有任何进展，并且失败原因都是永久性的（404、410、无效密钥、磁盘写入失败等本地错误），就立即停止。每轮按原因汇总失败数量写入日志，例如“HTTP 503 ×2，curl 28 ×1”；最终错误也会注明已重试的次数。之后才轮到切换代理。
- 密钥文件必须正好 16 字节；否则视为被拦截，不用它解密。
- HLS 合并的输入加上 `-probesize 200M -analyzeduration 120s`。部分来源的首段不是关键帧，按默认 5 秒探测找不到视频参数，封装 MP4 时会报 “dimensions not set”。用“关键帧间隔 10 秒、去掉首段”的素材复现了这个错误，加大探测后可以正常合并，完整解码无错误；关键帧之前的帧会被 FFmpeg 按默认行为丢弃。
- 合并前写入诊断日志：各轨道的分片、初始化段和密钥数量，时长，首个文件的大小和开头 16 字节，只记录本地文件名。合并失败后再让 FFmpeg 只探测一次输入，把识别到的流信息写入日志；“dimensions not set”这类错误附带中文说明。

### 源站并发限制与停滞

有的源站限制单个 IP 的并发连接：多出的连接被接受，但一直不回应。用户日志里，8 个并行连接中有 7 个在 20 秒时同时报 `curl: (28) … 0 bytes received`，之后再无进展。现在的处理：

- 每轮下载带停滞看门狗：连续 90 秒没有任何分片结束（无论成功或失败），只结束这一轮 curl，进入下一轮补下载；用户暂停和取消不受影响。
- 一轮停滞，或连接超时数达到当前并发的一半（至少 2 个）时，下一轮并发减半，即 8 → 4 → 2 → 1。在 3 轮自动补下载内可以降到 1。
- 每 30 秒记录一次本轮进度（已结束、成功、失败数，总完成数和并发数）。curl 改用 `--no-progress-meter`，重试提示也写入日志，每轮最多 50 行。

### 伪装成图片的分片

部分来源把 TS 分片伪装成图片：在真正的视频数据前拼接一段 PNG、JPEG、GIF 或 BMP 文件头，扩展名也常写成 `.png`、`.jpeg`。FFmpeg 读到开头就按图片识别（`Stream #0:0: Video: png`），合并时报 “dimensions not set”。N_m3u8DL-RE 原本会去掉这类图片头，改用 curl 后需要自己处理。

合并前逐个检查分片开头 16 个字节（16 路并发异步读取）。识别到图片签名后，查找连续 4 个间隔 188 字节的 `0x47`，作为真正的 TS 起点。同一来源的图片头通常长度相同，所以先验证上一个分片的偏移，不命中再读取前 64 KiB 或 1 MiB 查找。规划 Worker 随后生成合并专用的 `*.merge.m3u8`，用 `#EXT-X-BYTERANGE` 让 FFmpeg 跳过图片头。分片文件、原播放列表和任务记录都不改动，已经带字节范围的分片保持原样。找不到视频数据，或加密分片带有图片头时，在合并前给出明确错误，并把处理结果写入日志。

### HLS 边界与失败处理

- 属性列表宽松解析，容忍逗号后的空格、小写属性名和缺失的 `GROUP-ID`。`BANDWIDTH` 缺失时依次按 `AVERAGE-BANDWIDTH` 和分辨率排序。只声明音频编码的变体不作为视频；相同地址的清晰度只保留一个。
- 最佳清晰度的子列表返回 HTTP 错误时，最多再试 2 个较低清晰度，并提示“当前清晰度不可用”；网络错误仍交给代理重试。
- `data:` 形式的内嵌 AES-128 密钥直接写入本地，不经网络。base64 正文按字节解码；非 base64 正文中的 `%HH` 直接还原为一个字节（RFC 2397），所以 `%FF` 这类非 UTF-8 字节也能正确处理。密钥必须为 16 字节。初始向量格式错误、缺少密钥地址、SAMPLE-AES 或其他密钥格式都在下载前报错。
- 播放列表返回空正文时，提示“服务器返回了空的 HLS 播放列表”；返回 HTML 时，提示链接可能已失效或被拦截。重定向后的相对地址按最终地址解析。
- 分片返回 2xx 但内容是不足 64 KiB 的 `text/html` 时，视为拦截页：删除该文件并计为失败，错误信息注明“返回了网页”。真实分片即使被错误标成 HTML，体积通常也远大于这个阈值。
- curl 的常见退出码附带中文说明，例如 23 表示磁盘空间或目录权限问题，28 表示超时，6/7 表示域名或连接问题。只有网络类错误会切换到代理。
- 续传指纹是同步计算的 FNV-1a，不依赖 `crypto.subtle`。被强制结束后，截断的 `state.json`、不属于当前计划的记录或非正数的字节数都会被忽略，相应分片重新下载。
- 合并阶段先核对本地播放列表引用的分片、密钥和初始化段：每个文件都必须在 `state.json` 中有完成记录，并且大小一致。记录缺失（包括整份进度记录丢失）、文件缺失或大小不符时回到下载阶段，只补有问题的部分，而不是让 FFmpeg 报错或合并出残缺视频。
- 临时配置和下载到的播放列表清理失败时静默处理，不掩盖真正的下载结果；进度记录写入失败只会导致之后多下载一些分片。

## 服务与生命周期

- `DownloadService` 在 React 挂载前建立，页面切换或 StrictMode 不创建第二个队列。并发任务数为 1 到 5；HLS 每个任务只有一个 curl 进程，进程内最多 8 个分片并行。
- 网络和媒体工具均在子进程中异步运行，所有任务共享一个约 200 毫秒的进度刷新计时器，进度持久化最多约每 2 秒一次；阶段切换和停止立即保存。异步写库期间继续收到的进度不会被旧的保存结果覆盖。
- 下载进度由下载页面直接订阅，不经过应用级共享状态触发其他页面重绘；离开下载页后停止该页订阅，后台队列继续工作。新建下载与设置只订阅稳定的控制状态，不随进度刷新。此处遵循 React [`useSyncExternalStore` 快照约定](https://react.dev/reference/react/useSyncExternalStore)，不依靠 `startTransition` 将外部状态更新变成非阻塞更新。
- 通过官方 Neutralino `os.spawnProcess` 获取运行时 ID / PID，流式接收 stdout / stderr。PowerShell 使用 `ProcessStartInfo` 启动工具，参数按 Windows 规则引用；长 URL 和请求头由短期 JSON 参数文件传入，不作为 shell 语法执行。
- 暂停或停止通过官方进程 API 关闭监督器的标准输入；监督器持有实际工具进程句柄，停止工具及其子进程并等待退出，随后保存任务状态。curl、FFmpeg 与工具检查均采用此方式，避免强杀外层 shell 与工具刚启动之间的竞态。停止无法确认时阻止新任务与退出，允许重试停止。
- 页面重载先回收当前宿主会话记录的工作进程，按登记的协作取消方式发送 EOF 并确认退出；超时保留登记供再次恢复。工作进程监测宿主退出，在宿主意外结束时停止所属工具，防止残留进程继续写文件。下载服务在同一页面内重新读库时不重复回收其他服务新启动的进程。
- 写库失败时冻结新任务调度，并在下载页提供“恢复下载服务”。恢复先停止执行中的下载并确认所有未决进程已经退出，再从数据库读取实际修订号，将未完成任务保存为已暂停；保留下载/合并阶段和源文件，由用户手动继续。读库或停止仍失败则保留错误并允许再次恢复；不删除数据库、不重放可能已提交的旧写入。完成任务遗漏的刮削交接在恢复后重新尝试。
- 数据库扩展持有本地 IPC 监听进程的句柄。宿主异常退出后先留 2 秒供 IPC 正常收尾，仍未退出则结束扩展自身，释放所有者锁及媒体探测 Job。SQLite 下次启动恢复已提交的 WAL，未提交事务回滚；正常退出仍走任务停止和数据库关闭流程。
- 主窗口默认关闭后隐藏到托盘；关闭“关闭窗口后留在托盘”设置后，关闭主窗口直接走停止任务、保存状态和退出流程。显式退出及托盘不可用时同样正常收尾，详见 [可选后台运行](0016-optional-background-running.md)。

## 数据与边界

下载数据库为 `${NL_OSDATAPATH}/JAVM/downloads-v1.sqlite3`，独立于旧版媒体库。SQLite 扩展使用官方 stdin 引导 JSON，后续请求和响应都经过官方 Extension WebSocket；不建立业务 stdin/stdout 协议。

数据库有应用标识和版本检查、WAL、修订号冲突检测及 Windows 独占所有者锁。遇到不兼容的现有文件返回错误，不删除、不重建。应用内只暴露任务和设置操作，不接受任意 SQL。下载链接和请求头为本机续传所需数据，保存在本地任务记录；界面日志隐藏 URL 和请求头值。

下载任务按创建时间和 ID 稳定分页，每次最多 100 条，任务载荷约束在 1 MiB 内，前端在相邻页面之间让出事件循环。数据库新增对应排序索引；前端和数据库均限制新增后的任务总量不超过 1000 条。分页读取不截断原有历史记录；前端与数据库扩展需同步更新，不兼容的分页响应会显示错误。

当前范围为 Windows、可取得的 HTTP / HTTPS 视频直链、VOD HLS 和下载结果合并。未实现网站资源嗅探、磁力 / BT 引擎、DRM 解密、自动刮削入库、多语言轨选择、字幕合并或任意本地影片拼接。链接过期、资源变化或服务器拒绝 Range 时会保留现场并报错，不把不完整文件标为成功。
