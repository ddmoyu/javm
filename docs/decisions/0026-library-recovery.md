# ADR 0026：日常片库备份与恢复

2026-10-11。用户授权按功能审查建议补齐备份恢复，并在所有阶段完成后检查各模块完整操作流程。字幕（包括本地关联）和多语言音轨选择明确不开发。

## 范围

- 设置的“片库与迁移”提供创建备份、选择备份、检查摘要、二次确认恢复、进度、取消和结果路径。
- 本功能是片库数据库快照，包含作品、收藏、路径关联、别名和播放进度。视频、图片、NFO 文件、下载任务及设置不纳入此快照；界面在操作前明确范围。原文件需另行保留，移动后可用现有路径关联功能修复。
- 普通备份保存到用户选择的目录；恢复前自动保留当前库及待恢复快照至应用数据目录 `backups/recovery-<UUID>`。不自动清除备份，不覆盖用户同名文件。
- 不读写实际用户数据库做开发验证，仅使用合成数据、临时目录和隔离 Extension。

## 一致性与生命周期

复用官方 Extension，C++ 后台任务按页调用 [SQLite Backup API](https://www.sqlite.org/c3ref/backup_finish.html)。临时输出通过结构、完整性、外键和文件整理状态检查后才改为正式备份。恢复重新取得源的一致性快照，不信任上次检查之后可能被替换的文件。

还原写入现有 SQLite 连接，由 Backup API 的写事务提交；取消和复制失败在完成前回滚，不采用删除数据库再重建。保留恢复前副本；运行中扫描状态改为中断，历史启动请求不重放。禁止链接、同文件恢复、错误版本、缺失结构、异常关联和未完成文件整理。

若当前片库已经损坏，仍允许启动到恢复入口。恢复前独占原文件和 SQLite 边文件，持久写入恢复标记，将原始文件逐一归档，再放入已校验的快照。重命名阶段不接受取消；中途退出后，标记阻止下次启动误建空库，可重新选择有效备份继续恢复。损坏原件仅用于排查，不标作可用备份。

备份恢复独占片库任务，运行前要求下载、刮削、扫描和文件任务空闲。恢复关闭内置播放窗口，避免旧会话重新覆盖播放进度。状态与取消走内存通道，不等待数据库写锁；UI 每 500ms 轮询，失败退避。请求超时继续确认实际任务，不盲目重试。退出先取消并等待后台收尾。

## 实施与验证

1. 备份恢复原生与服务定向安全验证已通过，覆盖损坏库与恢复中断、WAL、结构拒绝、取消和同一请求重放。
2. 安全桌面样例已贯穿取流、实际下载器、刮削、NFO/图片、片库、播放及恢复。
3. 文件操作中断恢复、完成后重复提交、监听断线重连与补扫已验证。三十分钟监听检查使用模拟时间，不等于真实 NAS 或托盘耐久验收。
4. 便携版链接注册、冲突替换及仅解除当前所有者已接入；验证仅使用隔离注册表键，未注册开发机正式协议。
5. 逐模块复核与本轮证据见[闭环记录](../verification/2026-10-11-module-closure.md)。

名单数量和中文校对属于数据工作。用户随后确认已有演员足够，本轮停止后台名单采集，保留数据与断点，添加暂停标记防止自动重启。演员搜索独立于 CSV，按需在线查询；默认保留网站顺序，没有来源证据时不称为热度。
