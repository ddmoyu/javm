# 内置磁力资源搜索

2026-10-14。用户要求参考 GitHub 实现并接入磁力搜索，在比较外部服务体积后，明确选择“内置搜索源，直接使用”。本决策替代此前“磁力暂缓”的范围限制。

## GitHub 调研与体积取舍

常见实现是按来源发送 HTTP 请求，解析网页或 JSON，转成统一结果，并按 infohash 去重。Jackett 把来源适配集中在服务端，qBittorrent 则使用搜索插件。

2026-10-14 读取官方 Release 元数据：Jackett [v0.24.2830](https://github.com/Jackett/Jackett/releases/tag/v0.24.2830) 的 Windows ZIP 为 57,040,928 字节；Prowlarr [v2.6.5.5623](https://github.com/Prowlarr/Prowlarr/releases/tag/v2.6.5.5623) 的 Windows x64 ZIP 为 135,771,253 字节。这是官方压缩包下载体积，不是 JAVM 重打包后的实测增量。单独实现外部服务客户端预计不到 1 MB，但仍要求用户另行部署服务。

按用户选择，本次用 TypeScript 实现两个内置适配器，不引入 Python 插件运行环境、Jackett/Prowlarr 程序、YAML 解释器或 DHT 索引。依赖清单没有增加第三方包。GitHub 源码提供解析依据，不证明对应站点当前可用。

## 交互

- “资源刮削 → 搜索资源”内提供“影片资料／磁力资源”切换；直接输入番号或关键词即可搜索，资料失败不会阻止磁力搜索，切换保留各自状态。
- 影片详情的资源区提供“在线视频／磁力资源”切换；磁力使用当前番号，无番号时使用片名。
- 已返回的结果立即显示，其他来源继续查询；来源失败不隐藏成功结果，可以只重试失败项。
- 显示标题、已知大小、文件数、收录时间与做种数。没有做种证据显示“未知”，不沿用上游规则里的固定值 `1`。
- 按默认顺序或文件大小排序，本地每页展示 20 条。每个来源以首批 20 条去重结果为目标，先展示第一页，再在存在明确下一页链接时自动补页；数量不足时保留实际结果，最多三页。达到目标后仍可手动加载更多。BT 目录只取已知协议的首页，不猜测分页参数。
- 支持复制磁力和显式打开系统关联的外部下载器。交接成功只显示“再次打开下载器”，不创建 JAVM 下载任务或伪造下载进度。
- 桌面复制统一使用 Neutralino 官方 `clipboard.writeText`，在 `nativeAllowList` 中只增加写入权限；浏览器预览保留浏览器剪贴板适配。用户再次明确磁力不做内部下载。

## 后台处理与边界

复用现有常驻 libcurl、应用代理、按站点限频、重定向和停止确认机制。最多两项磁力来源任务；新查询会取消旧查询，旧传输确认结束前不释放并发名额。每项请求流程限时 25 秒，单页响应最多 1 MiB、最多解析 60 条，单次查询最多保留 200 条，BTDig 最多三页。空查询不请求热门列表。

网页解码、解析、hash 规范化和批量合并均在隔离 Worker 中执行，沿用既有 Worker 的启动、执行超时及取消机制。两个来源返回后的合并串行结算，防止相互覆盖。主线程只接收有界结果、排序与展示当前页。

支持 BTIH 十六进制与 Base32、SHA-256 BTMH，以及同时声明 v1/v2 的混合磁力。相同标题不作为合并依据；跨来源相同身份汇总来源和已知字段。只保留内容标识、展示名称、大小及有界 tracker 参数；外部交接前再次校验协议和 hash。

应用级服务持有查询与结果。独立关键词搜索不会因切换页面重启；详情发起的查询在最后一个对应详情关闭后取消，StrictMode 重新挂载不会误取消。主动取消保留已返回结果；代次隔离迟到响应；清理未确认时保留重试所有权并阻止新请求；退出等待清理与已有交接结束。

本次结果保存在当前应用会话，不新增磁力数据库表。没有添加内置 BT 引擎、登录/验证码窗口或外部服务设置。
