# 片库后台查询与有界分页

日期：2026-10-09。用户要求优化目录导入后的媒体库展示与虚拟列表。

## 问题

已有 TanStack Virtual 限制海报和列表的 DOM 数量，但服务仍把每批 100 条影片累积为完整数组；搜索、筛选、排序、发现页聚合和编辑查重继续在前端遍历整库。批次间让出事件循环不能消除数据量增长带来的内存与后续主线程计算开销。

## 查询与缓存

- `LibraryService` 只持有目录、扫描状态、总数、收藏数和当前详情。每个消费页面持有独立 `PagedQuery`，通过可见范围请求数据；缓存使用按位置索引的 `Map`，不分配整库长度的影片数组。
- 每次最多 100 条，每个视图最多缓存 6 页，即 600 条影片或维度记录。缓存淘汰后，回滚会重新读取对应页。详情单独持有当前影片，不依赖该页仍在缓存中。
- 每个视图最多一个在途请求；快速输入和滚动只保留最新条件或范围。查询代次校验丢弃过期成功与失败响应；错误需显式重试，不自动循环请求。隐藏或卸载视图停止调度后续请求。
- 搜索输入防抖 180ms。查询条件变化时重新计数；同一查询后续翻页不重复计数。扫描和收藏导致 revision 改变时清空页缓存、重新计数并读取可见页。总数缩小导致末页消失时自动收缩到有效页。
- `library.query` 实现搜索、收藏范围、演员/分类/年份/画质/时长/大小/资料状态组合筛选、关联维度和 8 项升降序排序。演员与分类包含全部关联项；搜索中的 `%`、`_` 按字面匹配。
- `library.facets` 在后台聚合并分页返回演员、分类、厂商、导演、系列、年份和画质。发现页按用户 2026-10-11 的要求改为每页查询和展示 100 项，仅保留当前页，不预取相邻页；筛选下拉最多显示 50 项，允许输入关键词继续查找。
- `library.summary` 返回全库计数，`library.video` 按 ID 读取当前详情，`library.duplicateCode` 索引查重；保留原 `library.videos` 接口用于既有扫描验证，正式前端不再调用。

## 原生执行与兼容

继续使用官方 Neutralino Extension 和现有最多 64 项的原生后台队列，不增加生产服务器。分页请求受 SQLite 互斥锁保护，扫描状态与取消仍直接读取内存状态，不等待分页队列。

SQL 条件值参数化，排序、方向与维度使用白名单；每组最多 1000 个筛选值，单值最多 2048 字节。分页和维度查询设置 10 秒 SQLite progress-handler 预算。这是 SQL 执行阶段的中断预算，不承诺中断阻塞中的操作系统 I/O，也不等同于取消已发送的请求。

新增标准索引覆盖入库时间、番号、收藏及反向演员/分类关联；临时视图合并旧字段和扫描字段。自然排序使用 Windows 中文数字排序，运行时注册的函数和排序规则不进入持久索引。保留 schema 4，不改写原有影片、关系或 NFO 记录；旧库迁移仍执行原先的备份与事务策略。

排序与搜索不使用前端整库计算。带筛选的总数、深 offset 页和自然排序仍可能扫描数据库，响应时间会随数据与存储变化；超时显示可重试错误。

## 界面执行

海报和表格继续按可见范围加 overscan 虚拟渲染，缺页使用等尺寸骨架。海报懒加载并异步解码。影片行与卡片使用稳定回调和 memo，减少滚动期间重复渲染。

页面首次进入才挂载，之后隐藏保留局部状态；后台扫描服务独立运行。从详情首次跳转发现或刮削页时，在页面挂载后交付导航参数。

本次验证包括 5 万条合成数据库的真实 Extension 请求和生产构建浏览器交互；不等同于真实 NAS、海报资源或桌面 WebView2 的规模验收，具体数据见 [验证记录](../verification/2026-10-09-library-paging.md)。
