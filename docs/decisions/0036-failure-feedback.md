# 关键功能异常反馈与异常退出诊断

日期：2026-10-15。

## 已确认范围

用户要求本次覆盖所有关键功能，反馈默认包含**完整下载链接**，并在软件未正常退出后的下次启动提供反馈入口。沿用 React、Mantine、TypeScript 和 Neutralino 官方 API，不引入崩溃上报 SDK、服务器或第三方依赖。

## 使用流程

2026-10-24：新增“启用问题反馈”开关，位于“设置 → 关于 JAVM → 诊断与反馈”和反馈弹框内，共用官方 Storage 的 `javm-feedback-settings-v1` 配置，默认开启。保存成功后即时生效，失败保留原设置并提示。关闭时收起当前弹框，停止反馈采集、全局异常监听与诊断定时器，等待已发出的写入结束后清理会话标记；普通业务错误提示和文件日志保留。下次启动先读取开关，关闭时不读取诊断历史、不采集系统信息、不创建会话标记；设置读取失败时也暂不启用诊断，并显示错误。已保存的历史记录不删除，重新开启时恢复有效期内的历史，但不追报关闭期间或遗留标记对应的异常退出。手动反馈入口同样遵循开关。

1. 操作最终失败后保留现有错误提示，应用级服务保存诊断快照并显示反馈弹框。下载自动重试过程中的临时分片错误不触发弹框，最终缺失分片、下载失败或合并失败才触发。
2. 弹框显示错误原因，可展开反馈文本；提供“暂不反馈”“仅复制”“反馈问题”。收集收尾日志的 3 秒内显示进度并暂时禁用复制。
3. “反馈问题”先使用现有 `copyText` 封装调用 `clipboard.writeText`。成功后才调用 `os.open`，打开 `https://github.com/ddmoyu/javm/issues/new`。
4. 提示“反馈信息已放入剪贴板，已请求打开 GitHub Issues，粘贴提交即可”。不会登录 GitHub、自动创建 Issue 或自动上传报告。URL 中不携带报告内容。
5. 复制失败时留在弹框，可重试或手动复制预览；浏览器打开失败时明确告知内容已复制，需手动前往 GitHub。
6. 失败下载的“更多操作 → 反馈此问题”可重新打开报告；“设置 → 关于 JAVM → 诊断与反馈”提供所有模块的历史入口。

2026-10-24：关于页的卡片改为“诊断与反馈”，仅保留反馈开关、记录数量和“查看记录”入口。历史列表在右侧“诊断记录”面板中展示，面板内部滚动；选择记录后在同一面板查看详情、预览和复制诊断，或打开 GitHub 手动反馈，“返回记录”回到列表并恢复键盘焦点。关闭面板返回原设置位置。查看历史期间新异常继续入库，但不自动切换当前记录或叠加反馈弹框；关闭反馈开关也关闭面板。原有 7 天、最多 8 份诊断及短时间重复故障合并规则保持不变。

## 采集内容与边界

| 类别 | 内容                                                                                                                                                            |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 异常 | 模块、错误描述、可用的 JS 堆栈、时间、报告 ID、会话 ID、任务 ID、阶段与错误码等上下文                                                                           |
| 复现 | 操作、番号、查询内容、来源及条目 ID、请求页码、来源页面、请求地址、视频链接、失败文件路径；只记录操作中实际取得的字段                                           |
| 下载 | 完整 HTTP/HTTPS 下载链接、下载或合并阶段、类型、已下载字节数及总量                                                                                              |
| 系统 | JAVM 版本、系统名称和版本、平台和应用架构、CPU 型号与核心/线程数、物理内存总量及采集时可用量、Neutralino 与客户端版本、WebView User Agent、语言、时区、采集时间 |
| 日志 | 失败当时固定前文，再收集最多 3 秒的后文；按任务 ID 排除其他任务记录，保留没有任务 ID 的公共记录                                                                 |

系统信息通过 [Neutralino 官方 computer API](https://neutralino.js.org/docs/api/computer/) 异步获取，各项最多等待 2 秒，失败时保留其他字段。不会枚举环境变量、请求头、Cookie、设备 ID、主机名、IP、MAC 或数据库内容。系统 API 权限仅新增 `computer.getOSInfo`、`computer.getCPUInfo`、`computer.getMemoryInfo`。

报告中的日志和上下文继续隐藏常见凭据，并隐藏 Windows、macOS、Linux 用户目录中的用户名；不保证识别任意非结构化文本中的全部秘密。按照用户确认，番号、查询内容、文件名及 HTTP/HTTPS 业务链接保留，链接包含原有查询参数与签名，但去掉 URL 用户名密码。弹框明确说明这一点，提交前可预览。不会自动请求或验证报告中的链接。

复现信息独立于故障前后日志，保存、重启恢复、预览与复制均保留；避免通用短上下文截断长链接。单个链接最多 8192 字符、路径最多 4096 字符、查询最多 500 字符，超长链接明确标记。扫描按前 30 个异常样本记录失败文件与原因，数量及摘录上限见统一日志约定。此前已经脱敏的历史报告不能恢复原始地址或文件名。

## 接入点

2026-10-19：扫描部分完成的反馈类型明确为“扫描部分完成”，保留已保存结果的说明和实际计数；样本警告本身不重复生成报告。详细诊断字段及数量限制见 [扫描诊断补充](0017-unified-logging.md#扫描诊断补充2026-10-19)。

| 扫描与媒体库     | 扫描 `failed/partial` 后汇总问题；数据库请求失败/超时；文件整理、目录监视和维护操作失败                                       |
| 刮削与资料       | 任务 `failed/partial`、队列错误、资料服务及 AI 操作错误；`needsInput` 和取消不触发                                            |
| 资源搜索         | 解析最终技术错误、资源记录保存失败、磁力来源搜索/复制/外部交接/清理失败；无结果、输入校验、需要登录或交互的解析状态不自动反馈 |
| 在线查询         | 在线演员搜索部分来源失败或超时、作品列表与详情失败、请求清理失败；空结果、未匹配条目及主动关闭不触发                          |
| 播放             | 窗口创建和启动超时、指令超时、子窗口超过 120 秒无响应、媒体加载/解码失败、子播放器回传日志；正常关闭不触发                    |
| 文件与图片       | NFO/STRM 批处理最终错误；图片处理失败、超时、部分成功后的清理警告；自动封面单项失败汇总；备份/恢复失败                        |
| 设置、更新与组件 | 设置读取/保存、播放和片库显示设置格式、Windows 协议关联、维护规则读取与清理后刷新失败；更新和受管组件错误                     |
| 界面与启动       | `error`、`unhandledrejection`、React 渲染边界、可运行的启动失败页面；边界按钮始终关联该次渲染故障，报告淘汰后可重建           |

现有统一日志作为通用接入口，新增业务可以调用 `reportFailure` 显式提供结构化上下文。不是每条 error 都弹框：下载中间输出、日志/反馈模块自身错误被排除。同模块、同任务、同错误且复现对象一致的故障在当前会话 60 秒内合并；不同番号、查询、页码或链接不会只因错误文案相同而合并。自动弹框至少间隔 30 秒，一次只显示一个，其余进入历史。用户正在查看的报告不会被新的故障挤出内存。

### 资料查询的固定诊断摘要（2026-10-19）

资料查询失败时将查询 ID、组件版本、实际请求网络模式、请求次数、耗时、来源结果与缺失字段名作为独立的结构化快照保存，复制报告时显示“资料查询诊断”。此快照不依赖启动日志，也不受前后文日志裁剪影响；恢复历史报告时仍经过白名单校验，兼容没有摘要的旧报告。

同一任务重试合并为一个查询摘要，不同查询即使错误文案相同也分别保存。前后文同时按任务与查询 ID 过滤，排除其他查询以及未关联的旧组件 stdout/资料 HTTP 日志。来源记录最多 64 组，遗漏数单独列出；结果数未知时不填 0。诊断不足时明确说明不能断定未收录或代理未开启。取消和已确认的纯无结果不自动反馈。

### 来源请求与解析诊断补充（2026-10-26）

为定位 Issue #11，在 schema 1 中增加可选的失败阶段、固定原因码及 HTTP 状态。前端按白名单接收，故障报告与历史恢复保留这些字段；来源、类别、阶段、原因与状态均相同才合并计数。旧组件和旧报告没有这些字段时仍可读取。阶段仅为 `request`、`response`、`parse`；不记录网页正文、脚本、原始异常或凭据。

内置 MetaTube 的 JavBus 补丁收集异步请求错误，并检查允许解析的 HTTP 错误响应，避免超时或拒绝访问被当作空结果。所有分支结束后，只要存在有效结果就保留；没有有效结果时传递请求失败，成功但确实为空的页面仍标记为 `empty`。FANZA 保留原解析器，补充挑战页面、区域限制、响应类型异常、页面数据缺失、脚本执行失败及数据解析失败的区分；缺少页面数据本身不能证明来源接口失效。

补丁、诊断代码与安全夹具纳入 MetaTube 独立组件指纹。应用分发需先取得相应平台的新 `deps-metatube-*` 产物，继续复用其他组件。验证范围见 [Issue #11 验证记录](../verification/2026-10-26-metadata-source-diagnostics.md)。

### 资料网络不可达时的普通提示（2026-10-26）

资料查询出现来源连接、DNS、TLS 或超时故障后，才使用该次 MetaTube 启动时的有效代理配置，通过常驻 HTTP 服务检测两个固定的 HTTPS 204 地址。不使用 ICMP，不根据应用代理开关判断电脑是否有代理，也不在查询前以检测站点的可达性拦截资料请求。检测只是网络可用性的参考，不能代表所有资料站点。

两次检测均明确连接失败时，查询显示普通网络提示，不生成自动故障报告；保留逐来源诊断日志。任一检测成功、响应不符合预期或检测设施异常时，仍保留原始来源故障。纯空结果显示普通提示；纯解析、拒绝访问以及内置服务错误不因检测而隐藏。

每次 MetaTube 启动持有独立检测实例，绑定当时代理配置；最多并发两个检测请求，单请求上限 4 秒，并发查询共用检测，明确结果缓存 30 秒。查询取消后释放检测订阅，最后一个调用者离开或服务关闭时取消检测。批量任务确认网络不可达后保留为待执行并暂停队列，只显示一条恢复提示；用户点击“继续队列”后重新执行真实请求，成功无需等待检测缓存失效。

本次定向验证使用新增安全 mock 用例，不连接真实资料来源，不运行全量测试。

## 存储与性能

- 复用有大小和保留期限制的统一 JSONL 文件日志。另保留最多 400 条内存日志，以覆盖尚未刷盘和文件写入失败时的诊断。
- 每份快照前文最多 100 行且不超过 14,000 字符，后文最多 4,000 字符，错误信息最多 4,000 字符；整份可复制文本保持有界。较早日志可能不在快照中，不把摘录描述为完整日志。
- 通过官方 Neutralino filesystem 在 `NL_DATAPATH/diagnostics` 保存最近 7 天最多 8 份报告。每次写唯一的新快照文件，附 SHA-256 校验，读回通过后才回收旧文件，保留最近两份完整快照；写入中可暂存第三份。启动回退到最新的可验证快照，不覆盖唯一副本。
- 独立的小型 `session-时间-会话ID.json` 文件作为运行标记，早于系统信息和旧日志采集建立。即使正文中断，文件名也可用于识别异常退出；不会因大报告文件写坏而丢掉运行标记。恢复报告保存成功后才清理上次标记。
- 文件访问异步，写入合并且同一时刻只有一项写入，不为每条日志排队一次存储调用；收尾采集定时器数量受报告上限约束。服务独立于 React 挂载，不因 StrictMode 启动两次。
- 兼容读取旧 `failure-feedback-v1`，不覆盖旧文件。旧格式损坏不再永久禁用新反馈保存；新快照损坏可回退，读目录或写入权限异常时在弹框中提示，内存报告仍可复制。诊断自身失败不改变业务操作结果，也不递归反馈。
- 新诊断文件不进入 `.storage` 业务设置目录；更新健康检查跳过旧诊断键，仍验证其他业务设置。试运行期间等待既有写入门闩，不把等待更新提交当成诊断 I/O 超时。

## 异常退出

在取得主实例且更新写入门闩放行后建立会话标记。正常退出在任务收尾和更新交接后删除当前标记，即使最后一次报告写入失败也尝试清除；退出失败则等待旧写入结束并立即恢复运行标记。隐藏到托盘不记为退出；用户主动重新加载界面会先结束当前诊断会话。

下次启动发现上次标记未正常结束时，报告使用上次会话 ID、上次启动时保存的系统信息和磁盘中可读的对应会话日志。提示为“上次未正常退出”，可能原因包括程序崩溃、强制结束或断电，不断言具体原因；报告时间是检测时间，最后可用日志时间另外说明。

本次不包含原生 minidump、原生堆栈或外部崩溃守护进程。宿主/API/前端资源尚未可用前的失败、写入失败或强制结束前未落盘的末尾日志无法保证恢复；进程已经退出后无法补采后文。文件读回校验不等于磁盘断电持久性保证。旧任务没有快照时，手动反馈明确标记系统信息为本次反馈时采集，不伪装为失败当时的信息。
