# MetaTube 基础刮削与下载交接

2026-10-10，按用户“先实现 metatube 刮削，补上基础的刮削功能，让下载，刮削闭环”的授权实施。沿用内置 MetaTube v1.4.0，不增加运行时服务或站点解析器。

## 使用与行为

- 新建下载默认在下载、合并成功后交接刮削：检查视频 → 单文件入库 → 识别番号 → MetaTube 搜索及详情 → 封面 → NFO 与片库保存。历史下载不会在升级后自行开始刮削，已完成任务可从菜单手动补做。
- 下载完成与刮削结果独立显示。资料来源离线、封面失败、写入失败不会把下载回退为失败，也不会触发重新下载视频。
- 影片详情的补全入口可创建单片任务。“搜索资源 → 批量刮削”可以按媒体目录添加尚缺资料或全部影片；“全部”仍然只补缺失字段。
- 自动匹配仅采用番号一致的候选。支持常见字母数字番号和 FC2，无法识别唯一番号、同一来源返回多个不同 ID、详情身份不一致时进入待确认。可补番号后重试，也可搜索并点击“采用并刮削”。现有片库番号冲突需要先编辑确认。
- 队列提供阶段、错误、暂停调度、取消和重试。暂停队列不打断当前影片；进入保存阶段后等待提交完成。重启后在途记录标为已中断，由用户恢复；已经下载但尚未成功交接的任务会补交接。

## 执行与持久化

`ScrapeService` 在应用层创建，独立于 React 页面挂载、切页和 StrictMode。并发为 1，任务及历史最多 1000 条；持久化与批量读取每页 100 条，界面每页 50 条，批量添加可取消。满额时提示清理已结束记录。下载记录保存 `scrapeTaskId`，刮削记录保存 `downloadId`，重复回调复用同一个任务。

MetaTube 前台搜索与后台刮削各有一个查询槽及独立取消信号。来源参数按 v1.4.0 的单个 provider 接口逐个请求，保持配置顺序；不把多个 provider 拼成逗号串。共用服务启动和进程生命周期仍由已有 `MetaTubeService` 管理。

SQLite 任务库从 schema 1 升级至 2，新增 `scrape_jobs`，使用 revision 乐观锁。升级前用 SQLite Backup API 创建 `.pre-v2-*.bak`，保留原下载记录。媒体库采用 [作品与资源独立模型](0021-metadata-first-library.md)，不将自动来源字段写入 `_manual`。

原生 Extension 的 `library.scrape.prepare/commit/cancel` 在现有后台工作队列执行磁盘、探测、XML 及数据库操作。单文件入库更新目录计数，不宣称已完整扫描该目录。扫描、旧库导入或媒体清理正在进行时，刮削给出可重试错误。

封面使用已有受管 curl 和代理设置，限制 HTTP(S)、重定向次数、45 秒单次传输和 20 MiB 文件大小。后台原生校验 JPEG/PNG/WebP 文件头并写入规范 NFO 所在目录，已有图片文件不覆盖。进程停止未确认时冻结刮削队列，重试先清理进程；主动退出也必须完成此清理。

## 保存约定

- 只补空值和扫描生成的文件名标题；保留非空资料和 `_manual` 中的人工值，包括明确清空的值。评分从 MetaTube 的 0–5 转为片库/NFO 的 0–10；作品时长保留已有资料；缺少时回退关联视频的 MediaInfo 实测，再补来源时长。
- 成功保存必须写入作品的规范 NFO。已有 NFO 原位保存；没有 NFO 时写入应用资料目录 `metadata/<work UUID>/movie.nfo`。支持无视频收藏刮削和独立 NFO 扫描，拒绝不同作品共用 NFO、链接路径和越界引用。
- 写入前再次核对视频和 NFO 签名，外部修改后拒绝覆盖并提示重试。用 pugixml 保留未知扩展及注释，未变化演员保留角色与头像；生成规范字段、`uniqueid type="javm-work"` 和 `uniqueid type="metatube"`。
- 同目录临时文件写完后替换；已有 NFO 首次写入前保留 `.javm.bak`。XML 最多 2 MiB。NFO 在数据库事务前写入，文件与 SQLite 不具有跨介质原子性；数据库失败可重试并重新读取已落盘 NFO。
- 自动来源记录在 `works.provenance._scrape`；现有原始 NFO 快照、手工字段及文件路径保留。封面下载或格式失败时仍保存文字资料，任务标为部分完成并展示原因。

## 后续范围

同一明确作品身份可关联多个视频。本版覆盖资料刮削，不提供 MetaTube 视频下载链接搜索。自动多源字段融合、批量重命名/移动、复杂分卷识别、字幕关联、封面裁剪与截图回退、自动重试退避和更复杂番号识别留待后续。当前批量“缺失资料”沿用 `scan_status < 2`，如需补已有 NFO 的缺项可选择全部影片。

验证与实际执行范围见 [基础刮削验证](../verification/2026-10-10-metatube-scraping.md)。
