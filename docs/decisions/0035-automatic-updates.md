# ADR 0035：正式版、Beta 与旧 Tauri 兼容升级

- 日期：2026-10-14
- 状态：源码已接入，四个平台的隔离升级、安装与回退验证通过；未发布应用版本。
- 依据：覆盖现有桌面平台；自动检查、手动下载、确认重启；安装失败及新版首次启动失败恢复程序与对应数据。保留旧版应用内升级，兼容附件使用旧密钥签名。

## 用户流程

设置提供“正式版”和“测试版（Beta）”两个通道及自动检查开关。正式通道只接收更高正式版，Beta 接收更高 Beta 或正式版，比较完整版本号。两者都忽略 Alpha、组件 Release、草稿及缺少新版签名清单的发布；切换通道不会降级。

默认开启自动检查，启动后至少等待 10 秒，每 24 小时检查一次；手动检查不受间隔限制。发现更新后显示入口，不自动下载。用户下载后可取消或稍后安装；再次启动可继续安装已就绪的包。重启确认说明任务停止、数据备份与系统授权，退出收尾完成后才替换文件。

## 整包与平台

保留当前安装器和便携包，更新也覆盖宿主、前端、数据库扩展及随包工具。

| 平台                 | 当前形式            | 更新与回退方式                                                                 |
| -------------------- | ------------------- | ------------------------------------------------------------------------------ |
| Windows 10/11 x64    | Setup               | 下载新旧两份签名清单指定的安装器；正常退出后 Inno 覆盖安装，失败重新安装旧版本 |
| Windows 10/11 x64    | Portable            | 校验完整归档，只替换安装清单拥有的程序文件；失败恢复文件快照                   |
| macOS 13+ x64、ARM64 | APP（DMG/ZIP 分发） | 更新完整 APP；需要写入授权时使用 root 私有暂存和恢复副本，重新验证签名后写入   |
| Ubuntu 24.04 x64     | Portable、AppImage  | 分别替换清单中的程序文件或实际 AppImage 文件；保留旧程序副本                   |
| Ubuntu 24.04 x64     | DEB                 | 通过 pkexec/dpkg 安装新包或旧包；系统授权被拒绝时明确失败                      |

不扩大至 Windows/Linux ARM64、旧 Linux ABI、RPM 或其他发行版。更新签名不等于 Windows Authenticode、Apple Developer ID 或公证。

## 责任边界与文件格式

TypeScript 的应用级 `UpdateService` 管理设置、通道、GitHub Release 发现和界面状态，独立于 React 页面生命周期。请求使用现有网络设置，限制分页、响应大小与超时。

官方 Neutralino Extension 承载 `update.*` 命令。新 C++ 更新模块负责验签、单个有界后台下载、哈希、快照、安装、进程监管及恢复；独立 `javm_updater` 在应用正常退出后接手。这是用户批准的原生进程生命周期和更新范围，业务服务仍在 TypeScript，不新增本地服务器或自定义通信协议。

正式版和 Beta 必须发布 `JAVM-update.json`。它签名原始 UTF-8 `payload`，包含应用标识、协议版本、版本/通道、平台/安装形式、附件名、大小和 SHA-256；客户端先验签，再校验下载内容。便携/APP 更新使用 `.jup` 完整归档，逐文件有哈希和权限，拒绝路径穿越、重复路径、链接、特殊文件和超限包。安装包与 AppImage 直接使用原发行附件。

签名算法为 ECDSA P-256/SHA-256，Windows 使用 CNG，POSIX 使用已有构建体系中的 OpenSSL 3。公钥固定编译进程序。下载支持取消和相同签名目标的断点续传，进度节流；未取得可信旧安装包时，Setup/DEB 不进入可安装状态。首次可完整使用该链路的发行版本必须是带齐清单的 Beta 或正式版，历史 Alpha 安装器没有相应回退清单。

## 失败回退

退出时先停止下载、扫描、刮削和后台进程，关闭数据库，最后写退出确认。退出被取消、超时或收尾失败时不替换程序；收尾已经部分执行的应用要求重新打开后继续。

安装前通过 SQLite backup API 保存 `library.sqlite3` 和 `downloads-v1.sqlite3`，并快照 Neutralino `.storage`。不备份媒体文件、封面缓存、日志或系统钥匙串。任务库包含下载与刮削记录。安装器需先下载当前版本的可信回退包；其他形式保留受管理程序文件的快照，用户额外文件不删。

新版试运行持有业务启动门闩。实际界面挂载、两份数据库初始化/迁移与设置 JSON 读取成功后发送健康确认；安装助手持久写入提交标记后，才放行数据库业务、网络、子进程和设置写入。首次启动上限 3 分钟，提交之后不做无限期崩溃回退。

安装或试运行失败时先停止新版进程树，再恢复程序和旧数据。失败后的数据库、WAL/SHM、设置另存以便诊断，不删除数据库再重建。失败版本不会继续自动提示，手动检查可重试。恢复资料损坏或授权不足时停止恢复并保留证据，不继续覆盖。此时需要完成修复，不能承诺任何磁盘/权限故障都可自动恢复。

事务位于应用数据目录的 `updates/<事务编号>/`，保存状态和 `recover.cmd`、`recover.command` 或 `recover.sh`；崩溃后再次启动会先尝试恢复，也可在应用关闭后运行该事务的恢复命令。提交标记存在时恢复命令不会降级。当前保留恢复副本，不自动清理；macOS 提权副本位于 root 私有数据目录。

## 签名密钥

新密钥由 [GitHub Actions 38500189863](https://github.com/ddmoyu/javm/actions/runs/38500189863) 生成。私钥只在 runner 内存中生成，用仓库 Actions 公钥做 sealed-box 加密后写入 `JAVM_UPDATE_PRIVATE_KEY`，未写入仓库或本地明文文件。公钥、指纹和生成来源记录在 `resources/update-public-key.json`，并经 [38500467889](https://github.com/ddmoyu/javm/actions/runs/38500467889) 签名验证。

原 `TAURI_SIGNING_PRIVATE_KEY` 与密码 secret 保持不变。旧公钥来自 `v0.5.3:src-tauri/tauri.conf.json`，记录在 `resources/legacy-update-public-key.json`。旧密钥 ID 为 `98F83826D5F5F573`，经 [38507101563](https://github.com/ddmoyu/javm/actions/runs/38507101563) 生成安全文本签名，并在本机独立验签成功。

密钥验证工作流只手动触发或在专用初始化分支触发；普通开发分支不自动运行。禁止每次发布生成新密钥。以后轮换公钥必须先通过仍受信任的旧密钥发布过渡版本；在旧客户端支持结束前不能删除旧 Tauri secret。

## 0.5.3 的兼容升级

0.5.3 确实已有更新公钥，其固定入口为 `https://github.com/ddmoyu/javm/releases/latest/download/latest.json`。新增公钥配置仅针对 Neutralino 更新器，不代表旧版没有签名。

正式版和 Beta 同时生成旧格式 `latest.json` 及 minisign `.sig`，由原 Tauri 私钥签名。旧版验证旧签名，安装后的新版使用新公钥；不修改已安装旧客户端的公钥。

- Windows：原 Tauri 更新器接受 PE 安装器，交接 `/UPDATE`。新 Inno 安装器识别已登记的旧目录并保留可取消的安装向导，不把 `/ARGS` 后应用参数用于选择升级目录。成功完成同目录安装后移除旧 NSIS 卸载入口，保留旧数据及用户文件；普通新装行为不变。
- macOS：增加两架构 `-legacy.app.tar.gz`，内容为完整签名 APP；由旧更新器替换原 APP，用户重新打开应用。
- Linux：提供 AppImage、DEB 的安装类型目标及 x64 回退目标，仍遵守新版 Ubuntu 24.04 系统前提。不会给旧 ARM64 客户端发送 x64 文件。

0.5.3 的固定 Latest 入口只接收正式版；发布 Beta 不会把旧 0.5.3 用户切到测试通道。旧版本若自行支持 Beta 地址，可消费 Beta 附件。首次跨 Tauri/Neutralino 升级仍由旧更新器执行，不能追溯获得新版的启动确认及数据回退；该保护从升级后的后续更新开始。旧数据库继续通过既有迁移入口处理，不自动执行旧下载/刮削任务。

兼容仅指上述现有平台和系统前提，旧版曾支持的更早系统不因此被纳入。发布说明必须明确首次升级边界。已在隔离 CI 使用原更新插件和真实安装包验证 0.5.3 到新版的交接；旧版业务界面、真实用户库和系统授权弹窗未加载，详见验证记录。

## 发布约束与验证

合并平台附件时必须具备新私钥、旧私钥和匹配公钥，先核对文件哈希，签名后重新验证。正式/Beta 发布缺少任意平台兼容附件、旧签名、`latest.json` 或 `JAVM-update.json` 都失败。草稿全部附件上传、回读校验成功后才公开；只有正式版设为 Latest，Beta/Alpha 都不会改变旧客户端的正式更新入口。Alpha 不生成自动更新清单。

本轮按用户指定范围执行类型检查、定向用例和 Windows、macOS 双架构、Linux 的独立安装验收，详见 [2026-10-14 验证记录](../verification/2026-10-14-automatic-updates.md)。平台安装报告明确区分 cloud 模式宿主启动与完整 GUI 验收，正式发布仍须执行完整发行检查。

## 2026-10-19：静态正式清单、缓存与镜像

用户授权在 1.0.12 优化更新检查并增加镜像。

- 正式通道直接获取 `https://github.com/ddmoyu/javm/releases/latest/download/JAVM-update.json`，不再查询 Releases API。先用内置公钥验签，再按当前平台、安装形式和版本判断是否可更新；当前版或较旧版本也不能跳过验签。更新日志入口仍指向对应版本的官方 Release。
- Beta 保留既有分页发现及数值版本排序规则，允许更高 Beta 或正式版，忽略 Alpha、组件、草稿和无清单的发布。两种通道共同使用有界缓存与退避。
- 每个元数据地址缓存 15 分钟，过期通过 ETag / Last-Modified 条件请求；内存最多 24 条、按 UTF-16 估算不超过 3 MiB。持久化仅保留最近 12 份不超过 64 KiB 的清单响应和 8 个来源的退避记录；缓存内容每次消费仍须原生验签。过期缓存不能在网络失败时伪装成“暂无更新”。每次请求限制 1 MiB、10 秒和最多 6 跳 HTTPS。
- 429，以及有 `X-RateLimit-Remaining: 0`、`Retry-After` 或限流错误正文的 403，才归为限流。遵守 Retry-After（秒数或 HTTP 日期）和 X-RateLimit-Reset；没有有效时间时按 30 秒指数增长，最长 1 小时，服务端时间最多保留 24 小时。临时网络错误与 5xx 同样退避，成功后清除；手动点击及重启不能绕过未到期的退避。
- 默认官方优先，失败后依次尝试 `https://gh-proxy.com/` 和 `https://ghfast.top/`。用户可选择仅官方、指定社区镜像或自定义 HTTPS 前缀；指定镜像失败后尝试官方。界面明确标记社区来源。前缀后拼接原始 GitHub URL，只传输公开更新元数据和附件，不传账号令牌。社区服务由第三方运营，可在设置中停用或替换。
- 检查、安装包和当前版本回退包使用相同来源配置。前端和原生均限制来源数量及 HTTPS 前缀格式，拒绝账号、端口、查询、片段和地址模板；下载重定向只允许 HTTPS。签名信任仍固定在官方公钥，不因镜像改变。安装前继续校验签名清单规定的大小和 SHA-256。
- 原生下载记录部分文件的来源。同一来源可续传；切换来源会清空当前下载残片，防止拼接不同来源数据。镜像返回损坏文件时丢弃无效字节并尝试下一来源；不支持 Range 时同源最多从头重试一次。取消立即终止后续来源尝试，状态显示当前下载域名。
- 本次只修改应用更新器及应用 HTTP 响应头透传。第三方组件配方、迁移映射与构建流程不变，完整发版继续消费已有组件 Release。

社区服务的前缀用法参考 [GH-Proxy 文档](https://gh-proxy.com/docs/quick-start) 和 [GHFast](https://ghfast.top/)。2026-10-19 两个地址均实测返回 v1.0.11 清单，官方 P-256 验签通过且 SHA-256 与官方附件一致；这仅证明本次探测结果，不是长期可用性承诺。
