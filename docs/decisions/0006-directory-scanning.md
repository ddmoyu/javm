# 目录扫描、兼容数据库与异步执行

日期：2026-10-09。用户已授权 C++ 实现目录添加和扫描，并明确所有功能不得阻塞 UI；本决策覆盖重构计划中原先的“TS 扫描/TS XML、C++ 仅 SQLite”边界。

## 执行与并发

- React 只提交异步请求、订阅状态与显示结果。应用级 `LibraryService` 不依赖页面挂载；切换页面与 StrictMode 不重建扫描任务。
- 使用官方 Neutralino Extension WebSocket 承载 `library.*` 请求。媒体库初始化、迁移、目录验证、分页和收藏通过独立单线程请求队列串行执行，队列最多 64 项，满时返回可重试错误。
- 扫描由原生协调线程枚举目录，再交给固定工作线程池探测和解析。按 2026-10-10 用户要求，并发固定为 `max(1, min(逻辑处理器数 - 2, 16))`，原生自动计算；目录页和添加目录弹窗均不显示并发设置。旧请求中的手动并发值不再生效，扫描启动后不改变该次并发。
- 最多排队 64 个文件任务；队满时仅后台枚举线程等待。每个活动探测使用独立 MediaInfo 子进程，优先级低于普通进程，标准流句柄显式隔离，15 秒超时，以 Windows Job Object 管理。取消会终止活动探测并跳过未开始的任务。
- 2026-10-13：MediaInfo 动态加载和进程捕获已拆为 `native/probe`；Windows 保留 Job Object，开发中的 POSIX 分支复用独立进程组监督器。结果边运行边读取，限制 16 KiB；扫描与单独探测共享上述自动并发上限。非 Windows 完整扫描仍未启用，目标系统验收与文件语义工作见[跨平台计划](../CROSS_PLATFORM_PLAN.md)。
- SQLite 连接由互斥锁保护，短事务串行写入；并行任务不同时使用同一连接。文件缺失检查在锁外执行，结果每 128 条短事务更新，未变化文件跳过重复入库。
- `library.status` 只读取内存快照，`library.cancel` 设置取消标记；两者不等待媒体库请求队列或数据库锁。所有真实文件 I/O 均位于原生进程，前端请求通过 Promise 返回。
- 前端最多每 500ms 更新扫描进度；影片按可见范围每次读取最多 100 条，每个查询视图最多缓存 6 页。搜索、筛选、排序与维度聚合由原生 SQLite 后台执行，列表沿用虚拟滚动，不再逐页累计整库。详见 [片库分页决策](0010-library-paging.md)。`async` 本身不能消除同步 CPU 计算造成的卡顿。

原生启动时通过 [std::thread::hardware_concurrency()](https://learn.microsoft.com/en-us/cpp/standard-library/thread-class?view=msvc-170#hardware_concurrency) 读取逻辑处理器数；读取失败或逻辑处理器数不超过 2 时使用 1 并发。先判断下限再减 2，避免无符号数下溢。状态轮询读取缓存，不重复查询。16 是硬上限；减 2 仅用于限制工作线程数量，不保证操作系统调度时独占保留两个逻辑处理器。

## 识别与资料导入

目录管理使用路径、视频数量与操作的紧凑表格，支持打开目录、重新扫描及删除，也可从目录行的右键菜单操作。按 [1.0 资料独立建模](0021-metadata-first-library.md)，移除目录只停止管理和扫描，保留作品、收藏、资源关联及磁盘文件。扫描或旧库导入期间拒绝删除，成功后刷新目录、计数、片库分页和当前详情。离线目录同样可以停止管理，无需先验证磁盘是否在线。添加目录请求响应失败时仍重新读取后台状态，已受理的扫描继续显示进度。

1. 只接受存在、可读取的绝对目录。按 Windows 路径大小写归一化去重，拒绝根目录重叠，不遍历符号链接和目录联接；递归最多 128 层。
2. 默认扩展名涵盖 MP4、MKV、AVI、TS、MOV 等常见容器，允许自定义；扩展名只是候选筛选，必须由 MediaInfo 确认真实视频流。空文件、隐藏名称与常见花絮目录跳过。
3. MediaInfoLib 26.10 读取真实时长、宽高及编码，保留毫秒和宽高，兼容旧表的秒数与分辨率字段。探测不到时长时才使用 NFO runtime。
4. 同目录优先 `<视频文件名>.nfo`；只有一个候选视频时才回退 `movie.nfo`，避免多影片混用资料。图片优先使用 NFO 中有效的根目录内引用，再回退同名 `-poster` 等图片；单视频目录可使用 `poster`/`folder.jpg`。
5. pugixml 1.16 解析 Unicode/BOM XML，并兼容旧编码、字段别名、CDATA、结构化评分和常见实体错误，成功时保存原始 NFO 字节快照。NFO 最大 2MiB，拒绝 DTD，限制节点数和深度；不下载 XML 中的远程图片。完整规则见 [NFO 兼容决策](0008-nfo-compatibility.md)。
6. 按文件大小和修改时间判断增量变化。NFO 单独判断变化，保留导入来源用于合并：可更新以前导入的相同字段，保留人工改动；首次仅用文件名生成的标题可由后补 NFO 替换。NFO 损坏时报告资料读取问题，仍保存有效视频的分辨率、时长、编码和指纹；不清空旧资料，不保存失败的 NFO 签名或覆盖原始快照。后补或修复的侧车 NFO 沿用已关联视频的作品身份，避免先导入独立 NFO 时产生第二部作品；多视频关联冲突仍明确拒绝猜测。
7. 可取消、逐文件错误反馈，最多保存前 30 个错误详情。离线目录和中断扫描不删除影片；在线完整扫描发现缺失文件时仅设置 missing 标记。恢复文件后复用影片 ID。

目录枚举与操作系统文件访问可能受网络共享超时影响；取消即时受理，MediaInfo 子进程有硬超时，但系统级目录访问仍可能延迟后台线程退出。尚未完成真实 NAS、机械硬盘、大型片库的性能验收，不以单元测试替代这些结果。

## 数据库与许可

- 媒体库 `javm.db` 位于下载数据库 `downloads-v1.sqlite3` 同级目录；默认由宿主 `${NL_OSDATAPATH}/JAVM` 指定。当前媒体 schema 6，application_id 1245793613；下载库独立。进度表见 [默认记忆播放进度](0015-automatic-playback-progress.md)，导入完成记录见 [启动导入旧库](0018-legacy-database-import.md)。
- 支持新空库、旧 JAVM `user_version=2` 和此前新工程 schema 3/4/5 的数据库副本。先检查表、关键列与完整性，通过 SQLite backup API 生成 `javm.db.pre-v6-<UUID>.bak`，然后事务迁移。
- 保留旧 `videos`、目录、演员/分类/标签关联、ID 和未知表；`javm_scan_directories`、`javm_scan_files` 存放扫描设置、文件签名、来源、缺失状态、精确视频参数与新收藏状态，`javm_nfo_sources` 保存原始 NFO 快照。旧库数据仅保留不等于全部旧业务已经迁移。
- 非法库、未来版本及迁移失败保留文件并报错，不删除重建。测试仅使用仓库内旧表定义生成的虚构数据。
- 启动时检测固定旧路径并显示导入引导；关闭旧程序后，经用户点击执行备份、合并与校验，成功后移除旧数据库并保留恢复副本。具体规则见 [启动导入旧库](0018-legacy-database-import.md)。不要将迁移后的文件交给旧程序继续写。
- 当前 SQLite 层使用 C API 和 RAII。`sqlite_orm` 免费 AGPL 方案未采用；`ormpp`（Apache-2.0）已调研，可作为后续明确授权的常规 CRUD 封装，尚未接入。JAVM 自有代码保持 MIT。
- MediaInfo 源码版本、下载 SHA-256 与附加功能裁剪配置由 `scripts/offline-dependencies.json` 固定，构建见[精简 MediaInfo](0014-lightweight-mediainfo.md)；pugixml 的版本与下载 SHA-256 在 CMake 中固定。依赖许可随 `bin/licenses` 打包。

## 开发基础准则

该准则适用于后续下载、刮削、文件操作、封面处理与查询等所有功能：耗时工作离开 UI 线程；任务/消息有界；状态可观察；取消和退出能够清理；批量计算采用 Worker 或可中断分片。性能验证同时记录输入/导航响应、长任务、内存与后台吞吐，不能仅凭“用了多线程”认定界面不会卡顿。
