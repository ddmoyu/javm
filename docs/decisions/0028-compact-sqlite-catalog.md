# ADR 0028：精简演员快照与预建 SQLite

- 日期：2026-10-12
- 状态：已实现
- 依据：用户要求移除内置名单里作品数量未知的演员，改用精简字段的 SQLite，保留在线搜索并重新构建。

## 数据与打包

`pnpm catalog:build` 复用 CSV 校验器，将开发侧采集快照转换为 `data/catalogs/javbus/catalog.sqlite3`。女演员和男演员只保留明确 `video_count` 的记录，明确的零值仍保留；其他分类不按数量过滤。当前 75,303 条女演员记录保留 7,804 条，移除 67,499 条；连同其他分类共 8,766 条。

SQLite 省去可推导的来源、实体类型、完整 URL 以及重复默认值，使用整数保存枚举、数量和时间；保留来源身份、分区、原名、显示名、别名、人工状态、类别和来源顺序。包含身份唯一索引、分类顺序索引、名称索引及按同名身份计算数量的视图。不同 ID 的同名演员不合计数量。

CSV 和采集清单留在开发目录，便于恢复和维护，不再导入前端资源。生产包只内嵌 SQLite；生成清单包含数量、大小及哈希，日志不输出记录内容。构建不采集网络数据。

## 运行时

通过 Neutralino 官方 `resources.extractFile` 将版本化快照提取到用户目录，再经官方 Extension 以只读方式附加到原生 SQLite 连接。发现页分页直接查询快照及少量临时覆盖记录，不再把所有内置名称从 JS 分批导入临时表。不增加 SQLite WASM 或自定义服务。

来源定位、显示别名和头像匹配仍由 TypeScript Worker 处理。身份记录通过 Extension 每批最多 500 条顺序传入 Worker；页面每次最多 100 项。首次安装仍包含快照提取、身份分页、Worker 整理和界面成本，不能把早先独立 SQLite 查询基准当作应用启动耗时。

演员关键词搜索保持独立在线查询，不依赖内置名录命中；在线失败沿用现有反馈和重试。不会因为本地已有部分结果而跳过在线查询。

## 旧数据迁移

缓存升至版本 8。旧演员 names 列表不再补回完整快照；身份记录保留明确数量、人工显示名、翻译状态和别名。普通未知记录不迁入。用户 CSV 只在迁移时读取，原文件和旧存储键不删除，不再持续全表回写 CSV。成功后保留与内置快照相比的增量缓存。

旧数量增量若只剩已移除身份的 ID，不能推测其姓名；跳过无法定位的增量，由旧 CSV 中有明确数量的完整记录恢复。旧缓存和 CSV 均保留。读取失败时不完成迁移、不覆盖该备份；新数据暂留内存并显示保存失败提示。

用户片库、收藏、名称维护表不删除或重建。已收藏且不在新快照中的演员仍参与发现页查询；本地作品关系保留。

## 验证边界

数据库与在线搜索使用独立安全虚构数据及 mock 验证，不打开真实内容界面，不访问真实站点。只运行本次新增或重写的定向用例，完成 Windows x64 Release 构建和内嵌资源检查；不运行完整测试，也不创建发布。

2026-10-12 实际结果：9 项定向用例通过，1 项无关旧用例由名称过滤跳过；类型检查、MSVC x64 Release、前端及桌面打包通过。主程序由 15,206,912 字节降至 7,153,664 字节（6.822 MiB，减少 52.96%）；SQLite 为 823,296 字节（0.785 MiB）。EXE 内嵌资源没有 CSV 或 AVWikiDB 数据；内嵌 SQLite 的 SHA-256 与生成清单一致，ZIP 中的主程序、资源档案和原生扩展均与本次产物一致。旧运行进程因占用输出目录已关闭，未自动打开真实数据界面。
