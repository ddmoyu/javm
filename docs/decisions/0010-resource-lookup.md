# ADR 0010：保留 Neutralino 的视频资源查找

2026-10-10，已按用户授权接入。磁力搜索与磁力下载暂不开发。

## 决策

2026-10-10，按用户纠正收拢为“番号或片名搜索 → 合并相同影片 → 打开详情 → 获取资源链接 → 隐藏 Neutralino/WebView2 → 捕获候选并回收实例 → HTTP 检查 HLS → 平铺链接 → 复制或加入现有下载模块”。撤掉搜索页的“视频资源／影片资料”二级切换和手动选择来源。旧版默认来源模板继续作为后台配置，不继续扩展通用 HTTP 网页解析。开发验证只使用本地安全 mock；迁移模板不代表已经验证真实网站兼容性。

影片按规范化番号合并；没有番号时按完整片名归并，多个不同番号不会因片名相同被合并。保留组内候选，用于详情读取失败时尝试其他候选。精确番号在资料服务失败时仍可打开基本详情并查找资源；只有片名时不猜测番号。

主界面继续使用官方 Neutralino、React 和 Mantine。取流复用当前运行的 Neutralino 可执行文件，启动独立会话，不引入新的 WebView 库、浏览器安装包或 C++ 业务服务。

## 隐藏与生命周期

通过既有官方 `os.spawnProcess` 进程管理启动 PowerShell 监督器。监督器调用 Win32 `CreateProcess`，在创建时设置 `STARTF_USESHOWWINDOW/SW_HIDE`，挂起创建后先加入具有 `KILL_ON_JOB_CLOSE` 的 Job Object，再恢复主线程。Neutralino 同时配置 `hidden`、`skipTaskbar`、不保存窗口状态和不打开检查器。

独立 profile 与配置均位于本任务临时目录。监督器持有 Job 句柄并观察主应用 PID；正常结束、取消、超时或监督器结束时回收该浏览器进程树。TypeScript 等待进程回收并删除临时目录后，才把候选交给 HLS 检查。无法确认回收时保留清理操作，暂停后续取流，支持重试清理。

用户已接受 Neutralino 创建期可能短暂抢焦点，窗口不显示仍是硬条件。不会为交互验证、登录、失败或超时显示取流窗口。

## 资源捕获

独立实例先导航 `about:blank`，关闭原生 API、扩展、全局变量注入、日志和认证文件导出。通过 WebView2 内置 CDP 接口监听网络，在监听安装完成后才导航来源页。CDP 只绑定本机随机端口，端点从本任务 profile 的 `DevToolsActivePort` 读取，连接来源限制为主应用 origin。这里没有自建业务服务器或 stdin/stdout 业务协议。

同时识别请求地址中的 `.m3u8` 与响应 MIME 中的 HLS 清单；附加监听 iframe 和 worker 会话。对常见播放器只尝试静音播放控件，不点击任意链接。禁止默认下载、弹窗、图片和直接媒体加载；HLS 候选由外部受管 HTTP 请求进行小范围检查，不在界面播放网页。

最多一个取流任务运行，自动遍历内置来源，应用级待查来源硬上限 32。按历史表现排序后逐个提交，避免一次性占满底层任务队列；每个隐藏实例工作截止 20 秒，HLS 检查保留 30 秒预算。候选上限 16、最多检查 3 个候选，网络观察上限 512 个请求与 16 个会话，HTTP 检查累计上限 32 次。网页解析和 HLS 解析的既有 Worker 继续复用。

## 结果与下载

应用级 `ResourceSearchService` 持有查找队列、进度和结果，页面切换不取消任务。重新查找取消旧查询并隔离迟到结果；用户取消时清空未开始的来源，保留已经找到的链接。搜索预览与片库详情均提供“获取资源链接”，预览按番号归档，不能把临时预览 ID 当作数据库作品 ID。

按用户确认，找到一个可用链接就立即显示，并继续尝试剩余来源、追加不同链接。界面只显示总体进度和资源链接，不列出来源及各来源状态；来源 ID、名称与结果仍在内部关联。按规范化 URL 去重，保留签名及其他查询参数；不同地址、不同参数的链接保留。沿用旧版平铺展示，显示 HLS 实际提供的 `720p／1080p` 等分辨率、像素尺寸与时长，支持按分辨率排序。分辨率缺失时显示未知，不根据地址或片名推测；嵌套 HLS 清单保留内层已读取的尺寸。

各来源的有效尝试次数、成功次数和最近成功时间随资源偏好异步保存。下次查找按 `(成功次数 + 1) / (有效尝试次数 + 2)` 平滑成功率排序，同分时成功次数多的优先，再保留原始顺序。未使用来源以中性分数参与，避免一次偶然命中永久领先。用户取消、清理失败、本地队列限制及环境不可用不计来源失败；复制和下载的再次校验不重复计入取流成功次数。旧的手选来源偏好不再限制自动查找范围。

只有通过清单与小范围分片检查的候选才显示为已找到。复制提供 m3u8 地址；点击“加入下载”会再次检查链接，再调用现有 `DownloadService.add`。同一结果重复点击不会重复交接，现有下载队列继续负责跨查询的重复链接校验。

只传递实际观察到的公开 `Referer`、`Origin`、`User-Agent`；Cookie 与 Authorization 不导入、不交给下载器。使用代理取流时，后续 HLS 检查优先保持同一代理线路。依赖不可复现会话、登录或交互验证的来源返回失败，不以显示窗口方式处理。

## 验证与限制

既有隐藏取流能力的证据见 [资源查找验证记录](../verification/2026-10-10-resource-lookup.md)，包含安全跨域 iframe、无后缀 HLS、独立失败与重试、下载交接、超时、取消和带活跃任务退出；不代表本次新界面已完成桌面回归。本次修改文件的定向类型及静态检查通过，[新增的 8 项安全 mock 用例](../../tests/unified-resource-search.test.ts)通过，涵盖影片合并、来源排序、恢复统计、即时追加链接、取消保留复制、迟到结果隔离、下载交接及嵌套 HLS 分辨率。全仓类型检查另在 `tests/avwiki-works.test.ts:136` 报告一处与本次改动无关的参数类型错误，未扩改该文件。不运行既有回归、完整测试或打包，不访问真实内容站点。不声称已完成新界面的桌面回归或真实站点兼容性验证。
