# ADR 0010：保留 Neutralino 的视频资源查找

2026-10-10，已按用户授权接入。磁力搜索与磁力下载暂不开发。

## 决策

2026-10-10，按用户纠正收拢为“番号或片名搜索 → 合并相同影片 → 打开详情 → 获取资源链接 → 隐藏 Neutralino/WebView2 → 捕获候选并回收实例 → HTTP 检查 HLS → 平铺链接 → 复制或加入现有下载模块”。撤掉搜索页的“视频资源／影片资料”二级切换和手动选择来源。旧版默认来源模板继续作为后台配置，不继续扩展通用 HTTP 网页解析。开发验证只使用本地安全 mock；迁移模板不代表已经验证真实网站兼容性。

影片按规范化番号合并；没有番号时按完整片名归并，多个不同番号不会因片名相同被合并。保留组内候选，用于详情读取失败时尝试其他候选。

2026-10-11 修正空资料占位：不得把用户输入的番号包装成“找到一部影片”。精确番号的搜索为空或失败、组内详情均不可用时，复用已有目录 HTTP 与 Worker 详情解析器，最多读取 JavBus 两个分区的同番号作品地址。只在取得标题、资料和一致身份后显示影片详情，已读取详情在本次搜索内缓存，收藏直接复用。后备读取不加载或补采目录；最多一个请求运行，有总超时、取消、清理失败重试与退出等待。

仍无资料时显示失败或空结果，另提供“按番号查找资源”按钮，进入资源标签并明确尚未取得影片资料。这个入口不占影片数量，也不能收藏空资料。只有片名时不猜测番号。返回空详情、只有番号的详情或与候选身份不一致的详情均不按成功处理。

主界面继续使用官方 Neutralino、React 和 Mantine。取流复用当前运行的 Neutralino 可执行文件，启动独立会话，不引入新的 WebView 库、浏览器安装包或 C++ 业务服务。

## 隐藏与生命周期

通过既有官方 `os.spawnProcess` 进程管理启动 PowerShell 监督器。监督器调用 Win32 `CreateProcess`，在创建时设置 `STARTF_USESHOWWINDOW/SW_HIDE`，挂起创建后先加入具有 `KILL_ON_JOB_CLOSE` 的 Job Object，再恢复主线程。Neutralino 同时配置 `hidden`、`skipTaskbar`、不保存窗口状态和不打开检查器。

独立 profile 与配置均位于本任务临时目录。监督器持有 Job 句柄并观察主应用 PID；正常结束、取消、超时或监督器结束时回收该浏览器进程树。TypeScript 等待进程回收并删除临时目录后，才把候选交给 HLS 检查。无法确认回收时保留清理操作，暂停后续取流，支持重试清理。

用户已接受 Neutralino 创建期可能短暂抢焦点，窗口不显示仍是硬条件。不会为交互验证、登录、失败或超时显示取流窗口。

## 资源捕获

独立实例先导航 `about:blank`，关闭原生 API、扩展、全局变量注入、日志和认证文件导出。通过 WebView2 内置 CDP 接口监听网络，在监听安装完成后才导航来源页。CDP 只绑定本机随机端口，端点从本任务 profile 的 `DevToolsActivePort` 读取，连接来源限制为主应用 origin。这里没有自建业务服务器或 stdin/stdout 业务协议。

2026-10-11：官方安全诊断和隔离空白页对照确认，Chromium 的 `--remote-debugging-port=0` 会设置原生 `navigator.webdriver=true`。启动器现先分配非零回环端口，创建进程前替换临时配置中的端口模板。非零端口不会由 Chromium 写出 `DevToolsActivePort`，因此启动器查询本机 TCP 监听者，确认属于本次 Job 后读取本机 `/json/version`；再次核对所属 Job 和返回端点的回环地址、端口、路径后，原子发布端点文件。端口竞争不会连接到其他进程；总期限和退出清理不变。未覆盖任何网页浏览器属性。验证与局限见[官方诊断记录](../verification/2026-10-11-cloudflare-official-diagnostic.md)。

同时识别请求地址中的 `.m3u8` 与响应 MIME 中的 HLS 清单；附加监听 iframe 和 worker 会话。对常见播放器只尝试静音播放控件，不点击任意链接。禁止默认下载、弹窗、图片和直接媒体加载；HLS 候选由外部受管 HTTP 请求进行小范围检查，不在界面播放网页。

2026-10-11 对照旧版取流修复迁移缺口：隐藏页面启用后台运行状态，使依赖动画帧的播放器能够初始化；预加载拦截 fetch、XHR、媒体属性和 `Hls.loadSource`，并在页面内扫描有界的脚本配置。兼容转义与相对地址、文本响应中的无后缀清单，同站和跨站 iframe 都执行播放器探测。每个文档最多 16 个候选；单段文本最多 65,536 字符、解转义后的扫描累计预算 524,288 字符、fetch 响应前缀最多 64 KiB，响应观察最多 16 次及两个并行读取；不执行提取的脚本、不把页面正文传回主界面。图片拦截只匹配路径扩展名，避免脚本查询参数中的图片名阻止播放器加载。

自动验证响应不再仅因 HTTP 403 或验证 iframe 存在而提前终止，在原有总期限内等待自动完成；可见登录输入或实际需要操作的验证控件仍结束隐藏取流，不点击验证控件。文档重载会清理旧执行环境，再观察新文档；共享 Worker 与其他自动附加目标不得永久停在等待调试器状态。执行环境最多 64 个，其他任务预算不变。安全复现及验证见[旧版取流迁移修复](../verification/2026-10-11-resource-capture-legacy.md)。

同日真实公开视频验证发现，原先对完整 URL 匹配 `.m3u8` 会把 `?src=...m3u8` 的播放器网页当成清单并提前返回。现仅检查 URL pathname 后缀，响应 MIME 识别继续保留。新增对应延迟播放器用例，并通过真实官方演示页、公开 HLS、原生下载器和全程解码的闭环；详见[真实公开视频验证](../verification/2026-10-11-public-resource-download.md)，不据此推断其他真实来源可用。

（2026-10-12 前）最多一个取流任务运行，自动遍历内置来源，应用级待查来源硬上限 32。按历史表现排序后逐个提交，避免一次性占满底层任务队列；每个隐藏实例工作截止 20 秒，HLS 检查保留 30 秒预算。候选上限 16、最多检查 3 个候选，网络观察上限 512 个请求与 16 个会话，HTTP 检查累计上限 32 次。网页解析和 HLS 解析的既有 Worker 继续复用。

2026-10-12 按用户要求改为并行：各来源按历史表现排序后同时提交，隐藏实例并行上限为 `max(2, min(逻辑处理器数 - 2, 8))`，其余来源在有空位时补上；取流服务总并发提高到 10，为复制、下载前的复检留出位置。单实例期限、候选与请求预算不变。真实验证中 7 个来源同时启动，22.2 秒全部结束，串行时约 95 秒。

2026-10-12 经用户授权，在全程隐藏的实例中逐个真实验证旧版来源（屏幕不显示任何页面，报告只记录主机名、状态和分辨率）。修正导航与单次执行的 3 秒命令超时、预置登录框误判、脚本跳转误报、源站 5xx 空等，以及原生 HTTP 小写 `User-Agent` 被 CDN 拒绝；在隐藏实例内识别广告直播和短预告，结果必须含不少于 600 秒的点播轨道。7 个来源通过并参与自动查找，6 个未取得正片的来源移入 `unverifiedResourceSources`。详见[真实来源验证](../verification/2026-10-12-resource-sources-live.md)。

## 结果与下载

应用级 `ResourceSearchService` 持有查找队列、进度和结果，页面切换不取消任务。2026-10-12 起，影片详情挂载期间持有对应番号，最后一个该番号的详情关闭（或切换到其他影片）后自动取消仍在进行的查找；卸载后立即重新挂载（StrictMode、切换标签）不会取消。重新查找取消旧查询并隔离迟到结果；用户取消时清空未开始的来源，保留已经找到的链接。搜索预览与片库详情均提供“获取资源链接”，预览按番号归档，不能把临时预览 ID 当作数据库作品 ID。

按用户确认，找到一个可用链接就立即显示，并继续尝试剩余来源、追加不同链接。界面只显示总体进度和资源链接，不列出来源及各来源状态；来源 ID、名称与结果仍在内部关联。按规范化 URL 去重，保留签名及其他查询参数；不同地址、不同参数的链接保留。沿用旧版平铺展示，显示 HLS 实际提供的 `720p／1080p` 等分辨率、像素尺寸与时长，支持按分辨率排序。分辨率缺失时显示未知，不根据地址或片名推测；嵌套 HLS 清单保留内层已读取的尺寸。

各来源的有效尝试次数、成功次数和最近成功时间随资源偏好异步保存。下次查找按 `(成功次数 + 1) / (有效尝试次数 + 2)` 平滑成功率排序，同分时成功次数多的优先，再保留原始顺序。未使用来源以中性分数参与，避免一次偶然命中永久领先。用户取消、清理失败、本地队列限制及环境不可用不计来源失败；复制和下载的再次校验不重复计入取流成功次数。旧的手选来源偏好不再限制自动查找范围。

只有通过清单与小范围分片检查的候选才显示为已找到。复制提供 m3u8 地址；点击“加入下载”会再次检查链接，再调用现有 `DownloadService.add`。同一结果重复点击不会重复交接，现有下载队列继续负责跨查询的重复链接校验。

只传递公开 `Referer`、`Origin`、`User-Agent`；优先采用实际网络请求及补充请求头事件中的上下文。仅从播放器配置或属性发现且尚未请求的候选，使用其所在页面（包含重定向或 iframe）的地址作为 Referer；之后若观察到网络请求，以实际请求头替换，页面扫描不能覆盖已观察到的上下文。Cookie 与 Authorization 不导入、不交给下载器。使用代理取流时，后续 HLS 检查优先保持同一代理线路。依赖不可复现会话、登录或交互验证的来源返回失败，不以显示窗口方式处理。
