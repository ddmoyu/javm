2026-10-10 后续实施：新增自动单片／批量刮削、封面落盘、NFO 写入及下载交接，范围以 [基础刮削 ADR](0020-metatube-scraping.md) 为准。下文“本轮不扩展”记录最初的资料辅助接入范围。

2026-10-09，按用户授权接入 MetaTube 和 AI。初始实现记录见 [资料辅助验证](../verification/2026-10-09-metatube-ai.md)，当前随包提供的实现与交付见 [内置 MetaTube 验证](../verification/2026-10-09-bundled-metatube.md)。

1. MetaTube：官方 Windows amd64 程序在构建时下载并校验、随运行包内置，用户无需下载安装或选择程序路径。仅使用内置服务，首次查询资料时启动并检查健康状态，此后持续运行。仅管理本应用启动的进程，关闭主窗到托盘继续工作，主程序退出时清理。
2. AI：OpenAI 兼容接口的地址、模型和 API Key，配置保存、连接测试、文件名／标题中的编号识别，以及标题和简介翻译。默认禁用，密钥用 Windows 当前用户 DPAPI 保护后存入官方 storage。
3. 业务闭环：MetaTube 搜索并查看资料、从影片编辑页获取候选；AI 结果和外部资料均由用户逐字段选择，再写入片库。保留原始 NFO 快照和手动字段，扫描不得覆盖已确认值。
4. 执行边界：TypeScript 应用级服务承担资料请求和生命周期，组件准备由构建脚本负责；SQLite 修改仍经过官方 C++ Extension。任务有超时、取消、响应大小和并发限制，不创建额外运行时服务器。
5. 验证：纯服务测试、合成数据库集成、隔离 Neutralino 桌面测试及设置／资料预览交互分别记录。不把模拟 AI 接口测试当作真实供应商密钥验收。

本轮不扩展其他站点的解析器、自动批量刮削、图片落盘或多 AI 供应商自动轮换。MetaTube 是资料来源，不等同于视频资源下载链接搜索。

接口依据：[MetaTube 官方发行](https://github.com/metatube-community/metatube-server-releases)、[v1.4.0 启动参数](https://github.com/metatube-community/metatube-sdk-go/blob/v1.4.0/cmd/cmd.go)、[服务路由](https://github.com/metatube-community/metatube-sdk-go/blob/v1.4.0/route/route.go)、[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat)。

## 使用方式

- “设置 → 刮削与资料”仅显示内置版本、运行状态和影片资料来源。2026-10-10 按用户要求移除外部服务、自启动开关和手动启停入口。启动 JAVM、打开设置或保存来源均不启动 MetaTube；首次搜索或读取详情才自动启动。查询完成、失败、取消或离开页面都不关闭已启动服务，主程序退出时一并停止；关闭窗口到托盘继续运行。空闲时保存来源后，下一次查询直接使用新值，无需重启。
- 在“设置 → AI 辅助”填写 OpenAI 兼容基础地址（通常包含 `/v1`）、模型标识和可选 API Key，连接测试成功后保存并启用。无鉴权的本地模型可不填 Key。测试使用草稿，不覆盖已保存值。
- 打开影片编辑，使用“MetaTube 查找”“AI 识别”或“AI 翻译标题与简介”。预览默认只勾选原资料缺失的字段；采用后仍是草稿，点击“保存修改”才写入片库。主动取消、解析失败或模型拒答均不写库。
- 资源页的 MetaTube 结果是影片资料，不是视频下载地址。原始 NFO 只读，本轮不生成或覆盖 NFO，不下载封面／图片。
- 2026-10-10 统一“查看资料”与媒体库的影片详情抽屉：共用封面、评分、资料、简介和截图查看器，关闭后保留搜索词与分页并恢复候选入口焦点。搜索候选只读预览，隐藏片库编辑和本地文件操作；来源提供的图片地址用于按需显示，不写入图片文件或媒体数据库。编辑页的查找仍进入逐字段确认流程。
- 资料展示与 MetaTube `MovieInfo` 对齐：补充发行品牌（`label`）、来源编号、来源网页、普通与高清海报／封面；预览只显示来源支持的字段，移除原始名称、分辨率、文件大小等本地占位。预览截图独立查看，重复图片去重，无效地址不影响文字资料。
- `thumb_url`／`big_thumb_url` 是缩略图字段，`cover_url`／`big_cover_url` 是封面字段，均不保证原图方向。MetaTube [图片比例定义](https://github.com/metatube-community/metatube-sdk-go/blob/v1.4.0/constant/ratio.go)提供 2:3 Primary、16:9 Thumb 和不裁剪的 Backdrop；[图片处理实现](https://github.com/metatube-community/metatube-sdk-go/blob/v1.4.0/engine/image.go)会从原图裁剪，因此竖版输出不等于独立的竖版素材。JAVM 详情按原图比例自适应，最长边受容器约束；片库提供竖版海报、横版封面和列表视图，所有封面按完整图片等比缩放。视图切换同步调整虚拟列表行高与加载占位，不主动抓取或裁剪额外图片。
- 来源返回 `preview_video_url` 或 `preview_video_hls_url` 时显示“播放预告片”，使用现有播放服务与播放器偏好，并传递来源网页；仅有 HLS 时明确指定流媒体格式。两种地址并存时默认播放普通地址，可从旁边的菜单选择流媒体。开始播放时关闭资料抽屉并保留搜索列表，未返回有效预告片时不显示播放入口。仅接受无凭据的 HTTP／HTTPS 地址；不预加载预告片。
- 用户确认统一采用 5 分制：MetaTube `score` 直接用于搜索预览与编辑草稿，详情和片库卡片显示“分数 / 5”，手动编辑限制为 0～5，0／缺失／越界视为暂无评分。既有 SQLite、原生更新接口和 NFO 归一化仍保持 10 分制；`LibraryService` 读取时除以 2，保存时将修改值及并发快照乘以 2，不提前四舍五入，不迁移或重写旧数据库。
- 本轮定向检查与合成预告片验证见 [资料与预告片验证](../verification/2026-10-10-metatube-details.md)。新增品牌、来源和多媒体信息只用于搜索详情，不扩展编辑字段或数据库持久化。
- 搜索结果整行是详情入口，支持鼠标、Enter 和空格，移除右侧独立“查看资料”按钮。搜索只返回候选摘要，第一次打开仍需请求完整资料；加载状态标记在当前行，支持取消。同一轮搜索最多缓存 50 条成功详情，再次打开直接复用；重新搜索或卸载后释放，失败和取消不缓存。

## 实现边界

`AiService`、`MetaTubeService` 和配置持久化独立于 React 页面生命周期，主窗口持有实例，播放器窗口不初始化它们。每个服务只接受一个前台操作，重复请求拒绝，不建立无界队列。MetaTube 搜索上限 500 条、界面每页 10 条；认证 API 响应上限 1 MiB、请求内容上限 64,000 字符，AI 超时 60 秒、资料查询超时 45 秒。

Windows 请求通过官方进程 API 管理系统 curl，避免 WebView CORS 限制。网络代理沿用应用设置，回环请求绕过代理。认证请求不跟随重定向；密钥不放在 URL 或命令行中，请求临时文件在结束后删除。配置整体经当前用户 DPAPI 加密后写入官方 storage，不能跨 Windows 用户直接复用。连接失败不显示原始供应商响应或密钥。

2026-10-10 修复常驻 MetaTube 沿用旧代理的问题：每次查询前比较进程启动时与当前保存的有效代理。启用、修改或停用代理后，下一次查询等待旧进程退出，再使用新配置启动；配置不变时复用进程，保存设置不启动服务，也不打断在途查询，无需退出 JAVM。搜索／详情的 HTTP 404 提示资料未找到或来源无法访问，不再引导用户修改内置服务的基础地址；上游全部来源搜索会忽略各来源错误，因此不能把 404 直接当作番号不存在。

MetaTube 的固定版本、官方包 URL 和 SHA-256 由 `scripts/offline-dependencies.json` 锁定。`offline:setup` 在构建阶段下载并校验，打包前再次检查组件版本、来源摘要、EXE 大小和哈希；缺失或不匹配时拒绝出包。运行时固定从 `bin/tools/metatube/metatube-server.exe` 启动，不查询 GitHub 版本、不下载或安装组件。设置页显示内置版本，移除程序路径选择及安装／更新入口；组件随 JAVM 包更新，损坏时提示完整解压或重新获取运行包。

旧设置中的 `binaryPath`、`mode`、`endpoint`、`token` 和 `autoStart` 不再生效，只读取 `providers`；保存时只写入当前支持的字段。用户数据目录内的旧安装记录不再覆盖包内组件；旧组件文件和 MetaTube 数据库都保留，不做删除或迁移。

内置 MetaTube 使用独立数据库、随机回环端口和随机访问令牌。首次请求等待本会话旧进程回收完成后启动，启动任务在应用级共用；取消查询不取消启动或关闭服务。健康检查同时验证受保护的数据库版本端点和来源列表，启动失败回收本次进程，下一次查询可重试。进程意外退出后不会自行重启，只在下一次查询时重新启动。退出时取消启动与查询、等待操作收尾并停止自有服务；监督器也会在宿主进程消失时结束子进程。进程参数经临时 JSON 传入，代理只覆盖实际子进程的环境项，保留系统环境；不能直接用官方 `envs` 覆盖整个宿主环境，依据 [Neutralino 6.10.0 进程实现](https://github.com/neutralinojs/neutralinojs/blob/v6.10.0/api/os/os.cpp)。

SQLite 更新使用受限字段白名单与事务。保存前按修改字段比较打开编辑器时的快照，拒绝并发覆盖、重复番号和未知字段；不修改媒体路径。人工确认值记录在现有 `javm_scan_files.nfo_data._manual`，无需改变 schema v4；扫描继续保存原始 NFO 快照，保留手动字段以及明确清空的值。
