# 重复视频与广告视频管理

日期：2026-10-10。按用户反馈恢复旧版目录页的重复视频、广告视频入口，补齐真实查询与清理，沿用 React、Mantine、官方 Neutralino Extension 和文件 API。

## 检查规则

- 重复视频：同一作品、规范化番号（去首尾空白、不区分大小写）或非空文件指纹相同即建立关联，交叉关联合并为一组，显示跨目录提示。按用户确认的“优先画质”给出建议：可用文件优先，时长接近时依次比较分辨率、同编码的码率、大小和副本后缀。时长容差为较长视频的 2%，最少 5 秒、最多 60 秒。显示逐项保留或清理理由、参数及预计释放空间。
- 2026-10-15：MediaInfo 新增视频流 `BitRate` 探测，以增量 `media_quality` 表保存；旧记录在下一次扫描时补探测，探测不支持码率时保存 0，避免反复探测。无实际码率时按大小和时长计算并明确标注“估算总码率”，包含音频和容器开销。实际视频码率和估算总码率不混用口径比较，不跨编码比较码率。建议仅依据参数，不代表画面质量检测。
- 已知分段（包括文件名标记）、不同番号交叉关联、明显不同的时长、未知大小或探测参数、同分辨率的不同编码及不足 5% 的非零码率差异均留待人工核对，不自动纳入清理。默认不选中；可选择建议项后手工调整，也可“一键清理建议项”直接进入确认框，确认后执行。
- 扫描后台生成兼容旧版的快速指纹：8 字节小端文件长度，以及头尾各 4 KiB 的 Adler-32。新文件和缺少指纹的旧记录在扫描时补齐，文件变化后重新计算。它仅用于找候选，不能证明文件逐字节相同；相同番号也可能是分段或不同版本。
- 广告视频：仅检查已入库记录，零字节、重复文件名、文件名或标题关键词命中进入候选，排除词优先。关键词不区分大小写，重复文件名沿用旧版精确匹配。支持编辑包含词、排除词、重复文件名开关，以及右键将文件名加入关键词。设置由官方 storage 保存；不识别视频画面、不剪除广告片段。新扫描仍跳过零字节，零字节检查覆盖旧库已有记录。

## 执行与界面

- 原生 SQLite 请求按稳定 ID 游标每次最多读 500 条轻量记录，并校验片库 revision。分组、排序、规则判断和选择集合存放在一个 Web Worker；主线程只持有当前页的 30 条结果。
- 应用级 `LibraryMaintenanceService` 随 `LibraryService` 生命周期创建；页面重挂载不重建任务。关闭正在读取的检查窗口会终止 Worker，批量清理在当前项完成后响应停止，应用退出等待当前文件与数据库操作结束。
- 同时只运行一个检查或清理任务；Worker 消息和原生文件操作顺序等待，不无限积累请求。读取显示进度、支持停止；结果支持分页、核对路径与视频参数、打开所在目录、单项选择及批量清理。

## 删除行为

确认框提供两种范围：删除视频及独占字幕并移除资源记录，或保留视频与记录、仅清除刮削资料。按 [1.0 资料独立建模](0021-metadata-first-library.md)，普通视频删除保留作品、收藏、NFO 和封面；最后一个资源删除后作品显示“未下载”。实际文件删除由 TypeScript 使用官方异步 `filesystem.remove` 完成；原生负责文件身份检查、数据库事务及操作互斥。

重复视频清理必须为待删除的可用文件留出未选中的可用副本，已标记的不同分段不能互相替代。选择集合及保留副本映射在 Worker 中计算；清单准备时原生重新读取保留记录，检查分段、路径、普通文件、非零大小和签名，逐文件删除前再次检查。保留文件已丢失、离线、变化或被选中时拒绝清理并提示重新扫描或调整选择。仅清理资料、广告清理和已确认不存在的文件记录不要求保留副本；缺失文件在提交前恢复时保留数据库记录。

每个视频先生成清单并锁定扫描、导入、刮削提交与资料编辑。拒绝离线目录、符号链接、目录联接和已变化的视频，逐个文件删除前复核签名；普通删除先处理独占字幕，最后删除视频，确认清单中文件已消失后才更新数据库。原生只接受当前 token 清单内的文件检查，完成或中止后释放锁。

普通删除只处理视频和属于该视频的独占字幕。资料清理只处理可确认的 NFO、同名封面及数据库引用的独占封面（包括应用资料目录中的规范 NFO）；共享资料拒绝清理，同名目录和整个 `extrafanart` 目录均保留，不递归删除父目录。保留数量会显示在清理结果中。

逐项失败保留对应数据库记录，显示路径与错误，允许核对后重试。文件系统和 SQLite 不能组成一个事务：删除失败前已完成的实体文件删除无法回滚，界面明确说明这一点。成功后刷新目录计数、片库分页、详情与检查结果；重新读取失败时保持错误状态，不显示为“未发现候选”。
