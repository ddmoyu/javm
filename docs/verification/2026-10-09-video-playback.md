# 视频播放验证

2026-10-09，Windows / Neutralino 6.10.0 / WebView2，Video.js 10.0.1。

使用 `pnpm test:playback` 验证正式播放组件及实际播放服务，使用 `pnpm test:player-window` 从 `play()` 入口验证独立窗口。素材为 FFmpeg 合成的 640×360、20 秒 H.264/AAC 视频，测试配置禁用数据库扩展；未读取真实影片或用户数据库。

## 独立无边框窗口验证

21:04 完成最终检查、构建和测试：`pnpm check` 无格式、lint 或类型错误；`pnpm build` 通过，仍有依赖指令和包大小提示；`pnpm test` 为 132 通过、65 跳过。新增 7 条窗口通信／关闭测试和 4 条拖动合并／取消测试。

- 独立窗口生产构建：7/7 通过，`.tmp/playback-Rw9dD7/result.json`，截图同目录 `player-window.png`。
- 独立窗口 Vite 开发模式：7/7 通过，`.tmp/playback-KCLCpu/result.json`。
- 媒体回归生产构建：14/14 通过，`.tmp/playback-GXXa03/result.json`；修正取消方式后又在开发模式回归 14/14，通过记录 `.tmp/playback-xrHmzn/result.json`。
- 窗口验证覆盖独立进程、无系统边框、禁用扩展、自绘最大化／还原、最小化后换片恢复并复用、窗口布局、子窗口本地与网络 HLS、关闭重开以及主程序退出前的播放收尾。没有未处理的 JavaScript 异常。

另外使用真实鼠标在桌面上验证了标题栏拖动、双击最大化、双击还原、最大化状态下拖动还原，并用 Alt+F4 关闭子窗口。拖动前后原生坐标从 `(480,240)` 变为 `(630,340)`；子宿主结束后主宿主仍在运行。此轮隔离目录为 `.tmp/playback-rQurum/`。

关闭慢请求时发现外层 shell 强制终止与 curl 启动存在竞态，导致 curl 持有管道直到约 30 秒超时。播放请求现通过官方 `os.updateSpawnedProcess(..., "stdInEnd")` 发送 EOF 取消，由持有实际 curl 句柄的监督进程终止 curl，不传递 stdin 业务数据。取消方式仅在播放传输中启用。修复后独立窗口关闭耗时为生产模式 1,349 ms、开发模式 1,272 ms；媒体回归为 1,150 ms，进程及挂载均清空。两套测试都增加了关闭应小于 10 秒的断言，避免仅等待自然超时后误判成功。

主窗口数据库和下载服务的实际业务并行运行、系统强制结束／休眠、多屏混合 DPI 拖动及长期运行未在本轮隔离测试中验收。子窗口初始化分支和禁用扩展参数已检查；不得把禁用数据库的测试描述为真实业务队列验收。

## 首次媒体播放验证结果

- 生产构建：14/14 通过，记录 `.tmp/playback-9ogh5E/result.json`，截图同目录 `player.png`。
- Vite 开发模式：14/14 通过，记录 `.tmp/playback-1xFNp8/result.json`。
- 播放服务、输入校验及 HLS 加载器回归：18/18 通过。
- `pnpm test`：105 通过、65 条按原有条件跳过；不是全部原生数据库用例通过的证明。
- `pnpm build` 通过；仍有 bundle 大小及依赖 `use no memo` 指令提示。播放器延迟加载。
- 播放改动范围的格式检查通过，TypeScript / lint 无播放相关错误。全仓 `pnpm check` 被同时发生的其他文件格式变更阻挡，未批量改写这些文件；`vp check --no-fmt` 无错误，其他页面有 4 条警告。

| 样本                                        | 生产模式开始播放检查 |   定位检查 |
| ------------------------------------------- | -------------------: | ---------: |
| 本地 MP4，中文 / 空格 / `# & %`             |               610 ms |      51 ms |
| 本地 MP4，数据偏移超过 4 GiB                |               374 ms |      52 ms |
| 本地 M3U8 / TS                              |               533 ms |      51 ms |
| 网络 MP4                                    |               368 ms |      51 ms |
| HLS 重定向 / fMP4 / AES-128 / 无扩展名      |           371–485 ms |   50–52 ms |
| 无 CORS / 原生类型探测 / 字节范围 / Referer |       1,368–1,779 ms | 784–834 ms |

以上是本机回环测试，不代表公网速度。开始播放检查包含至少 0.25 秒的实际播放，检查间隔 50 ms；定位检查同样受 50 ms 轮询粒度影响。全部样本确认真实画面宽度、播放进度推进、暂停后定位不误恢复、关闭后移除媒体 source 与挂载。

缺失文件返回明确错误。生产模式的慢请求测试确认关闭前存在 1 个原生请求进程，关闭后进程和挂载均为空；没有未处理的 JavaScript 异常。HLS 用例实际启动独立解封装 Worker。

大文件由稀疏 `free` atom 与 `co64` 构造，真实音视频数据位于 4 GiB 之后。修复前官方资源服务开放 Range 的开始播放检查约 9–11 秒；改为 Worker 有界读取后约 0.4 秒。修复后的生产测试宿主峰值工作集 43.5 MiB、累计 CPU 时间 1,641 ms；该数据仅包含 Neutralino 主进程，不包含 WebView2 子进程，不作为总内存或总 CPU 声明。
