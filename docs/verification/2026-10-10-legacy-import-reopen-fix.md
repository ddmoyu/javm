# 旧库迁移跳过、重开和别名分组修复

2026-10-10。针对用户反馈的跳过后片库不可用、不能重新打开迁移，以及 `旧库关联记录缺失：studios`。

## 原因与修改

- 当前新版媒体库 schema 5 的完整性检查报告 16 个 `never used` 页；旧版媒体库完整性检查正常。原有报错统一写成“旧库”，误导了错误归属。现在明确标识当前片库或旧数据副本，并附数据库路径及校验详情。
- 迁移服务初始化只执行一次，正式界面没有重开入口。增加同一服务上的 `open()`，重新检测、检查去重和无待导入数据反馈；“系统设置 → 片库与迁移”提供固定入口。
- 原生探测不再依赖当前媒体库构造或升级成功。导入启动失败而原生服务尚未初始化时，状态查询返回 `unchecked`，前端恢复可重试状态，不会永久停留在运行中。
- 旧版 `entity_alias/cluster.rs` 的 `create_entity` 以首条别名自增 ID 生成独立分组编号；它不引用厂商、演员或标签表。修正迁移映射与表处理顺序，保留新版分组和主名，重新映射番号关联。此前测试中将别名编号关联演员主键的断言一并纠正。
