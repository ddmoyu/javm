真实媒体用例包括：带请求头的 MP4 下载、TS 分片 HLS、主播放列表下的独立 fMP4 视频与音频、暂停后的 HTTP Range 续传、HTTP 403 失败、已有输入直接合并、合并失败后保留输入并单独重试、包含中文及 shell 特殊字符的长参数，以及宿主意外退出后的工具进程回收。

并行与大小回归增加了两条真实慢速 MP4 同时传输，检查服务器同时存在至少两个请求、执行期间事件循环持续响应，并检查最终 MP4 的记录大小等于文件属性。状态机测试覆盖并发数升降、多个任务共用一次进度发布、控制状态引用稳定、慢速写库不回退进度，以及旧完成记录异步补齐大小且不延迟队列启动。HLS 测试覆盖分离音视频的大小汇总、估算与未知总量，以及最终文件实际大小。

媒体样本由 FFmpeg 生成，包含 12 秒测试图和正弦音频；测试服务器仅监听回环地址，不使用真实网站账号、受保护资源或用户影片。下载器与 FFmpeg 实际执行，ffprobe 检查产物流和时长。失败合并用例注入明确的 FFmpeg 失败，其下载与后续合并仍执行真实工具。

SQLite 用例启动实际 C++ 扩展，以测试对端发送官方 Extension 引导与事件信封，验证任务、设置、修订号冲突、进程重启恢复、独占所有者和不兼容旧文件的完整保留。全部使用 `.tmp/download-db-*` 新建数据库；未使用用户旧库。

生命周期用例在 `.tmp/download-host-*` 启动真实 Neutralino cloud 宿主及隔离扩展，写入设置后强制结束宿主，检查扩展释放所有者锁、数据库 `integrity_check`、已提交设置和重新获取写锁。UI 验证宿主重启后原有三个完成任务仍正常显示；再次强制结束后，扩展及其 cmd 包装进程均已退出。

该回归发现并修复两处实际问题：宿主结束后继承的句柄可能让扩展继续等待；令牌中的 `_` 被转义会导致部分启动握手失败。测试对端固定使用含下划线的连接令牌并检查原始 URL。真实进程测试使用明确的 20 秒级上限，避免默认 5 秒上限在系统负载较高时误报。

## 界面和真实宿主

独立配置位于 `.tmp/download-ui`，使用复制的官方宿主、扩展和 DLL，以 cloud 模式启动真实 Neutralino API。生产前端的隔离副本仅额外加载官方全局变量脚本，再由浏览器操作表单和列表。数据库、输出目录与正式应用隔离。

已观察到以下流程完成：

1. 下载设置发现并实际启动四种工具，将设置写入 SQLite。
2. 表单批量加入 MP4 与 m3u8，任务显示真实进度，HLS 合并后进入“已完成”。
3. MP4 下载中点击暂停，等待进程停止后显示“已暂停”，继续后生成最终 MP4。
4. 新任务下载过程中重载页面，旧进程回收，任务恢复为“已暂停”；点击继续后下载、合并完成。
5. 列表、计数、操作按钮与任务日志随状态更新；日志中的地址被隐藏。

最终界面截图保存在本机 `.tmp/download-ui/downloads-complete.jpg`。该验证覆盖生产界面和真实 Native API，未覆盖 WebView2 原生窗口关闭、托盘菜单点击及窗口位置恢复的视觉交互；这些代码已接入，仍需单独进行原生窗口验收。

隔离测试宿主、下载工具及扩展已关闭。AppData 下该测试实例的认证文件删除被自动审批策略拦截，文件暂留；其宿主已经退出，未打入发行包。

## N_m3u8DL-RE 原始日志与大小解析修正

用户指出 HLS 下载器能够输出大小后，按应用相同的管道重定向方式和下载参数，实际运行本机 `0.6.0+df70f0b3da0c630bd413bf617e758051f6b64757`，分别下载限速的 TS 播放列表和音视频分轨主播放列表。原始 stdout 已保留为测试夹具：[TS 原始输出](../../tests/fixtures/downloads/nm3u8dl-ts.stdout.txt)、[分轨原始输出](../../tests/fixtures/downloads/nm3u8dl-tracks.stdout.txt)。未重新排版；本次两个进程均成功，stderr 均为空。

TS 输出中实际包含以下内容（仅从连续输出中截取完整进度行）：

```text
Vid Kbps ---------------------- 9/12 75.00% 421.25KB/561.67KB67.39KBps00:00:02
Vid Kbps ------------------------------12/12 100.00%532.97KB - 00:00:00
```

其中 `421.25KB` 是已下载大小，`561.67KB` 是当时的预计总量，`67.39KBps` 是速度。该次预计总量曾显示为 `1.15MB`、`4.15MB` 等不同值；完成后下载器显示 `532.97KB`，源 TS 文件实际为 545,764 字节。预计总量需要保留“约”，最终 MP4 大小以合并后文件属性为准。

TS 的 7,541 字节 stdout 只有 6 对 CRLF，大部分进度行没有换行；百分比、大小、速度和 ETA 之间也可能没有空格。此前按换行分割、要求字段间有空格的解析器，回放 TS 的 129 个原始数据块和分轨的 106 个原始数据块时，均得到 0 次进度更新。此前的手写格式测试及完成后文件检查未发现这个问题，不能作为下载期间 HLS 大小显示正常的证据。

本次新增按完整进度行拆分的增量解析器，缓存跨事件的残片，并移除轨道名称末尾变化的进度条，避免把同一轨道反复累加。真实日志在 1、17、256、4096 字符和整段输入下均能一致解析：TS 117 次、分轨 178 次更新，结束时分轨大小合计 `377.34KB + 118.23KB`。待下载轨道尚无大小时，总量保持未知；有完整估算后显示预计总量。

真实工具集成测试将两种 HLS 样本限速，新增“下载结束前已出现正数大小”的断言。隔离真实宿主 `.tmp/hls-size-ui` 的列表已观察到“下载中 / 185.9 KB / 约 2.2 MB”，截图为 `.tmp/hls-size-ui/hls-progress.jpg`。完整采集含原始数据块时间、启动参数和输出文件属性，位于 `.tmp/hls-size-log-capture-1791540543292`。

该界面任务随后下载、合并完成，显示最终 MP4 为 `486.6 KB`，文件属性为 498,231 字节；控制台无警告或错误。测试宿主、扩展及限速样本服务器均已关闭。首次运行曾因隔离目录布局找不到下载器，已通过该实例的下载设置指定工具路径后重试成功。
