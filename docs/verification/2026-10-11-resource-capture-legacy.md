# 旧版资源链接捕获迁移修复

2026-10-11。用户反馈新版获取不到资源链接，要求参考旧版处理。

## 对照与复现

静态对照旧版提交 `dd0e6b62b263258b6e78106c72017b3b470b4097` 的 `src-tauri/src/resource_scrape/video_finder.rs`。13 个来源模板一致；旧版还会在 document-start 拦截 XHR/fetch、媒体属性和 Hls 播放器，并扫描脚本中的候选。新版此前主要依赖网络 URL/MIME 和主文档媒体元素，遗漏配置公布、iframe 播放器启动和文本清单。

本轮先用新建的安全 fixture 运行修改前的取流模块，复现三个失败：脚本只公布链接时超时；隐藏页面依赖 `requestAnimationFrame` 时超时；带自动验证标记的 403 在重载之前就返回人工操作错误。没有依据这些样例推断真实站点全部失败的唯一原因。

## 修改范围

- 隐藏页面启用后台运行状态，窗口仍不显示；复用目录模块已有的做法。
- 恢复有界的页面内捕获：播放器配置、XHR/fetch 文本、媒体属性和 `Hls.loadSource`；同时探测同站及跨站 iframe。
- 自动验证允许在既有期限内完成，人工验证仍退出；重载后弃用旧文档执行环境。
- 图片拦截按 URL 路径匹配，不再因播放器脚本参数包含图片名而误拦。
- 实际网络上下文优先于页面推导的 Referer，观察补充请求头事件；只传递公开请求头。
- 原有来源队列、HLS 清单与分片验证、下载交接、超时与进程清理继续复用。
