# 发现有资料但刮削失败的修复

## 原因

- 发现页通过 `AvwikiWorksService` 读取 JavBus 的完整详情，搜索页可通过 `JavbusMovieLookup` 后备读取；后台工厂却只把 MetaTube 传给 `MetadataPipeline`。服务查询失败时，后台不会走已经能提供资料的目录读取流程。
- 已看到的详情只保留在页面状态或当前搜索缓存中，后台无法复用。即使已知候选来自 JavBus，刮削仍调用 MetaTube 详情。
- 手动匹配关闭资源查询入口时，也错误地关闭了精确番号的目录详情后备查询。
- 切换到其他来源后如果仍沿用原候选身份，会触发详情身份校验失败，因此不能只给原 `details()` 增加不同来源返回值。

## 调整

- 增加有界的应用级有效详情缓存；发现读取、搜索查看和收藏保存共用，后台刮削先复用已经读取的完整资料。
- 通过 `MovieMetadataResolver` 接入现有目录读取器；明确的 JavBus 候选直接查询对应来源，其他来源失败、无同番号结果或详情无效时按精确番号后备查询。
- 管线返回实际采用的候选与详情，刮削任务在保存前更新来源身份，并继续核对候选、详情和片库番号；拒绝空资料、番号占位或错误番号，不降低保存校验。
- 手动匹配启用精确详情后备；前后台各一个有界读取槽并共享缓存和原 HTTP 调度，取消前台不会取消后台。
- 保留多来源补全、清理未确认时停止调度、取消后的迟到结果丢弃和重启后的来源恢复。无需更改原生扩展或数据库格式。
