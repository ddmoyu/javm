- 迁移旧版 13 个来源定位模板，提供来源选择、单源状态、重试、取消和结果筛选。

## 安全桌面证据

报告：`.tmp/resource-lookup-yGwYMM/report.json`。Node 只提供两个绑定 `127.0.0.1` 的测试站点，页面只含 `DEMO-001` 等虚构文字，HLS 清单和 8 字节分片均为合成数据，不能作为真实视频播放。

| 场景                       | 观察结果                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| 提交界面表单后按番号定位   | 请求 `/page/demo-001`，进入另一个 origin 的 iframe，得到 HLS 主清单和 720p 变体          |
| 点击界面的“加入下载”       | 重新请求清单与分片，下载入口收到一个 HLS 任务和公开 User-Agent/Referer；重复操作未再交接 |
| 一个来源 404，另一来源成功 | 分别展示失败与成功；单独重试失败来源保留已有成功结果                                     |
| 清单地址没有 m3u8 后缀     | 按响应 MIME 捕获并检查 `/hls/demo-004/manifest?token=safe`                               |
| 页面没有资源               | 20 秒到期失败并回收实例                                                                  |
| 用户取消                   | 返回取消状态，回收实例                                                                   |
| 有活跃取流任务时退出服务   | 活跃任务取消，等待回收后结束                                                             |
| 图片与弹窗样例             | 测试图片及弹窗目标均没有收到请求                                                         |
| 临时会话清理               | 本次新增的 `javm-webview-*` 目录遗留数为 0                                               |

桌面 fixture 使用生产取流、受管 curl、Worker 和实际资源结果组件；下载末端使用记录输入的 mock，不启动下载器或写入真实媒体库。此前的 [隐藏启动诊断](2026-10-10-hidden-webview-selection.md) 已记录 Win32 隐藏启动的可见性与焦点事件；这次闭环 fixture 验证功能和清理，没有增加截图或声称再次完成系统级窗口事件观测。
