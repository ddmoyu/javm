## 发版前发现并修复的问题

- macOS Intel 的 curl 组件混用了组件自带 OpenSSL 4.1.0 静态库和系统目录中的旧头文件，导致链接失败。`9b0164b` 固定头文件、SSL 和 Crypto 静态库到同一组件 SDK，并修正导入目标的系统头文件搜索方式；原生应用消费该组件时采用同一约束。
- [组件流水线 40077437060](https://github.com/ddmoyu/javm/actions/runs/40077437060)只重建三个 POSIX curl 组件并全部通过，Windows 全部复用。此前组件流水线已完成其他变更组件的独立发布。
- 已提交的目录文件头记录 SQLite 3.50.4，当前锁定 Node 的内置 SQLite 为 3.53.4。重新生成时改变了文件头的版本标记，造成已跟踪文件与发布提交不一致。四个平台生成的哈希完全相同。
- 使用锁定工具链重新生成并提交目录文件和清单。逐字节比较确认只有偏移 98、99 的两个版本标记字节变化，其他内容、大小、行数和来源清单均未改变；没有修改用户数据库。
- 同步后的目录 SHA-256 为 `a2defc223f4bac703b8d2eb8e9fd0ecdc38e9bd1ba6570adb24a4f538198c2e9`，与四个平台构建结果一致。发布源码一致性检查保持启用。
