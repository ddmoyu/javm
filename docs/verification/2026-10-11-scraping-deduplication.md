# 刮削任务重复添加修复

## 原因与调整

- 原来普通添加只匹配排队中、运行中的任务；失败、完成、取消等状态不参与去重，再次添加会创建新的 UUID 和列表行。
- 现在对所有状态识别同一刮削目标：正在执行或等待的任务直接复用；手动再次添加已结束任务在原行重新排队，保留 ID 与创建时间；下载重复交接保持幂等，不自动重复执行。
- 文件路径忽略 Windows 大小写和斜杠差异，同一作品的不同文件仍各自保留任务。纯资料任务按作品 ID、有效来源身份或明确的规范番号识别；不按影片标题合并，也不合并明确冲突的片库 ID。
- 启动时自动合并以前保存的重复记录，保留最早记录 ID 与最近尝试状态。先写入合并结果再删除冗余任务，写入或删除失败可在重启后继续；不删除媒体文件、图片或片库资料。
- 来源任务在准备后才取得片库 ID 的情况也会合并；手动匹配到正在刮削的目标时保留运行任务。合入的收藏意图会保存，不重新请求资料和图片。取消后仍在清理时明确提示等待，避免新任务与旧操作重叠。
- 同时将已识别的番号保存到任务查询字段，资料请求失败时列表仍能显示已确认的番号。
