## 旧版参考范围

参考 Git 基线 `dd0e6b62b263258b6e78106c72017b3b470b4097` 的 [下载管理器](https://github.com/ddmoyu/javm/blob/dd0e6b62b263258b6e78106c72017b3b470b4097/src-tauri/src/download/manager.rs)，从 Git 历史读取，没有把旧 Rust 服务复制到新工程。

| 旧版思路                                            | 当前实现与取舍                                                                                          |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `keep_tail` 按字符边界保留有限日志                  | TypeScript 按 UTF-16 代理对边界截断；分别限制进程输出、解析残片和界面日志                               |
| ANSI 清理、CR/LF 拆分、缓存未完成行、退出时处理残片 | 保留这些边界，并适配当前下载器没有换行的连续表格输出                                                    |
| 正常下载与完成行分别读取大小、速度                  | 同时兼容缺少空格、完成行没有总量/速度、数字附加标记；拒绝无效计数和非有限数值                           |
| 定时刷新进度                                        | 沿用新服务的所有任务共用 200 ms 发布机制，下载与合并仍在异步子进程中运行                                |
| 根据日志判断合并阶段                                | 不直接套用。分轨源的 `Binary merging...` 后还可能继续下载音轨；最终合并要等待下载进程退出和输入文件校验 |

旧版正常/完成行正则要求若干字段之间有空格，不能直接用于当前 `0.6.0` 的原始输出。旧版只处理一个进度值的方式也不足以表达分轨总量。当前版本对各轨道分别记录，最终成功仍要求实际 MP4 非空、视频/预期音频存在且时长合理。

## 实测发现与修复

1. **等待音轨让已有视频进度变成未知。** Tears of Steel 下载视频时，音轨长期输出 `0/100 0.00% - - --:--:--`。此前汇总逻辑因音轨没有总量而把整个进度设为 `null`。现保留已下载大小，以各轨道百分比平均作为临时进度；全部轨道有大小后改用字节加权。不能可靠计算全部大小时仍显示“总大小未知”。
2. **速度后的数字标记导致重复轨道统计。** Angel One 实际输出 `0.00Bps(1)`。此前增量拆行器不接受该格式，使残片混入轨道标识，最终全部轨道已有大小时汇总仍未知。用原始日志回放稳定复现失败后，补齐标记解析，最终可在下载结束前获取总量，完成后各轨道只累加一次。
3. **自动选择下载了多语言音轨。** `--auto-select` 对 Angel One 选出了五种语言音轨，而合并只映射一条音轨，原行为取到了按文件名排序靠前的德语。改为显式 `--select-video best --select-audio best`，不再按目录顺序决定语言；该样本选出英语 6 声道。此选择是下载器的“最佳”规则，未增加固定英语偏好或语言选择界面。
4. **完善边界处理。** 补充 Unicode 安全截断、进程结束时无换行残片、超长无效日志、异常计数、数值溢出和进度显示为 `100.00%` 但分片未齐等用例。

- [Angel One 完整 stdout](../../tests/fixtures/downloads/nm3u8dl-angel-one.stdout.txt)：保持原始字节，SHA256 为 `FAF05FF9A20141030A6313623D77CB8D42888D1C97EFEA06BBF28719AF067339`。

## 重现与证据

```powershell
pnpm test:downloads:public
```

命令显式开启联网测试，同时最多下载两个样本；失败源保持失败，命令返回非零。不进入普通 `pnpm test` 或自动 CI。测试产物保存在 `.tmp/public-hls-review/run-<时间戳>/<样本>/`，包含各次工具参数、原始 stdout/stderr、进度时间、ffprobe 信息和最终 MP4。对每个成功样本检查音视频轨、时长、文件大小、下载完成前的大小更新，以及已下载字节数大于零时进度不为未知。

测试使用隔离的 Node 文件适配器执行生产下载引擎，没有写入用户下载数据库。本次公开流验证没有操作桌面 UI；子进程回调耗时也不能等同于浏览器帧率。此前真实 Neutralino 宿主下的界面、并行、切页和暂停恢复验证见 [下载验证记录](2026-10-09-video-downloads.md)。
