# JAVM 桌面应用重构计划

本文规定 JAVM 从 Vue 与 Tauri Rust 迁移到 React、TypeScript、Mantine、Vite+ 和 Neutralinojs 的实施范围、模块边界、技术选型与验收标准。普通业务优先使用 TypeScript、Web 标准和 Neutralino 官方能力；SQLite 由独立 C++ 数据库扩展访问，使用 Neutralino 官方 Extension 协议通信。

2026-10-10 功能核对：当前实现与剩余工作见 [功能开发状态](FEATURE_STATUS.md)。下文保留阶段规划及初始决策；早期状态和最终验收复选框不能替代当前源码与逐项验证记录。磁力按用户要求暂不开发。

2026-10-11 范围更新：字幕（含本地关联）与多语言音轨选择明确不做。日常片库备份／损坏恢复、系统链接注册及在线演员搜索已接入，现有演员名单停止扩充；默认保留网站顺序，不在缺乏证据时标为热度。最新开发闭环及安全桌面验证见[模块复核记录](verification/2026-10-11-module-closure.md)。

2026-10-09 实施更新：工程与 Mantine 界面已完成初始化，目录扫描和下载按用户授权接入。目录枚举、MediaInfo 探测、pugixml NFO 解析属于已批准的 C++ 范围，覆盖下文原先 TS 扫描/XML 与“C++ 仅 SQLite”的规划；以 [目录扫描 ADR](decisions/0006-directory-scanning.md) 为准。所有功能均遵循耗时操作异步、不阻塞 UI 的基础准则；按 2026-10-10 用户要求，MediaInfo 并发由原生自动计算为 `max(1, min(逻辑处理器数 - 2, 16))`，不提供手动设置，硬上限 16。下表的初始状态仅记录计划创建时的阶段。

目标是完整迁移现有媒体管理流程，重新设计 React 界面，减少重复基础设施和不必要的原生依赖。Windows 为首个交付平台，架构预留 macOS 和 Linux 适配。关闭主窗口后进入托盘，下载和刮削继续；主动退出应用才停止任务。

2026-10-10 刮削实施更新：按用户授权实现 MetaTube 基础单片／批量刮削，以及新下载完成后的单文件入库、元数据、封面、NFO 保存和片库刷新。调度在应用级 TypeScript 服务，NFO 安全写入与文件校验复用 C++ 后台媒体扩展；保留人工字段。具体范围和后续边界见 [基础刮削 ADR](decisions/0020-metatube-scraping.md)。

2026-10-10 数据模型更新：按用户确认，1.0 是新版本，仅迁移 0.5.3。片库改为作品、视频资源、NFO 独立建模，支持搜索收藏后无视频落资料、后补视频与下载交接；开发期媒体结构不做兼容。见 [作品与资源 ADR](decisions/0021-metadata-first-library.md)。

## 一 已确认的技术决策

| 编号 | 决策 | 约束 |
| --- | --- | --- |
| D01 | 使用 React 与 TypeScript 重构界面 | 不继续使用 Vue、Pinia 和 Vue 组件实现 |
| D02 | 使用 Mantine | 不采用 shadcn，也不照搬原 shadcn-vue 组件体系 |
| D03 | 使用 Vite+ 统一前端工具链 | 优先使用其构建、检查、格式化、测试能力，不重复默认安装 ESLint、Prettier 或 Biome |
| D04 | 使用官方 Neutralinojs 桌面框架 | 官方 API 已覆盖的能力不再自行建设 C++ 替代层 |
| D05 | Windows 优先，预留跨平台 | 平台差异放进适配模块，不散布在业务和组件中 |
| D06 | 关闭窗口进入托盘 | 隐藏窗口而非销毁主 WebView，主动退出才执行任务收尾 |
| D07 | TS/JS 实现普通业务 | HTML、刮削规则、网络请求、任务调度、普通文件业务由 TS 实现；目录扫描、视频探测与 NFO 解析按 ADR 0006 在 C++ 后台执行 |
| D08 | 保留 SQLite，允许 C++ 操作数据库与媒体扫描 | 数据库及目录扫描是明确批准的原生模块，不要求先证明极限性能需求 |
| D09 | C++ 采用官方 Extension 通信 | 不采用自定义 stdin/stdout 业务协议，不建立第二套 HTTP/WebSocket 服务器，不默认维护定制 Neutralino 核心 |
| D10 | 其他模块仅在实测需要极限性能时考虑 C++ | 平台功能缺口单独评估，不能把功能缺口当作性能理由自动扩大 C++ 范围 |
| D11 | Tailwind 可以按需引入 | 用于提高布局开发效率，不与 Mantine 重复建立控件样式体系 |
| D12 | 尽量复用成熟外部工具 | 第一阶段保留 FFmpeg、N_m3u8DL-RE、MetaTube，不重写下载和媒体解码引擎 |

本计划中的“开发建议”不是新增的用户确认。例如 C++20、具体 JSON 库、WebSocket 客户端、状态管理库和安装器属于待技术验证的选择。实施时需记录最终选择、版本和原因，不把备选清单全部装入项目。

## 二 重构范围与完成定义

### 功能范围

以参考基线的实际页面、命令注册和业务代码为准建立功能清单，不只依据 README。已有功能按阶段迁移；某个功能若暂时无法覆盖，必须明确列为缺口，不能默认为取消。

首个完整版本需要覆盖：媒体库、目录管理、发现与收藏、资源刮削、下载管理、视频播放、封面截图、设置、MetaTube 管理、日志、深度链接与更新流程。实现顺序不代表最终功能删减。

### 完成定义

1. Windows 上关键流程贯通，浏览器预览和实际 Neutralino 应用分别验证。
2. 参考版本的主要用户数据可以在备份副本上迁移，保留媒体关联、收藏、别名和任务记录。
3. 已完成部分不依赖自有 Rust 后端或 Tauri API。
4. 主窗口隐藏到托盘后，下载和刮削能够持续调度，而非仅保留已经启动的下载进程。
5. 主动退出能够保存状态、停止调度并清理外部进程，无无主下载器或 FFmpeg 残留。
6. C++ 承担 SQLite 访问、事务、迁移、备份、原生进程生命周期，以及用户授权的后台目录扫描、视频探测与 NFO 解析。
7. 每个未解决兼容问题都有记录和处理结论，没有用模拟结果替代实际可用性。

### 首期不新增的范围

- 不新增内置 BT 下载引擎。现有磁力链接展示不等于已经实现 BT 下载。
- 不新增视频内容识别或自动剪除广告片段。现有广告文件筛选主要是规则检查。
- 不新建 Node.js 常驻业务服务器，不引入 Express、NestJS 等服务端框架。
- 不默认引入 CEF、独立 WebView2 辅助进程、libmpv 或新的本地媒体服务器。
- 不要求首版同时完成三个桌面平台的发布验证。
- 不因构建工具内部使用 Rust 或 Go 就重写这些工具；约束针对应用自身业务实现。

## 三 架构和职责边界

### 分层方案

| 层次 | 技术与位置 | 负责内容 | 不负责的内容 |
| --- | --- | --- | --- |
| 页面层 | React、Mantine | 页面布局、输入、选择、反馈、进度展示 | 不直接启动工具进程或执行数据库通信协议 |
| 业务服务层 | 独立 TypeScript 模块 | 扫描控制、刮削、下载调度、文件业务、AI、元数据融合 | 不依赖某个 React 组件的挂载周期，不在 UI 线程执行耗时同步计算 |
| 平台适配层 | `@neutralinojs/lib` 的薄封装 | 文件、网络、进程、窗口、托盘、日志、资源路径 | 不重做官方 Promise、认证和基础通信实现 |
| 数据访问层 | TS Repository 与类型化 DTO | 向数据库扩展发送明确的业务请求，转换数据形态 | 不向页面暴露任意 SQL 执行接口 |
| 数据库与媒体扩展 | C++、SQLite、MediaInfo、pugixml | 查询、事务、迁移、备份、后台目录扫描、视频探测、NFO 解析 | 不持有下载器、不执行站点刮削、不调用 AI |
| 外部工具层 | 已有可执行文件 | 下载、视频探测、截帧、聚合元数据服务 | 不替代应用任务状态与恢复规则 |

React 通过业务服务获得数据；业务服务通过平台适配层调用 Neutralino，通过数据访问层访问 SQLite。应用级服务在启动时创建，在主动退出时销毁。页面切换只改变视图和订阅，不改变任务所有权。

### 官方能力复用表

| 需求 | 优先使用 | 应用仍需补充的逻辑 |
| --- | --- | --- |
| HTTP 与 HTTPS | `Neutralino.net`，需要浏览器网络语义时用 `fetch` | 请求策略、错误分类、业务重试、Cookie 策略与代理能力验证 |
| 文件读写与目录 | `Neutralino.filesystem` | 批量策略、路径规则、增量扫描和失败恢复 |
| 文件变化监听 | 官方 watcher 和 `watchFile` 事件 | 去抖、合并、排除临时文件和避免重复扫描 |
| 外部程序 | `os.spawnProcess`、`updateSpawnedProcess`、`spawnedProcess` | 工具参数、输出解析、进程树清理和任务状态 |
| 窗口和托盘 | `window`、`os.setTray`、相关事件 | 隐藏与显示策略、退出协调 |
| 文件选择和系统打开 | 官方 OS API | 业务参数校验和用户反馈 |
| 本地封面与视频 URL | `server.mount` | 资源映射、编码、生命周期、大文件与 Range 实测 |
| 简单配置 | `storage` 或官方文件 API | 默认值、配置升级和备份 |
| 日志 | 官方异步 `filesystem` API | 统一 JSONL、字段与脱敏、大小轮转和 7 天清理，见 ADR 0017 |
| 前端资源更新 | `updater` | 与原生扩展及外部工具的版本协调 |
| C++ 通信 | 官方 `extensions` 机制 | 数据库业务层的请求编号、响应、超时和协议版本 |

框架已有 HTTP、文件和进程能力，不意味着框架已经实现业务队列。应用需要写业务状态机，但不能据此重新引入一套原生基础设施。

## 五 前端重构与界面方案

### 页面结构

保留七个核心页面的业务定位：媒体库、发现、目录管理、下载管理、资源刮削、系统设置、视频播放。允许重新安排导航与布局，但在设计评审前不删除现有入口。

| 页面 | 必需区域 | 需要设计的交互状态 |
| --- | --- | --- |
| 媒体库 | 搜索筛选、卡片或列表、详情、批量操作 | 初次使用、加载、无结果、扫描中、文件失效、批量处理中 |
| 发现 | 演员与分类维度、作品、收藏 | 资料未补全、抓取中、失败、别名冲突 |
| 目录 | 目录列表、扫描状态、统计 | 路径失效、权限拒绝、扫描取消、增量完成 |
| 下载 | 队列、状态筛选、速度进度、任务操作 | 排队、下载、合并、暂停、取消、失败、后处理失败 |
| 刮削 | 单项搜索、来源结果、融合预览、批量任务 | 部分结果、验证等待、来源超时、取消、部分保存 |
| 设置 | 路径、代理、下载、刮削、AI、MetaTube、更新 | 未保存、验证中、保存失败、需要重启 |
| 播放 | 视频区域、控制条、错误与外部打开 | 加载、定位、格式不支持、网络中断 |

正式页面实现前先完成主界面、下载页、刮削页和设置页的原型，确认导航、信息密度、主题、窗口最小尺寸与键盘操作。Mantine 提供基础交互控件，媒体卡片、任务行、详情面板属于应用组件。

### 样式边界

- Mantine theme 统一颜色、字体、间距、圆角、控件尺寸和明暗主题。
- CSS Modules 处理业务组件样式，CSS 变量承接主题值。
- Tailwind 若引入，主要用于布局、对齐和间距，避免同时定义另一套按钮、输入框主题。
- 接入时验证 CSS reset、层叠顺序和弹层样式，避免 Mantine 与全局样式相互覆盖。
- 不同时混用多个完整 UI 组件库。选定图标库后统一使用。

### 状态和业务服务

页面局部交互使用 React state。跨页面 UI 状态与后端查询缓存分开设计：轻量 store、查询库和路由库在 P1 根据实际需求选择，不默认同时引入 Zustand、Redux 和其他状态体系。

下载、刮削、扫描、工具监督由应用级 TS 服务持有。React 只订阅快照和事件。React StrictMode 开发环境的重复初始化检查不能导致重复启动进程、重复监听或重复建任务；服务启动需要幂等，并有明确的 dispose 流程。

DOMParser 用于静态 HTML 与 XML。解析文档不会自动执行页面脚本；动态来源需使用浏览器加载流程。涉及大量纯计算时可放入 Worker，但 DOMParser 不应假定在 Worker 中可用，Neutralino 客户端调用也通过宿主协调。

## 六 数据库扩展设计

### 范围

C++ 数据库扩展只操作 SQLite 和必要的数据库备份文件。TS 负责业务规则以及下载器、网络、媒体文件操作；C++ 提供原子的数据访问操作，不执行这些外部动作。

不采用 SQLite WASM、IndexedDB 或整库 JSON 替代主数据库；不使用 SQLite 命令行程序作为主数据通道；不引入 Node.js 原生数据库插件。

### 参考数据库与兼容内容

参考源码实际创建的是应用数据目录下的 `javm.db`，`DB_SCHEMA_VERSION` 为 `2`。不能将前端遗留封装中的其他数据库文件名当作迁移依据。MetaTube 的数据库单独管理，不与应用主数据库合并。

| 数据组 | 参考表 | 迁移要求 |
| --- | --- | --- |
| 视频与目录 | `videos`、`directories` | 保留 ID、路径、文件信息、元数据、图片引用和目录关系 |
| 演员与维度 | `actors`、`tags`、`genres`、`studios`、`series`、`directors` | 保留资料、名称和已有扩展字段 |
| 视频关系 | `video_actors`、`video_tags`、`video_genres`、`video_studios`、`video_series`、`video_directors` | 保留多对多关系和约束 |
| 作品与收藏 | `actor_works`、`facet_works`、`favorites` | 保留作品缓存和收藏语义 |
| 别名与证据 | `entity_aliases`、`designation_entities`、`alias_evidence`、`alias_overrides` | 保留来源、合并屏蔽与人工选择 |
| 任务 | `downloads`、`scrape_tasks` | 保留记录、错误和临时路径；运行状态需要恢复判断 |
| 应用元信息 | `app_meta` | 保留兼容字段；新增迁移记录需独立设计 |

版本号不能完整描述实际结构，旧代码存在通过 `ALTER TABLE` 补列的逻辑。迁移前应同时检查 `user_version`、实际列、索引和约束。

### 数据库实现建议

| 项目 | 方案 |
| --- | --- |
| SQLite 接入 | 原生 SQLite C API，加小型 C++ RAII 封装；ORM 非默认依赖 |
| C++ 标准 | 建议 C++20，依据 WebSocket 和 JSON 库的实际要求锁定 |
| 连接所有权 | 首期采用有明确所有权的数据库工作线程与写入队列，不让多个线程并发使用同一连接 |
| 读扩展 | 查询延迟实测需要时再增加只读连接，不能默认无限创建连接 |
| 事务 | 一个业务写操作在扩展内完成事务，不通过多次 TS 往返维持悬挂事务 |
| 外键 | 每个适用连接显式启用并检查，不能认为设置一次即自动覆盖所有连接 |
| WAL | 启动初始化时设置并验证；备份和退出正确处理 WAL |
| 锁冲突 | 配置有界 busy timeout，区分暂时锁冲突与不可恢复错误 |
| 查询 | 参数化 SQL；排序字段和可选列使用白名单；分页和批量上限可配置 |
| 数据类型 | 明确空字符串与 NULL；可能超出 JS 安全整数范围的整数以十进制字符串传输 |
| 日志 | 应用级服务通过官方异步文件 API 统一记录；5 MiB × 10 个文件、保留 7 天，不另外引入日志框架 |
| 版本 | 分开维护应用版本、数据库结构版本和扩展协议版本 |

SQLite 事务只能保护数据库。视频移动、图片落盘等文件动作与数据库之间不能形成跨资源原子事务，应由 TS 使用操作记录、临时文件、补偿和恢复检查协调。

### 业务接口草案

下列是待冻结的业务契约，不是 Neutralino 自带 API。

| 接口组 | 示例方法 | 结果或约束 |
| --- | --- | --- |
| 初始化 | `db.initialize`、`db.getInfo` | 数据库位置、结构版本、协议版本、可用能力 |
| 视频 | `videos.list`、`videos.get`、`videos.updateMetadata` | 分页列表、详情、原子元数据写入 |
| 扫描 | `scan.lookupFiles`、`scan.upsertBatch` | 批量比对、批量入库、成功失败统计 |
| 目录 | `directories.list`、`directories.upsert`、`directories.remove` | 明确仅删记录还是解除关联，不直接删除媒体文件 |
| 演员和维度 | `actors.*`、`facets.*`、`favorites.*` | 查询、资料更新、关联和收藏事务 |
| 别名 | `aliases.loadEvidence`、`aliases.saveDecision` | TS 计算结果落盘，C++ 验证关系约束 |
| 下载任务 | `downloads.list`、`downloads.create`、`downloads.transition` | 支持期望版本或当前状态检查，避免旧事件覆盖新状态 |
| 刮削任务 | `scrapeTasks.*` | 批量创建、进度、结果与恢复查询 |
| 文件操作记录 | `fileOperations.*` | 仅保存操作阶段和恢复信息；必要新增表必须经过迁移 |
| 维护 | `db.backup`、`db.checkIntegrity` | 一致性备份、检查结果；恢复由维护流程独占执行 |
| 关闭 | `db.prepareShutdown` | 停止接收新写入、完成可收尾事务并关闭连接 |

不提供让任意页面直接提交 SQL 文本的公共接口。批量接口避免“一行数据一次 IPC”，减少序列化与通信开销。

## 七 官方 Extension 通信契约

### 传输方式

Neutralino 根据扩展配置启动 C++ 数据库进程，并通过标准输入提供官方连接参数。C++ 随后连接 Neutralino 已有的 WebSocket 扩展端点。标准输入在这里仅承担官方引导参数，不作为自建的业务管道。

TS 使用 `extensions.dispatch` 发送数据库业务事件。扩展通过官方广播机制回传响应，TS 在应用级注册一次响应监听并按请求编号匹配。若使用多窗口，各响应携带目标客户端标识，避免不同窗口消费彼此结果。[官方机制见参考资料 S05、S06]

普通 Neutralino API 的 Promise 关联由框架完成。数据库扩展的业务请求是事件载荷，需要另行关联；`dispatch` 完成只表示发送操作完成，不能视为 SQL 已提交。

### 请求与响应示例

以下 JSON 是传输在官方事件中的业务载荷，不替代官方 WebSocket envelope。命名仅用于说明，P1 冻结后以契约文件为准。

```json
{
  "protocolVersion": 1,
  "clientId": "main",
  "requestId": "request-uuid",
  "method": "videos.list",
  "params": {
    "page": 1,
    "pageSize": 50,
    "filter": { "directoryId": "directory-id" }
  }
}
```

```json
{
  "protocolVersion": 1,
  "clientId": "main",
  "requestId": "request-uuid",
  "ok": true,
  "result": { "items": [], "total": 0 }
}
```

失败响应使用 `ok: false` 和包含 `code`、`message`、`retryable` 的 `error` 对象。数据库内部路径、凭据和完整 SQL 参数不直接显示给用户。

### 必需的协议行为

1. 启动握手确认协议兼容和数据库就绪后再开放依赖数据库的功能。
2. 为请求设置超时，并区分查询超时、写入结果未知、扩展断线和参数错误。
3. 对可能重试的写操作提供幂等键或结果查询。超时并不说明事务没有提交，不能盲目重发创建任务和收藏切换。
4. 任务更新携带任务运行代次或记录版本，拒绝旧进度覆盖已暂停、已取消或已重试的新状态。
5. 扩展重连后重新查询快照，不试图依赖已经丢失的进度事件补齐全部状态。
6. 扩展离线时停止接受依赖数据库的新任务；不要让前端继续显示保存成功。已运行工具进入明确的受限状态并执行恢复策略。
7. 官方 IPC 关闭后数据库扩展应完成有界清理并退出；宿主正常退出前主动发送关闭请求。
8. 设置消息、批量条数和结果大小上限；媒体二进制不经过数据库 JSON 事件。

### 客户端库选型

| 需求 | 候选 | 选择要求 |
| --- | --- | --- |
| WebSocket 客户端 | WebSocket++、IXWebSocket、其他经验证的轻量实现 | 能接入官方端点，支持 Windows、无额外服务器，退出可靠；检查维护状态和传递依赖 |
| JSON | nlohmann/json、RapidJSON、Glaze | 根据易用性、编译要求与协议规模选择一个，不追求未测量的性能排名 |
| SQLite | 官方 amalgamation 或明确锁定的依赖来源 | 版本、编译选项和来源可复现 |

独立扩展不能直接链接 Neutralino 进程内的 C++ 对象。复用官方能力应通过官方 API 协议完成。选型定案前不默认引入 Boost、线程池、HTTP 客户端或日志库。

## 八 数据迁移和文件一致性

### 无损迁移要求

参考基线的 `db/mod.rs` 存在旧版本或数据库打开失败时删除数据库再初始化的行为。新实现不得照搬：版本未知、文件打不开或迁移失败时，应保留原文件并报告诊断，不通过删库恢复。[S03]

迁移步骤：

1. 定位用户实际数据目录，识别主数据库、配置、图片资料目录、任务临时文件和 MetaTube 独立数据库。
2. 停止旧程序写入，或采用 SQLite 官方备份机制取得一致性副本；活动 WAL 数据库不能只复制 `.db` 主文件。
3. 对副本检查完整性、结构、记录计数、关联关系和关键配置。
4. 在独立的新版本数据目录执行迁移；旧程序和新程序不得同时写同一份业务数据库。
5. 显式执行可审查的迁移步骤，成功后再更新迁移版本。未知的更高版本停止写入并提示不兼容。
6. 校验媒体数、收藏、演员关系、别名人工覆盖、任务记录、图片与视频路径。
7. 保留旧数据的完整恢复副本和迁移前备份，记录新旧版本、备份位置和验证结果。按 [启动导入旧库](decisions/0018-legacy-database-import.md)，用户在引导中开始导入后，在事务合并、校验和完成记录提交成功后移除旧路径数据库，避免重复提示；失败或取消保留原库。
8. 回退时使用旧版本兼容的副本，不让旧程序打开未经验证的新结构。

旧数据库中的运行中状态不是活进程证据。应用重启后应根据任务状态、输出文件、临时分片和工具能力重新判断，不能直接恢复成“下载中”或“刮削中”。

### 快速哈希与名称规则

参考扫描器使用基于文件大小与头尾采样的 Adler-32 快速哈希。迁移时保留采样位置、字节顺序、短文件处理与输出格式。快速哈希只作为候选判定，不作为文件完全相同的充分证据。

现有别名归一化主要涉及全半角、大小写和空白。不能直接用范围更广的 Unicode 归一化替代而不验证，否则可能改变既有别名键和聚类结果。

### 文件与数据库操作

| 操作 | 协调策略 |
| --- | --- |
| 保存 NFO 或封面 | 先写临时文件并校验，再落到目标位置；数据库提交失败时记录待恢复状态 |
| 同卷移动 | 检查目标冲突，执行移动，再同步数据库；失败时有补偿记录 |
| 跨卷移动 | 复制并验证完成后处理源文件，不能认为跨卷 rename 天然原子 |
| 删除视频 | 保持“仅删库”和“删文件及记录”的用户语义；逐步记录结果，失败不显示整体成功 |
| 批量操作 | 返回逐项成功、失败和可重试结果，保留已成功部分的信息 |
| 应用异常退出 | 启动时检查未完成操作记录，给出确定的恢复或人工处理状态 |

文件业务和恢复流程默认由 TS 协调，数据库扩展仅保证对应记录的事务性。

## 九 应用生命周期、托盘与任务恢复

### 启动与关闭

| 场景 | 预期行为 | 实现责任 |
| --- | --- | --- |
| 正常启动 | 初始化官方客户端，注册应用级事件，等待数据库扩展就绪，检查版本与恢复记录，再启动队列 | TS 应用服务、官方 Extension、C++ 数据库 |
| 点击窗口关闭按钮或 Alt+F4 | 默认隐藏主窗口并继续任务；关闭“关闭窗口后留在托盘”后，停止任务并退出软件 | `windowClose` 与标题栏共用关闭入口，按已保存偏好决定隐藏或统一退出 |
| 托盘打开主窗口 | 恢复已有窗口和当前任务状态，不重新初始化队列 | 官方窗口与托盘 API |
| 从托盘或菜单主动退出 | 停止接单、停止任务并保存状态、回收外部进程、关闭数据库扩展，最后退出宿主 | TS 统一退出协调器 |
| 系统休眠再唤醒 | 重新判断网络与进程，恢复调度，校准超时；不把休眠时间误算为正常任务执行时间 | TS 生命周期服务 |
| 宿主意外结束 | 扩展检测通信断开后自行清理退出；下次启动核对任务与文件 | C++ 仅负责自身，TS 负责业务恢复 |
| 扩展意外结束 | 停止新数据库写入和依赖写入的后续操作，显示服务异常；重连后重新核对状态 | TS 数据库客户端 |
| 第二个应用实例 | 不重复启动同一组下载与刮削；单实例或受控多实例行为在 P0 验证后固定 | 官方现有能力优先，平台适配补足 |

主窗口隐藏不等于 WebView 被销毁。下载器可能继续运行，但 TS 队列仍可能受到隐藏窗口定时器节流影响。因此必须实际验证“前一个任务完成后，隐藏状态下仍能启动后一个任务”，不能只验证外部进程尚在运行。

后台运行开关位于“设置 → 外观与交互”，默认开启，修改后自动保存到官方 Neutralino Storage。关闭入口等待首次读取和正在进行的保存，托盘不可用时走统一退出流程；托盘菜单“退出”始终停止任务并退出，详见 [可选后台运行](decisions/0016-optional-background-running.md)。

队列以事件、Promise 和受控唤醒驱动，避免依赖持续高频计时器。Web Worker 可承担无 DOM 的计算，但不能当作不受操作系统或 WebView 生命周期影响的后台服务保证。若原型不能满足隐藏后持续运行的要求，先查官方配置与可支持的执行方式，再记录需要对齐的架构缺口，不擅自将业务搬到 C++。

### 主动退出顺序

1. 将应用状态置为 `stopping`，阻止新任务、重试和界面触发的写操作。
2. 通知网络请求和刮削流程取消，阻止本轮执行的迟到结果写入。
3. 请求下载器、FFmpeg 和本应用启动的 MetaTube 结束；核对其子进程与输出文件。
4. 将未完成任务保存为可恢复状态，记录临时目录、阶段和必要的错误信息。
5. 等待已接受的数据库事务完成，拒绝新请求，关闭连接，通知扩展正常结束。
6. 核对扩展和受管进程结束，再调用官方退出 API。

退出应有明确的等待状态和上限策略。达到上限时显示剩余任务与处理结果，不无限假死，也不把尚未确认落盘的状态标记为成功。系统强制结束无法保证执行完整收尾，因此恢复流程必须独立成立。

### 任务状态与持久化

参考数据库下载状态使用数字，需要在兼容层保留含义，不能因为新界面采用字符串枚举而误读历史值。

| 旧值 | 含义 | 新实现注意事项 |
| --- | --- | --- |
| 0 | 排队 | 并发容量和依赖满足后才开始 |
| 1 | 准备 | 工具检查、参数和目标路径检查失败应可解释 |
| 2 | 下载 | 由真实进程与日志确认，进度事件不等于持久化事务 |
| 3 | 合并 | 区分下载器内部合并和单独 FFmpeg 进程 |
| 4 | 刮削 | 下载成功但刮削失败时保留已下载文件和独立错误 |
| 5 | 暂停 | 停止当前执行并保留可恢复材料，不承诺所有来源都可无损续传 |
| 6 | 完成 | 输出文件和必要后处理已核验 |
| 7 | 失败 | 保存失败阶段，允许只重试失败步骤 |
| 8 | 重试中 | 遵守退避与次数限制，不与旧进程重复执行 |
| 9 | 已取消 | 明确保留或清理临时文件的既有用户语义 |

刮削保留等待、运行、完成、部分成功、失败等语义，并记录验证、元数据获取、封面下载、保存 NFO、更新数据库各步骤。应用退出造成的中断与用户取消必须可区分；如增加字段或状态，应通过迁移实现，不能复用旧数字改变含义。

每次运行分配 `runId` 或递增代次。任务暂停、取消、重新启动后，旧代次的进度和结果只能用于诊断，不再改变新执行状态。持久化以阶段变化为主，进度适度合并写入，避免每一行工具输出产生一次 SQLite 事务。

## 十 网络访问、刮削与 HTML/XML 处理

### 网络能力选择

| 需求 | 首选 | 适用范围与限制 |
| --- | --- | --- |
| 常规接口请求 | Web `fetch`、`AbortController` | 浏览器网络模型，是否允许跨域由实际运行配置和服务端决定 |
| 原生 HTTP 请求 | Neutralino `net.request/get/post` | 绕开 WebView 的 CORS 检查；代理、重定向、响应类型、Cookie 与取消能力逐项按所选版本验证 |
| 用户希望解除 CORS 限制的场景 | 优先原生请求；Windows WebView 参数作为可验证的兼容选项 | 禁用 WebView 网络安全不是跨平台统一能力，也不会自动绕过站点验证 |
| 已登录页面和动态站点 | 官方窗口与可用 WebView 能力的原型 | 必须验证 Cookie、会话、脚本执行、页面加载事件和结果回传，不能假定具有 Tauri 相同接口 |
| 下载 HLS/DASH 或大文件 | 既有外部下载器 | TS 负责配置和进度，不将整段视频读入 JS 内存 |
| 下载封面和小型响应 | 原生请求或 `fetch` 配合官方文件 API | 校验大小、类型与失败状态，避免将错误页保存为图片 |
| AI 接口 | TS `fetch` 或原生 HTTP 适配器 | 按现有提供方、流式能力和代理配置验证，不为了普通请求引入 C++ HTTP 栈 |

这些是应用内部统一请求适配器的实现选项，不是每个站点各自维护一套网络库。请求参数统一包含超时、重试策略、取消信号和日志关联标识；没有真实取消能力的底层调用必须阻止迟到结果继续提交，不能把“前端不等待了”伪装成底层已经停止。

原版 Rust 网络栈包含特定客户端行为和 WebView 回退。浏览器 `fetch` 与 Neutralino 原生 HTTP 不会自动复现客户端指纹、验证行为或会话共享。站点可用性需要逐个验证，不能用“已经关闭 CORS”代替验证。参见 [Neutralino 网络 API](https://neutralino.js.org/docs/api/net/) 与 [配置文档](https://neutralino.js.org/docs/configuration/neutralino.config.json/)。

### 解析与规则组织

| 工作 | 默认实现 | 何时引入第三方库 |
| --- | --- | --- |
| HTML 元素查询 | 浏览器 `DOMParser`、`querySelector` | Worker 无 DOM 或需要统一容错解析时，评估 `htmlparser2`、`parse5` |
| XML/NFO 读取 | `DOMParser`，显式检查解析错误 | 对象映射明显简化业务时，评估 `fast-xml-parser` |
| XML/NFO 输出 | `XMLSerializer` 或可验证的 XML 构建器 | 复杂结构需要稳定构建时再选库，不拼接未转义的原始文本 |
| JSON | 标准 `JSON.parse/stringify` | 运行时边界校验可选 Zod，不能只依赖 TS 类型断言 |
| 番号、名称、标签规则 | TS 正则、规则表、纯函数 | 不引入 C++ 正则和 Unicode 处理库作为默认依赖 |
| 文本编码 | `TextDecoder` 与明确的编码回退 | 仅在 Web 平台不覆盖实际样本时添加兼容库 |
| 不可信富文本展示 | 安全文本渲染；确需 HTML 时使用 DOMPurify | 解析采集页不等于可以直接把页面 HTML 注入应用 |
| 多来源字段融合 | TS 字段级规则和来源信息 | 数据库保存结果和证据，不承担站点解析 |

每个站点适配器包含地址构建、响应获取、解析、标准化和诊断五部分。固定测试样本覆盖正常页、字段缺失、布局变化和验证页；验证页不应被解析成“没有影片”。

多来源融合保留字段来源、优先级、人工覆盖和可重算依据。演员与标签的别名推断不覆盖用户已经确认的映射。AI 输出视为候选结果，经过结构校验后进入相同融合流程。

现有动态取流窗口是 P0 核心验证点。如果官方能力无法满足某个现有流程，记录具体缺失的 API 和受影响站点，再决定兼容方案；不提前安装 Playwright 作为生产浏览器、不默认增加第二套 WebView。

2026-10-10 取流按用户授权完成“番号＋来源 → 对应资源页 → 隐藏 Neutralino 捕获 → 退出 → HLS 检查 → 结果显示 → 下载交接”，不继续扩展 HTTP 网页解析，磁力暂不开发。窗口不显示是硬条件，短暂焦点事件作为已接受限制；采用 Win32 显式隐藏启动、Job Object 进程树回收和 WebView2 本机 CDP 网络监听，不增加 WebView 库。成功、失败、超时、取消及应用退出都回收本任务实例。已完成安全 mock 桌面闭环与 7 项新增测试，真实内容站点和发布包未验证。架构见 [ADR 0010](decisions/0010-resource-lookup.md)，当前范围见 [m3u8 获取方案](plans/2026-10-10-m3u8-resolution.md) 与 [闭环验证](verification/2026-10-10-resource-lookup.md)；历史证据见 [隐藏宿主选型](verification/2026-10-10-hidden-webview-selection.md) 和 [HTTP 阶段记录](verification/2026-10-10-stream-resolution-http.md)。

同日按用户纠正，搜索入口统一为“番号／片名 → 合并相同影片 → 详情 → 获取资源链接”，移除“视频资源／影片资料”二级切换及手选来源。后台按持久化成功率与成功次数自动排序来源，找到即显示并继续追加不同链接；链接平铺展示分辨率、像素尺寸及可用时长，可复制或加入既有下载模块。仅片名不能确定番号时不猜测。具体规则与本次新增 8 项安全 mock、定向检查的验证边界见 [ADR 0010](decisions/0010-resource-lookup.md)。

## 十一 文件、外部工具与媒体播放

### 文件操作

扫描使用官方目录遍历和文件信息 API，由 TS 分批调度。保留视频扩展名、忽略目录、广告文件过滤、快捷方式或链接处理等既有规则；遇到目录无权限、路径消失或网络盘断开时返回局部错误，不终止所有扫描。

不把整个目录的文件内容一次读进内存。快速哈希通过可用的分段文件读取获取样本；若选定官方版本不能直接满足读取方式，先评估文件流或其他官方接口，再测量替代实现，不默认添加 C++ 扫描器。

文件监控事件需要去抖、合并，并在溢出或不确定时做增量复核。UNC 路径、中文、空格、长路径、大小写差异、只读文件和同名冲突均需要 Windows 实测。

### 工具进程适配器

| 工具 | 上游主要技术 | 本项目实现 | 重点验证 |
| --- | --- | --- | --- |
| N_m3u8DL-RE | C# / .NET | TS 组装参数，官方进程 API 启动，解析进度与退出 | 暂停恢复、代理、分片目录、合并阶段、子进程终止 |
| FFmpeg | C | TS 封装截图、转封装与必要的媒体操作 | 编码器可用性、参数转义、输出覆盖和中止后文件状态 |
| 下载媒体探测 | 复用现有 MediaInfo 与官方 Extension | 音视频轨、时长、合并校验 | 已移除 ffprobe；有界后台队列、超时、取消与退出清理 |
| MetaTube | Go | TS 管理配置、启动、健康检查和停止 | 数据目录、端口冲突、独立数据库、是否由本应用拥有进程 |

统一适配器处理启动失败、stdout/stderr 分块、半行、ANSI 转义、退出码、超时和取消。工具可能以 `\r` 更新同一行，不能只按 `\n` 切分。日志仅保留受控缓冲和滚动文件，防止长期下载使内存无限增长。

官方进程 API 已提供进程启动与事件，优先复用；但它的停止操作是否覆盖下载器启动的 FFmpeg 子进程必须用实际版本验证。若需要平台补足，集中在进程适配层，精确作用于本应用拥有的进程，不能按进程名称批量杀死用户的其他 FFmpeg 或 MetaTube。

Windows 路径和命令行参数使用统一经过测试的转义函数，覆盖引号、空格及 shell 元字符。避免把网页内容或配置值直接拼进 shell 命令。非必要不经过 shell；平台 API 的实际启动语义以原型为准。

工具由用户指定路径或应用受控目录提供。自动下载工具时校验来源、版本、架构和校验值；解压方案按实际格式评估 TS 库或平台已有能力，不为工具安装默认加入完整 C++ 压缩库。

### 播放方案

1. 已按授权接入 Video.js 10 默认控件，普通视频与 hls.js HLS 适配器共用函数入口 `play(source)`，不新增文件或链接输入界面，见 [内置视频播放](decisions/0009-video-playback.md)。
2. 本地文件优先使用官方 `server.mount`。Service Worker 将开放 Range 拆成有界请求，避免宿主一次读取整部视频；不新建本地媒体 HTTP 服务。实际大文件拖动、音轨和资源占用必须测试。
3. 挂载范围限于需要展示的媒体与图片目录，目录变化时同步卸载，不能把整个用户盘作为通用资源根目录。
4. 容器与编解码器支持以 Windows WebView2 实测为准。对无法内嵌播放的格式提供明确提示及现有外部播放器能力，不把浏览器可用等同于支持所有视频格式。
5. 截图继续可由 FFmpeg 完成，避免因浏览器画布跨域或格式限制导致现有能力退化。
6. 播放器已按用户确认采用独立无边框窗口与自绘标题栏。子窗口禁用 Extensions，只初始化播放服务；主窗口持有唯一的数据库和任务队列。关闭、换片、最小化恢复及退出清理用 `pnpm test:player-window` 验证。
7. 播放偏好已按授权接入：默认内置／外部播放器、自定义 `.exe` 路径、内置播放进度持久化，以及“复用现有窗口／在新窗口中播放”；设置需保存，下次播放生效。内置播放器默认记忆每个视频的播放位置，无进度开关和 200 条限制。进度逐行保存到独立 SQLite 表，多个窗口独立播放和关闭，显式退出清理所有窗口。关闭或换片保存进度，片尾最后 5 秒清除续播位置，详见 [默认记忆播放进度](decisions/0015-automatic-playback-progress.md)、 [播放偏好](decisions/0011-playback-preferences.md)、[播放偏好验证](verification/2026-10-09-playback-preferences.md) 与 [多窗口验证](verification/2026-10-09-player-multiple-windows.md)。

Vite+ 的 lint/format 对应 Oxlint/Oxfmt，不能简单写成“内置 ESLint 和 Prettier”。`vp check` 的类型检查需要配置并实际验证启用，尤其要区分普通检查和启用类型检查后的行为；以选定版本的 [Vite+ Check 文档](https://viteplus.dev/guide/check) 为准。需要生态尚不支持的特定 ESLint 规则时再作局部评估，不预先安装重复工具链。

### 本机 C++ 构建约定

本机 Visual Studio 为 Insiders/预览安装。优先使用以下入口初始化环境或发现安装目录：

- `C:\Program Files\Microsoft Visual Studio\18\Insiders\VC\Auxiliary\Build\vcvars64.bat`。
- `C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe`，查询必须包含 `-prerelease`。
- LLVM 辅助工具位于 `C:\Program Files\LLVM\bin`。

不得把具体 `VC\Tools\MSVC\<版本>` 写死到工程或通用脚本。CI 通过 CMake presets 和工具发现配置编译器，机器专属路径只留在本机说明或用户级 preset。若构建输出被正在运行的应用占用，结束本项目相关进程，重新构建成功后再启动，不创建含糊的临时改名发行物。

## 十五 测试与验收矩阵

### 分层验证

| 层次 | 应验证的真实行为 | 不足以作为通过证据的结果 |
| --- | --- | --- |
| TS 纯逻辑 | 番号、别名、解析、融合、状态转换、退出协调 | 只验证 mock 被调用 |
| React 交互 | 筛选、选择、批量操作、错误与重试、键盘行为 | 只有页面截图或无数据空壳 |
| SQL/迁移 | 真实 SQLite 约束、事务回滚、旧结构、关系数和备份可恢复 | 使用内存数组代替 SQL |
| Extension | 真实官方消息、并发请求、超时与迟到响应、断线、异常退出 | 只通过直接 C++ 函数调用 |
| 文件与进程 | 中文路径、权限失败、跨卷、半成品、子进程和错误退出码 | 只检查启动 API 返回成功 |
| 网络/刮削 | 固定样本回归与当前站点验证分别记录 | 固定样本通过就宣称线上全部可用 |
| 桌面生命周期 | 隐藏持续调度、主动退出、休眠恢复、重开和多实例 | 浏览器预览通过 |
| 发行 | 干净环境启动、资源和扩展路径、更新回退 | 仅开发机热更新成功 |

### 关键回归场景

- 迁移前后，媒体、演员、收藏、别名人工覆盖和关系记录数量一致；差异必须能追溯到明确的修复规则。
- 中途断网、代理失效、HTTP 错误、站点验证页和封面下载失败不会产生虚假的完成状态。
- 下载成功、NFO 失败时可以只补做 NFO；数据库写入失败时不重复下载已有成品。
- 暂停后重新开始，旧执行的进度和完成回调不会覆盖新执行状态。
- 同一目录重复扫描不产生重复媒体；文件移走、改名与跨盘移动有稳定的重匹配行为。
- 数据库只读、被占用、磁盘满、迁移失败时不删库、不清空用户配置。
- 关闭主窗口、关闭播放窗口、托盘退出、系统强制结束属于不同路径，分别验证。
- 退出后无本应用创建的孤儿工具进程；强制结束后的下次启动可识别未完成操作。
- 日志默认不记录完整 API 密钥、会话凭据或含敏感参数的完整请求地址。
- 首次启动、空库、旧数据、未知更高版本数据库、损坏数据库均有明确状态。

### 性能基线与 C++ 扩大条件

建议使用 1,000、10,000、50,000 条媒体记录和具有真实关联密度的样本建立基线。记录机器、构建模式、冷热缓存、磁盘类型以及数据规模，测量首屏、筛选、详情、扫描、内存和隐藏运行期间 CPU。具体性能目标在 P0/P3 获得基线后固定，不在未测量时写成已经达到的承诺。

发现问题时先检查 SQL 索引、分页、避免全量传输、图片缓存、虚拟化、并发数量和重复渲染。只有能证明瓶颈属于计算密集型业务、TS 优化与合适 Worker 仍不能满足目标，才提出新增 C++ 模块；提案需包含测量数据、收益、通信成本和维护代价。SQLite 模块不受这一前置限制，因为用户已明确选择 C++ 操作数据库。

## 十六 风险、兼容差异与待定项

| 项目 | 当前判断 | 处理方式 | 决策时点 |
| --- | --- | --- | --- |
| 动态取流与验证页面 | 官方 Neutralino 与 Tauri 的 WebView 能力不一定等价 | 优先官方原型，列出具体缺口，不默认增加浏览器引擎 | P0 |
| 隐藏后的 TS 调度 | 必须实测隐藏、休眠和任务切换 | 事件驱动并核对平台策略，不能仅依赖高频定时器 | P0 |
| SQLite 旧库兼容 | 版本号不足以代表全部实际列结构 | 结构检查、备份、迁移记录与回退副本 | P0/P2 |
| 扩展自动退出 | 不能假定宿主会可靠终止所有扩展 | 扩展处理连接断开，正常退出先清理连接和事务 | P0/P2 |
| 进程树终止 | 官方父进程停止不等于已证明全部后代停止 | 实际下载/合并测试，必要时集中平台适配 | P0/P4 |
| 原生请求与浏览器会话 | 两种请求渠道的 Cookie、代理与证书行为可能不同 | 显式会话策略与逐站点验证 | P0/P5 |
| 多窗口重复服务 | 窗口实现可能引入额外进程/扩展 | 明确主窗口所有者与辅助窗口协议 | P0/P1 |
| 内嵌播放格式 | 受 WebView 和系统编解码器影响 | 测试样本矩阵与外部播放回退 | P0/P4 |
| 更新范围 | 官方资源更新不等于完整宿主和扩展二进制更新 | 分离资源升级与整包升级，校验协议兼容 | P0 调研、P6 落地 |
| 深度链接/单实例 | 不假定开箱即满足旧实现 | 核对官方能力和 Windows 注册/启动流程 | P0 调研、P6 落地 |
| C++ 库选择 | WS/JSON 尚未最终确定 | 对照第七节做最小原型，只选需要的一组 | P0/P1 |
| 状态管理和可选前端库 | 框架已选，辅助库尚未固定 | 按实际页面复杂度选择，不需要逐个包向用户确认 | P1 |
| 发行形式 | 安装包、便携版及是否同时提供尚未固定 | 保留标准数据目录设计，发行前明确用户可见行为 | P6 |
| 统计功能 | 原版存在相关实现，重构不自动扩大数据收集 | 核对现有开关和行为，明确是否保留 | P6 |

React、Mantine、官方通信、SQLite 和 Windows/托盘行为已经确认，不需要再次征求相同确认。只有影响功能范围或用户行为的分歧需要对齐，例如某动态来源无法覆盖、是否取消原有功能、改为不同后台运行架构或发行形式。例行库版本、脚本命名和目录内部拆分由实施者依据本计划处理。

## 十七 打包、发布与回退

发行包包含前端构建资源、匹配的 Neutralino 宿主、数据库扩展和必要配置。外部工具明确标注随包提供、首次下载或用户指定三种来源之一，并记录平台架构和许可证；不能假定开发机 PATH 中的程序会出现在用户机器上。

| 检查项 | 要求 |
| --- | --- |
| 版本一致性 | 应用版本、宿主/客户端组合、扩展协议版本、数据库版本及工具版本有可追溯清单 |
| 原生运行依赖 | 明确 WebView2 与 MSVC 运行库部署方式，在干净 Windows 环境验证 |
| 资源路径 | 从发行包所在位置解析只读资源，从数据目录解析可写文件；不能依赖开发目录 |
| 前端资源更新 | 官方 updater 能力用于其支持的资源范围，升级后仍与扩展协议兼容 |
| 整包更新 | 涉及宿主、扩展或工具二进制时使用经过验证的整包升级流程，不只替换 `resources.neu` |
| 数据迁移 | 升级前可恢复备份，失败保留原件；降级不能直接打开不兼容新结构 |

| 故障回退 | 保留可启动旧包与兼容数据副本，记录升级结果，避免无限重启更新 |
| 跨平台预留 | 平台路径、工具名、托盘、进程停止与分发配置集中适配；未经实测不宣称已经支持 |
